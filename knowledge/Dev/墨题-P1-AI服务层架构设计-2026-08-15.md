# P1 AI 服务层架构设计

> 基于墨题现状（ai_client.py 已是 OpenAI-compatible 通用客户端）
> **核心结论：Provider 抽象已有 80%，缺「按任务路由 + 本地优先 + 降级」三层能力**

## 一、现状盘点（实证）

| 已有 | 说明 |
|:---|:---|
| ✅ `chat_completion` OpenAI-compatible | base_url + api_key + model + temperature + response_format 全可配 |
| ✅ 多 Profile（ai_profiles 表）| enabled/is_default/api_key_encrypted/default_model/temperature |
| ✅ 模型发现 | openai `/v1/models` + ollama `/api/tags` 双格式 |
| ✅ 密钥加密存储 | unprotect_text + 加密 |
| ✅ 重试 | 429/500/502/503/504 × 3 次 |
| ✅ 模型目录缓存 | ai_profile_models 表（重启后可用）|

**已验证兼容**：DeepSeek / 百炼 / 本地 Qwen（llama.cpp OpenAI 端点）天然支持——只需在 UI 配 base_url。

## 二、缺口定义

1. ❌ **没有任务级路由**：现在所有功能都用 default profile——错题归因/词汇标注/作文批改应该用不同 provider
2. ❌ **没有本地优先策略**：离线/局域网时不能自动切本地 Qwen
3. ❌ **没有降级链**：云端 429/超时 → 本地 → 缓存（现在只有重试，没有降级）
4. ❌ **没有成本/用量记录**：不知道每个功能花了多少 token

## 三、目标架构

```
┌─────────────────────────────────────────────────┐
│               业务层 (services/*)                │
│  wrong_analysis │ vocabulary │ import │ ...      │
└──────────────────────┬──────────────────────────┘
                       │ 统一调用
┌──────────────────────▼──────────────────────────┐
│           AI Router（新增 ai_router.py）          │
│  按任务 → 选 profile → 本地优先 → 降级链 → 用量   │
│  ┌───────────┐ ┌───────────┐ ┌────────────────┐  │
│  │ 任务路由表  │ │ 健康检查   │ │ 降级链(轮询)    │  │
│  └───────────┘ └───────────┘ └────────────────┘  │
└──────────────────────┬──────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────┐
│       Provider 适配层（现有 ai_client 扩展）       │
│  chat_completion(base_url, key, model)          │
│  ├─ DeepSeek API（云端，默认）                    │
│  ├─ 百炼/其他 OpenAI-compatible（可配）           │
│  └─ 本地 Qwen3-8B（llama.cpp, 127.0.0.1:8080）   │
└─────────────────────────────────────────────────┘
```

## 四、任务路由表（新增 ai_router.py）

```python
# 配置存 ai_profiles 表：每 profile 加 task_tags 字段（JSON 数组）
TASK_ROUTES = {
    "wrong_diagnosis":   {"primary": "cloud-deepseek", "fallback": ["local-qwen", "cache"]},
    "vocab_labeling":    {"primary": "cloud-deepseek", "fallback": ["local-qwen"]},
    "essay_grading":     {"primary": "cloud-deepseek", "fallback": []},
    "article_generate":  {"primary": "local-qwen",    "fallback": ["cloud-deepseek"]},  # 批量可慢
    "ocr_fallback":      {"primary": "local-qwen",    "fallback": []},                    # 隐私
    "chat_explain":      {"primary": "cloud-deepseek", "fallback": ["local-qwen"]},
}
```

**路由逻辑**：
1. 任务 → 查 TASK_ROUTES → 取 primary profile
2. 健康检查（profile 的 base_url 可达性，缓存 60s）
3. primary 失败（429/超时/网络）→ fallback 链轮询
4. 全失败 → 抛「AI 服务暂不可用」+ 明确错误码（业务层降级：诊断报告出本地统计版）

## 五、本地 Qwen 接入（sora 已有环境）

```python
# settings 里加一个 profile（UI 或 seed）:
{
  "name": "本地Qwen",
  "base_url": "http://127.0.0.1:8080/v1",   # llama.cpp server 默认端口
  "api_key": "not-needed",                    # llama.cpp 不鉴权（或配置）
  "default_model": "qwen3-8b",
  "task_tags": ["wrong_diagnosis", "vocab_labeling", ...],
  "enabled": true,
  "priority": 10                              # 本地优先时置顶
}
```

**注意**：本地 Qwen3-8B 48.8 t/s、8K 上下文——适合批量/短任务（分类/标注/OCR 兜底），**不适合长文归因**（错题 prompt 可能 >8K）——所以 TASK_ROUTES 里本地 Qwen 做 fallback 而非 primary（article_generate/ocr 例外）。

## 六、降级策略

| 场景 | 行为 |
|:---|:---|
| 云端 429 配额 | fallback 链 → 本地 Qwen → 缓存结果（同 task+input hash）|
| 云端超时（>60s）| 重试 2 次 → fallback |
| 全 Provider 失败 | 业务层降级：统计版报告 + 「AI 增强暂不可用」提示（不阻断功能）|
| 本地 Qwen 未启动 | 健康检查失败 → 跳过，不阻塞云端 |
| 缓存命中（同输入 hash）| 直接返回（错题诊断复用场景多）|

## 七、用量记录（新增 ai_usage 表）

```sql
CREATE TABLE ai_usage (
  id INTEGER PRIMARY KEY,
  task TEXT NOT NULL,            -- wrong_diagnosis / vocab_labeling ...
  provider TEXT NOT NULL,        -- deepseek / local-qwen / bailian
  model TEXT NOT NULL,
  prompt_tokens INTEGER DEFAULT 0,
  completion_tokens INTEGER DEFAULT 0,
  latency_ms INTEGER DEFAULT 0,
  status TEXT NOT NULL,          -- ok / fallback / failed
  created_at TEXT NOT NULL
);
```

**价值**：成本透明（每月 $ 统计）、任务分布、降级率监控——为「本地优先」优化提供数据

## 八、实施清单

| 步骤 | 内容 | 工作量 |
|:---|:---|:---|
| 1 | ai_profiles 加 task_tags + priority 字段（迁移）| 0.5 天 |
| 2 | 新建 ai_router.py（路由表 + 健康检查 + 降级链）| 1-1.5 天 |
| 3 | ai_usage 表 + 记录埋点（改 chat_completion 返回 usage）| 0.5 天 |
| 4 | 存量调用改走 router（grep chat_completion 调用点）| 0.5 天 |
| 5 | 本地 Qwen 接入验证（llama.cpp server + 实测归因）| 0.5 天 |

**总计 3-3.5 人天**

## 九、验收标准

- [ ] 同任务配置 3 个 profile（云端主/本地备/缓存）→ 云端故意 429 时自动走本地
- [ ] 本地 Qwen 未启动不阻塞云端功能
- [ ] 每个功能调用都能在 ai_usage 查到记录（task/provider/tokens）
- [ ] 切换 provider 不改业务层代码（只改配置）
- [ ] 错题归因在本地 Qwen 上输出格式合法（JSON 解析通过）
