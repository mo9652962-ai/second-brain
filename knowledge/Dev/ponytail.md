# Ponytail · AI 编程极简原则

来源：小黑盒 (50k⭐)
链接：https://github.com/DietrichGebert/ponytail

## 核心理念
让 AI 写代码前先冷静，**能少写就少写**。

## 决策顺序

```
① 这个功能真的需要写吗？
② 项目里是不是已经有类似代码？
③ 标准库能不能解决？
④ 平台原生能力能不能解决？
⑤ 已安装依赖能不能解决？
⑥ 能不能用一行代码解决？
⑦ 最后才写最小可用实现
```

## 解决的问题

| 问题 | 说明 |
|:-----|:------|
| 过度工程 | 小需求写成大架构 |
| 乱加依赖 | 标准库能做的事也要装包 |
| 重复造轮子 | 项目里已有却重写 |
| 改动范围太大 | 本来改一处结果动一片 |
| 只修表象 | 没找根因，局部打补丁 |

## 不省的部分
安全、输入校验、错误处理、数据保护、可访问性 **不能省**。

## 模式

| 模式 | 说明 |
|:-----|:------|
| lite | 轻度约束 |
| full | 默认强度 |
| ultra | 更强极简倾向 |
| off | 关闭 |

## 对我（k）的启发
- 回复也遵循这个原则：能不写就不写，能复用就复用
- 先看现有 Skill/知识库能不能解决，再创作新内容
- 最小改动完成需求，不堆砌不必要的信息
