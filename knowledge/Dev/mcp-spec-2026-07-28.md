# MCP 2026-07-28 规范候选版 — 最大规模升级

> 来源：AI 早报 7.29 + 官方博客验证 · 2026-07-31 落地

## 核心变化：无状态协议核心

| 旧（2025-11-25） | 新（2026-07-28） |
|-----------------|-----------------|
| initialize/initialized 握手 | 无握手，每个请求自包含 |
| Mcp-Session-Id header（会话粘滞） | 无会话，普通 HTTP 负载均衡即可横向扩展 |
| 有状态双向 | 请求/响应无状态 |
| 需要 sticky session / 共享会话存储 | 纯轮询负载均衡，无状态网关 |

**意义**：MCP 服务器可以部署在 serverless/edge 基础设施上，这是从"开发者笔记本协议"走向"企业级网关协议"的转折点。

## Extensions 成为一等公民

- 扩展用 reverse-DNS ID 标识（如 `io.modelcontextprotocol/tasks`）
- 通过 capabilities 的 `extensions` map 协商
- 独立版本管理，独立于核心规范演进
- 两个官方扩展随发布：

### MCP Apps (SEP-1865) — 服务端渲染 UI
- 服务器声明 HTML UI，宿主在**沙箱 iframe** 中渲染
- 工具预先声明 UI 模板 → 宿主可预取、缓存、安全审查
- UI 动作走同一 JSON-RPC 通道 → 所有 UI 操作走同一审计路径
- 不支持 Apps 的宿主自动降级为纯文本/结构化数据

### Tasks — 长任务扩展（从实验特性转正）
- 旧：同步工具调用阻塞等待
- 新：`tools/call` 返回 task handle → 客户端用 `tasks/get`/`tasks/update`/`tasks/cancel` 驱动
- `tasks/list` 被移除（无会话时无法安全列出）
- **服务端主导**：客户端声明支持，服务器决定何时作为任务运行

## 授权强化

- 对齐生产级 OAuth 2.0 / OIDC 部署
- 连接企业身份系统（Entra/Okta）无需变通方案
- Enterprise Managed Authorization (EMA) 扩展：管理员一次授权，用户经 IdP 组继承

## 治理机制（3 项）

1. **功能生命周期政策**：Active → Deprecated → Removed，每阶段至少 12 个月
2. **扩展框架**：新能力以 opt-in 扩展发布，成熟后才可能进核心
3. **一致性要求**：Standards Track SEP 必须配套一致性测试用例才能转正

## 迁移清单（如果维护 MCP 服务器）

- [ ] 审计对 `Mcp-Session-Id` / 隐式会话状态的依赖 → 显式 handle 模式
- [ ] 实验版 Tasks API → 新无状态生命周期
- [ ] 错误码 `-32002` → `-32602`
- [ ] 规划 Roots / Sampling / Logging 在 12 个月弃用窗口关闭前迁移
- [ ] 服务端发起的 elicitation/sampling → `InputRequiredResult`

> ✅ **2026-08-03 已评估（本栈不适用）**：当前体系 jlc-mcp（38 工具）/ codebase-memory-mcp 均为本地进程型无状态 MCP，无 Session-Id / 旧 Tasks / `-32002` 错误码依赖 → 迁移清单无需执行。未来新装 MCP 服务器时按下方「对我们体系的影响」执行（优先 stateless 2026-07-28 规范实现）。

| 现有工具 | 影响 |
|---------|------|

| 规则 #2 MCP 配置铁律 | 新增：检查 MCP 服务器是否依赖 Session-Id，新装优先选 stateless 版 |
