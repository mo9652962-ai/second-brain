# Agent Autoloop — 让命令行 Agent 自己接活的中台

> W45 精选（新面孔）。**4,003★ / 154 commits / 24 contributors / v1.6.4（2026-11-08，5 天前建仓）/ MIT**。中文项目，Node 24+，Windows 原生支持。
> 真实性：**高**——5 天 154 commits、24 贡献者、每天 2-3 个 release，是高频迭代的真项目，不是刷星。

## 一句话定位

把 Claude Code / Codex / dsh 这类「人守着终端」的 CLI agent 变成**事件驱动后台工**：定时任务、GitHub Issue、线上告警进来 → 内核按规则派给某个 agent 在某个目录干 → 干完一轮就退出 → 遇到「删数据/重启服务/花钱/对外发消息」才推卡片找人拍板 → 人回答后**接着原会话**干完。

## 为什么它值得看：内核设计（约 1,850 行，零运行时依赖）

内核不读系统时钟、不用随机数、不向外发请求，插件主动连进来——同样输入永远同样结果。四个机制都是借经典计算机系统：

| 机制 | 来源 | 做法 | 解决的问题 |
|:--|:--|:--|:--|
| **挂起零消耗** | 进程挂起 | 等人拍板时进程直接退出，等待状态存库；人答了再拉起原会话 | 等待期间不占进程、不烧 token（三天不回就三天不花钱） |
| **事件溯源** | event sourcing | 所有状态从一条只追加的日志算出来，日志+索引同事务落盘才应答；`agent-autoloop why 1` 查任意一轮来龙去脉 | 进程被强杀不丢已确认的事；格式变了从日志重建，不写迁移脚本 |
| **指令数据分离** | SQL 参数化 | Issue 标题/正文等外部文字**只作为资料写进文件，不拼进提示词**；提示词里只有校验过的类型、编号、链接；`cwd`/`agent`/`access` 只由本机规则决定，事件里带这些字段直接拒收 | **prompt injection 的架构级防线** |
| **跳数熔断** | 网络 TTL | Agent 交回的事件再派给 Agent，层数一路累加，经过人工提问和定时复查也不清零；超 8 层只记录不派活并弹卡片 | Agent 之间互相派活无限循环 |

## 插件体系（四个方向都可换）

| 方向 | 内置 |
|:--|:--|
| 事件来源 | GitHub Webhook / GitLab Webhook / HTTP 接口 / 定时规则（cron）/ Issue 轮询 |
| Agent | Claude Code / Codex / ACP / **DeepSeek Harness** / 通用命令（任何「收提示词、打印最后一条回复」的 CLI） |
| 通道 | 桌面通知（默认开）/ 飞书 / 钉钉 / 企微 / Slack / Discord |
| 交付 | `delivery` 插件：PR 打 `deliver` 标签 → 审代码 → 等 CI → 合并 → 等部署 → 核对线上版本 |

**Hermes 接入命令（README 给的）**：`hermes chat -Q -q {prompt}`。

## 规则就是一份 JSON

```json
{ "name": "早报", "when": { "cron": "0 9 * * *" }, "to": "codex", "cwd": "~/notes",
  "prompt": "整理昨天的笔记和提交，写今天的早报。" }
```

- 外部事件同理：`"when": {"source":"github","types":["issues.opened"]}`，可加 `parallel`、`skill`、`resume`
- `pause/resume/run` 不改规则文件；`check` 校验草稿；`rules explain` 看生效规则与下次定时；`emit --dry-run` 预演派给谁
- 改错了/文件读不到 → **继续按旧规则跑 + 弹卡片提醒**（fail-safe 而非 fail-open）

## Agent 与中台的唯一约定

「在最后一条回复里交代结果」。需要请示就在回复末尾附一段 ```agent-autoloop``` 代码块，支持 `ask`（提问）/`notice`（通知）/`resolve`（结案）/`later`（预约复查）/`events`（触发新事件）。JSON 写错只在原会话里重写那一段，**不重做已经干完的业务**。

## 💎 可借鉴点

| 借鉴 | 映射到 sora 的现状 | 落地动作 |
|:--|:--|:--|
| **指令数据分离** | Hermes cron 的 prompt 里会内联网页/Issue 文本 → 有注入面 | 定规矩：外部文本先落盘成文件，prompt 里只写路径 + 校验过的元数据；**这与今天 AGENTS.md 被拦截（检测到注入）的事件直接呼应** |
| 跳数熔断（TTL 8） | 多 agent 委派可能 A→B→A 循环 | 给 `delegate_task` 加「委派深度」概念，超过 3 层禁止再委派 |
| 挂起零消耗 | cron 现在是「跑完就退」，已符合；但等待人工审批时仍占会话 | 需要人拍板的任务，先落盘状态再退出，等回复再拉起 |
| 事件溯源日志 | Hermes 有 agent.log，但不是「状态可重建」 | 关键自动化（闲鱼接单、墨题部署）保留只追加的操作日志，出问题能复盘「为什么跑了这一轮」 |
| fail-safe 规则加载 | 配置改坏就崩是常见坑 | cron 脚本读配置失败 → 用上一份好的 + 告警，不静默停摆 |
| 卡片式审批 | sora 在手机上处理事务 | 需要拍板时给「一句话 + 2-3 个选项」，不给长报告 |
