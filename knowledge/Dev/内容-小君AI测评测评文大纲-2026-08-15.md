## 正文结构

### 1. 项目是什么（60 秒）
- 小君AI测评：输入项目描述 → 输出全套 AI 方案（策略/模型/Agent/GitHub 参考/成本估算/Prompt 生成）
- 技术栈：Next.js 14 + better-sqlite3，6188 行，依赖极简
- 名字撞车：阿里 AgentScope 是开发框架，这是评估平台——同名隐患

### 2. 实测过程（干货段）
- 部署：npm install → dev 3.3s Ready → 知识库自动初始化（103 条种子）
- 配 Provider：DeepSeek 连接 test 通过
- **坑 1**：模型名 `deepseek-v4-flash-260425` 被拒 → 官方 API 只认 `deepseek-v4-flash`（中转别名 ≠ 官方 ID）
- **坑 2**：不配 `DATABASE_ENCRYPTION_KEY` 连接不持久化，重启就丢
- **坑 3**：dev 和 build 共用 .next → `Cannot find module './682.js'`（部署 Next.js 的人秒懂）

### 3. 报告质量验证（有图有真相）
- 真实评估（电商网站）：25 秒出 54KB 报告
- 六维评分：技术可行性 82 / Agent 适配度 79 / 风险可控度 67
- GitHub 核验：commerce 14K★ / spree 15.6K★ / reaction 12.4K★——真实数据，不编造
- 策略判定：「基于开源二次开发，置信度 92%」——有依据

### 4. 发现的 bug + PR 故事（差异化内容）
- 首次初始化知识库就崩：`SQLITE_CONSTRAINT_PRIMARYKEY`
- 根因：种子数据 2 个重复 id（mcp-brave-search / plugin-github-copilot）→ 裸 INSERT 撞主键
- 修复：删 2 行 + 验证 6/6 测试全绿 → fork → PR（10 分钟全流程）
- 论点：**开源项目再小，实证测试都能找到真问题**

### 5. 竞品对比（格局）
- 纯模型选型红海：modelcompare / BenchLM / Ofox / chooseaimodel（5+ 个）
- 小君差异化：全套方案（Agent+Skill+MCP+Workflow+Prompt）不只是选模型
- **PawBench 数据**：工具/框架选对 > 模型选对（qwen3.6-plus+QwenPaw 76.5 > qwen3.6-max-preview+Hermes 70.2）

### 6. 值得学的（架构）
- 知识库 + 来源核验 + 规则引擎三件套
- 「报告只出不核验数据」原则
- 模型目录带 lifecycle：旧 ID 自动标 deprecated 提示迁移（DeepSeek 旧别名坑）

### 7. 结论 + 评分
- 给分：功能 7/10（真实能用）、架构 8/10（思路清晰）、成熟度 4/10（3 stars 早期原型）
- 适合谁：想研究 AI 选型实现的人 / 部署学习者
- 不适合谁：当产品用（名字撞车 + 单用户）
