# 别吹"独立开发"——学生应先学协作

## 核心论点

1. **"沉默的大多数"才是真相**：90% 的独立项目烂尾，但算法不推这些——只推成功故事。
2. **过早追求全栈 = 挖空地基**：同时追十只兔子，一只都抓不住。
3. **独立开发学不会协作**：没有 code review、没有需求对齐、没有冲突处理——坏习惯自强化。
4. **协作者比独狼更值钱**：面试官看的是你在不同项目里被合并的 PR、和维护者的技术讨论、在不同代码风格间切换的能力。

## 适合新手投稿的开源平台

### 1. up-for-grabs
- **定位**：专收录适合新手的开源项目
- **特点**：索引上千个项目里标记了 `good first issue` / `first-timers-only` 的任务
- **任务类型**：修拼写错误、补文档、加类型注解——不难，但你会被迫阅读 CONTRIBUTING.md、遵守代码规范、接受陌生人的 review
- **网址**：https://up-for-grabs.net

### 2. 24pullrequests
- **定位**：每年 12 月圣诞月活动，鼓励开发者在 24 天内给开源项目提 24 个 PR
- **特点**：从修文档到修 bug 到加测试，每完成一个点亮一格
- **效果**：一个月下来，GitHub 主页铺满跨项目的合并记录——比半成品"独立项目"值钱得多

## 金句（可复用）

- "独立开发是目标，不是起点。先学会在别人的代码上跳舞，再去盖自己的房子。"
- "一个人写代码，错误自我强化，坏习惯越积越深。"
- "在成熟的协作体系里当一个靠谱的贡献者——听起来平淡，长期价值高出几个数量级。"

## 可输出的场景

- B站/公众号："为什么我不建议大学生独立开发"（踩坑/认知类）
- 闲鱼接单话术：修代码 bug 才是真功夫，别只盯着做一个完整项目
- 面试准备：用 24pullrequests 铺 GitHub 主页
