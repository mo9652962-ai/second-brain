# 📌 知识库查询依据规则 — Query Attribution Rules

> **目的**：回答必须显式标注来源页面——「回答标来源」不是可选项，是纪律。
> 依据：OpenAI 引用格式化指南 + RAG claim-attribution 方法论 + Karpathy LLM-Wiki 查询规范（2026-09-05 千轮研究落地）

## 一、回答前（Query 流程）

1. **先读 [[index]]** 定位相关页面 → read_file 深入 → 再作答
2. **不凭记忆作答**：知识库有的信息必须从页面取；记忆只是辅助线索，不是依据
3. **跨域问题多查**：复杂问题至少查 2 个域（如「墨题商业」→ Projects/ + Productivity/）

## 二、回答中（Attribution 规则）

| 场景 | 要求 |
|:---|:---|
| 单页依据 | 句末标注 `(来源: `页面名`)` |
| 多页综合 | `基于 `A` 和 `B``——每句结论对应它的支撑页 |
| 知识库没有 | 明确说「知识库未覆盖，以下来自外部/推理」——**不硬贴来源** |
| 页面冲突 | 标出双方 `(`A` 说 X, `B` 说 Y)`，不擅自合并抹平 |
| 自己的经验 | 标注 `(经验/判断)`，与库内依据区分 |

## 三、回答后（Backflow 规则）

1. **有价值的回答写回**：实质综合分析存回 knowledge/（synthesis 或对应域），并在 log.md 记录 query
2. **发现缺口补录**：回答时发现知识库缺关键资料 → 创建页面或记入 [[MOC-Inbox]]
3. **不收藏即止**：回答了但没沉淀 = 这次查询白做

## 四、证据不足时（Abstain 规则）

- 检索不到相关片段 → 直说「资料不足」，不硬编
- 分数/依据太弱 → 降级为「推测」并说明为什么推测
- 证据冲突 → 并列展示，标注待人工裁决
