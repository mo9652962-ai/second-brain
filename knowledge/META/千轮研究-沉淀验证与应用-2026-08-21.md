## 新增 3 坑（千轮研究挖掘，程序员Orion 未覆盖）

- **#30 事务内做网络 IO**：@Transactional 含 MQ 发送 → 回滚后消息已发出 → 用「本地消息表 + 异步投递」
- **#31 幂等 key 缺状态**：同一 requestId 不同状态变更 = 不同请求 → key 含当前+期望状态 + 状态机校验
- **#32 连接池配置**：池大小 = core×2+spindle（不是越大越好）；获取连接超时 ≤3s；maxLifetime 30min

## 深化补充（已有坑的进阶）

| 坑 | 进阶补充 |
|:---|:---|
| 缓存一致性 | 延迟双删 + binlog/CDC(Canal) 终极方案 + TTL 兜底 |
| 分布式锁 | 锁管并发 ≠ 幂等管重复；Watchdog 续约；单机 AtomicBoolean + 分布式双保障 |
| 乐观锁 | version 字段法 + 秒杀场景用 Redis 原子/Lua |
| 操作审计 | 9 必记字段 + 事件化 + 哈希链防篡改 + 二级审计 |
| 幂等 | 幂等表（本地事务唯一索引）= 最优雅方案，比 Redis 锁可靠 |
