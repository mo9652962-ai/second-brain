# 事务内做网络 IO = 隐形炸弹（千轮研究 2026-08-21）

> 来源：千轮研究——千万级订单系统血泪复盘（TrueSight/阿里云 2026）+ 程序员Orion 系列验证

## 坑

`@Transactional` 方法内包含网络 IO（远程调用/MQ 发送）→ DB 事务回滚但 MQ 已发出 → 下游凭空生成订单/重复处理。

## 保命打法（事务最小化）

```
① 事务内只含必要 DB 变更——严禁网络 IO
② 「先落地，后通知」: 状态变更写本地「消息表」→ 事务提交 → 异步线程/定时任务投递 MQ
③ 幂等先行: 订单号作唯一键, 无论 MQ 重发多少次 DB 只处理一次
④ Redis 锁 + DB 事务边界错位: 锁释放时事务可能还没提交 → 别用锁包住整个事务
```

> 三原则：接口必幂等、事务必闭环、缓存不代替数据库。
