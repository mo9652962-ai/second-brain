# 代码审查铁律：跑通 ≠ 交付（程序员Orion · 抖音 2026-08-21）

> 来源：抖音 @程序员Orion（创业中）《代码跑通就算做完？不懂 Code Review 潜...》（1:21，页面章节要点）

## 学生思维 vs 商业团队

| 学生思维 | 商业团队标准 |
|:---|:---|
| 跑通了就提交 | 遵守协作规范（PR/MR + 审查）|
| 代码直接进主分支 | 代码经审查才能合并进主分支 |
| 「我写的没问题」| 代码质量 = 团队共同责任 |

> 跑通 = 能工作；审查 = 工作得好 + 不会炸 + 别人能维护

## 落地门禁（sora 已实践）

```
□ PR/MR + 至少一次 review（自己 + 外部第二意见）
□ 门禁: grep 冲突标记 + 构建 + 测试（墨题铁律）
□ AI 产出必审（ZCode/dsh 写完 review 才提交）
□ 外部审查: Gemini 第二意见 / ai-code-review / github-code-review 技能
```
