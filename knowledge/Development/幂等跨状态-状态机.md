# 幂等 key 缺状态 = 状态机崩溃（千轮研究 2026-08-21）

> 来源：千轮研究——线上事故复盘《Redis幂等性设计边界没覆盖跨状态请求》（2026-08 编程实验室）

## 事故

```
同一采购单回调 2 次: 第一次「采购成功」第二次「采购失败」
幂等 key 只含 orderId+requestId → 第二次被拦截
→ 但实际: 第一次更新为「采购中」, 第二次覆盖为「采购失败」→ 触发退款 → 状态机非法跳转
```

**根因**：幂等 key 校验了 requestId，没校验**状态变更方向**——同一 requestId 不同状态 = 不同请求。

## 保命打法（状态机 + 幂等双重校验）

```python
# 幂等 key 含当前状态 + 期望状态
key = f"idempotent:{order_id}:{request_id}:{current_status}:{expected_next}"
# 状态机校验前置: 检查当前状态是否允许转换
allowed = transitions[current_status]
if expected_next not in allowed:
    raise InvalidTransition
```

**要点**：状态机回滚场景——回滚后是新起点，旧幂等 key 应失效（TTL 1h + 转换成功后立即删除）。
