# Vibe Coding 项目部署全流程（下）——拆解

## 🎬 核心

> AI 写完代码只是开始。部署三段论：**选对部署方式 → 安全接入公网 → 上线后有人看着**。这三件事不需要会写代码，但需要沉淀为流程化方案。

```
部署方式选择(原生/Docker/面板) → 反向代理+证书+安全检查 → 监控报警+备份+托管+账单
        ↓                          ↓                          ↓
   无技术背景选面板            生产环境首轮 AI 只读          别让它失去控制
```

## 关键内容（章节要点）

### 一、部署方式三选一（00:52）

| 方式 | 适用 | 特点 |
|:---|:---|:---|
| 原生安装 | 有运维经验 | 直接装环境，可控但费心 |
| Docker | 标准化交付 | 环境隔离、可迁移 |
| **可视化面板**（1Panel/宝塔类） | **无技术背景首选** | **唯一「看得见」的方式**——作者明确推荐 |

### 二、把项目接上外面（03:48）

- **反向代理**：Nginx/Caddy 把内网服务暴露到域名
- **证书申请**：HTTPS 必备（Let's Encrypt 自动续期）
- **安全检查**：⚠️ **生产环境第一轮只让 AI 只读检查，避免误操作**（金句级纪律）
- 接入前确认端口/防火墙/权限边界

### 三、上线之后别让它失去控制（08:56）

| 事项 | 要点 |
|:---|:---|
| **监控和报警** | 挂了要知道（uptime 监控/告警渠道） |
| **数据备份** | 定期备份，出事能回滚 |
| **服务托管** | 进程守护（systemd/pm2），崩了自动拉起 |
| **账单管理** | 云资源费用盯住，防意外扣费 |

### 结语金句

> 「上线后半段决定成败的是：**路接不接得住、门有没有关上、跑起来之后有没有人看着**。」
> 「在使用 AI 时要反复确认其操作和后果，将相关流程沉淀为成熟的方案。」
