> 来源：抖音 @程序员Orion（创业中）《微服务不配超时机制？一个几毫秒的慢查询，能让你的全...》（1:32）

## 核心认知

> 不配超时控制 = 给项目安定时炸弹。**服务雪崩**是微服务最可怕的连环车祸。

## 雪崩机制

```
链路: 网关 → 订单服务 → 库存服务 → 商品服务 → 数据库
触发: 最底层一次偶发慢查询卡住
链条: 商品死等DB → 库存死等商品 → 订单死等库存
结果: 上游线程全被扣死 → 新请求涌入 → 线程池耗尽 → 系统当场瘫痪
```

## 全链路超时防线（保命清单）

| 防线 | 说明 |
|:---|:---|
| 网关超时 | 入口请求超时 |
| OpenFeign 调用超时 | 服务间调用（connect/read）|
| HTTP 客户端超时 | 外部 API 调用 |
| 数据库 connect 超时 | 连接池获取 |
| 读写超时 | SQL 执行 |
| MQ 消费超时 | 异步消息 |
| 线程池队列强度 | 控制并发上限 |

> 金句：宁可单个接口快速失败返回降级提示，绝不让一个下游服务拖垮整个系统。
