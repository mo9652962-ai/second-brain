# 深分页灾难：LIMIT OFFSET 别乱用（程序员Orion · 抖音 2026-08-21）

> 来源：抖音 @程序员Orion（创业中）《数据一多接口就卡死？别再无脑用 LIMIT OFF...》（1:XX）
> 转写 466 字（SenseVoice）

## 事故

```
LIMIT 10 OFFSET 100000 → 数据库先扫描跳过前 10 万条 → 全表扫描越来越慢 → CPU 拉爆
```

## 保命打法

```
小数据(后台管理列表): 传统分页 LIMIT/OFFSET
大数据(无限下拉流/消息列表): 游标分页
  → 传上一页最后一条 ID/时间戳 → WHERE id > ? ORDER BY id LIMIT n
  → 精准命中索引, 无无效扫描
```

**注意**：排序字段必须稳定唯一（如自增 ID/时间戳+ID），否则翻页重复/漏数据。

## 落地检查

```
□ 无限下拉/大表列表 → 游标分页（WHERE id > last_id）
□ 排序字段唯一稳定（id 或 created_at+id 复合）
□ 索引覆盖排序字段
```
