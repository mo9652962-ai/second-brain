# 写码前扫坑清单（开发 B 坑系列汇总）

> 2026-08-21 程序员Orion 系列 11 条沉淀浓缩。**写代码前扫一遍，交付翻车率直降**。
> 用法：接任何开发任务 → 对照本清单逐项检查设计 → 该改的改完再写码。

## 一、接口安全 5 坑（攻防一体）

| # | 坑 | 写码时怎么查 | 参考 |
|:--|:---|:---|:---|
| 1 | **前端隐藏按钮 = 安全？** | 每个管理接口后端独立鉴权（不信前端 role）；默认拒绝 | 前端隐藏≠安全.md |
| 2 | **参数/幂等/限流缺失** | 入口参数校验；下单/支付接口幂等；验证码/发送类限流 | 接口三件套.md |
| 3 | **换 ID 拿别人数据（IDOR）** | 查询带 user_id 过滤（WHERE id=? AND user_id=?）| IDOR.md |
| 4 | **上传只看后缀** | 四层检查：限大小/验内容(magic bytes)/随机名/隔离禁执行 | 文件上传四层.md |
| 5 | **验证码无后端限流** | 后端限频（手机号/IP/设备）+ 人机验证 + 熔断 + 有效期 | 验证码限流.md |

## 二、性能 3 坑

| # | 坑 | 写码时怎么查 | 参考 |
|:--|:---|:---|:---|
| 6 | **循环调外部 API（自我 DDoS）** | 改批量接口；没批量上 MQ/延迟队列限频 | 循环调API.md |
| 7 | **for 循环插库（N+1 通讯）** | executemany / <foreach> 批量 SQL + rewriteBatchedStatements | 循环插库.md |
| 8 | **本地缓存跨节点（脏数据）** | 多节点部署用 Redis 全局缓存，关自带缓存 | 循环插库.md |

## 五、API 契约 1 坑

| # | 坑 | 写码时怎么查 | 参考 |
|:--|:---|:---|:---|
| 14 | **改返回字段/结构（前端白屏）** | 上线接口不删字段不改结构；必须动 → API 版本控制（v1/v2 并存）| 接口契约.md |
| 15 | **空 catch 吞异常（静默失败）** | 能恢复→弹窗提示重试；致命→记日志；关键流程→返回明确失败状态 | 空catch吞异常.md |
| 16 | **并发超卖/覆盖（先查再扣）** | 条件更新兜底：UPDATE ... WHERE stock > 0，影响行数=0 报错（乐观锁）| 并发超卖.md |
| 17 | **跑通就交付（无 Code Review）** | 代码经审查才能合并/交付：PR + review + 门禁（grep 冲突/构建/测试）| 代码审查铁律.md |
| 18 | **数据库公网裸奔（3306 暴露）** | VPC 私有子网：DB/缓存不分配公网 IP，仅内网通信；远程用堡垒机/SSH 隧道 | 数据库公网裸奔.md |
| 19 | **缓存一致性（忘了删/TTL 同点）** | 先更库后删缓存；TTL 加随机抖动防雪崩 | 缓存一致性.md |

## 六、通用排障顺序（出问题时）

```
① 查自己业务接口/参数/字段值（排除 90%）
② 查外部接口（微信/支付宝/短信）
③ 查权限/配置（开通状态/回调域名/appid）
```

## 使用流程（接开发任务时）

```
1. 读需求 → 对照「接口安全 5 坑」检查设计（鉴权/校验/IDOR/上传/限流）
2. 涉及性能 → 对照「性能 3 坑」（批量/缓存/队列）
3. 涉及架构 → 对照「架构 2 坑」（单体/超时）
4. 涉及支付/数据 → 对照「支付/数据/合规 3 坑」
5. 写码 → 测试（web-api-testing 边界/并发）→ 交付前再过一遍
```
