# 缓存一致性（程序员Orion · 抖音 2026-08-21）

> 来源：抖音 @程序员Orion（创业中）《Redis 塞满就完事了？缓存忘了删，老板改的价格...》（1:19）
> 转写 467 字（SenseVoice）
> 与「循环插入与缓存-两个夺命坑」的坑 1 互补，组成缓存三件套

## 两个坑

```
坑1 更新忘删缓存: 老板改价 9.9 → 缓存没清 → 几万用户看 99 → 炸片
坑2 TTL 同点过期(雪崩): 所有缓存 12 点集体失效 → 海量并发砸 MySQL → 宕机
```

## 保命打法

```
① 数据更新: 先更新库, 后删缓存 —— 绝不修改缓存内容, 直接删, 下个请求查最新
② TTL 随机打散: 1小时 + 1~10分钟随机抖动 → 绝不同一秒失效
```

## 缓存三件套（完整）

1. **Redis 全局缓存**（多节点不用本地缓存 → 防脏数据）
2. **先更库后删缓存**（更新路径）
3. **TTL 随机抖动**（防缓存雪崩）

> 金句：缓存不是塞进去就完事，最难的是保证一致性。

## 落地检查

```
□ 更新/删除操作后: 删对应缓存 key（DEL），不是改缓存
□ TTL = base + random(1~10min)
□ 缓存 key 设计: 业务前缀+ID+版本，防错乱
□ 兜底: 缓存 MISS 时 DB 查询 + 回填（防穿透可加空值缓存/布隆）
```
