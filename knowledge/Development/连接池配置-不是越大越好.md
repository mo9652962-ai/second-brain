# 连接池配置：不是越大越好（千轮研究 2026-08-21）

> 来源：千轮研究——HikariCP 官方 Wiki About Pool Sizing + 阿里云 HikariCP 调优指南

## 三大常见错误

```
① 最大连接数拍脑袋（500）→ 每连接 2-4MB 内存 → 1-2GB 白耗
② 超时参数用默认（30s）→ 线程池被等待线程占满
③ 不设 maxLifetime（0）→ 僵尸连接
```

## 正确配置（已验证模板）

```yaml
maximum-pool-size: 25      # 8核CPU按公式算17, 留余量25
minimum-idle: 5
connection-timeout: 3000   # 3秒快速失败（核心链路1s内）
idle-timeout: 1800000      # 30分钟回收空闲
max-lifetime: 1800000      # 30分钟强制换新
leak-detection-threshold: 60000  # 60秒未归还报警
```

**池大小公式**：`connections = (core_count × 2) + effective_spindle_count`（SSD 用 core×4）
**多实例**：`(数据库 max_connections × 0.8) / 实例数`，留 20% 余量
**铁律**：小池子饱和 + 线程等待连接（10 连接可扛 3000 用户 6000 TPS）
