# 并发超卖：条件更新兜底（程序员Orion · 抖音 2026-08-21）

> 来源：抖音 @程序员Orion（创业中）《1件库存卖给2个人？你以为的偶发Bug，其实是致命...》（1:11）
> 转写 419 字（SenseVoice）

## 事故模型

```
先查库存 → 够 → 扣减   (新手写法)
两人同时下单 → 同时查到剩 1 → 同时放行 → 同时扣减 → 库存变 -1
同理: 两人同时改配置 → 后提交覆盖前人
```

## 保命打法：数据库条件更新（乐观锁）

```sql
-- 库存减 1, 条件库存 > 0
UPDATE product SET stock = stock - 1 WHERE id = ? AND stock > 0;
-- 影响行数 = 0 → 被别人抢先 → 报错打回
```

```python
cur = conn.cursor()
cur.execute("UPDATE product SET stock = stock - 1 WHERE id = ? AND stock > 0", (pid,))
if cur.rowcount == 0:
    raise SoldOut("库存不足")
```

## 核心认知

> 并发问题最阴险：**低流量岁月静好，高流量集中爆炸**。单人测试通过 ≠ 系统能扛并发。

## 落地检查

```
□ 扣库存/扣余额/改配置 → 条件更新 (WHERE stock > 0 / balance >= amount / version = ?)
□ 影响行数判断 → 失败报错打回
□ 订单唯一: 幂等键 (防重复提交, 呼应接口三件套)
□ 高流量压测: 并发 N 请求验证不超卖
```
