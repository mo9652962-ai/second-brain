# SOP-002: 技术与研报深度调研自闭环流程

- **ID**: SOP-002
- **Category**: RES（研究）
- **状态**: Active
- **维护者**: k

## 1. 前置条件与触发上下文

- **触发**: 新工具/新技术研究 / 千轮研究 / 需要可信结论的调研
- **前置**: 搜索引擎可用（web_search/curl 兜底）/ 代理可用（国外源）
- **原则**: 多源交叉验证，不轻信单一来源

## 2. 确定性执行步骤

```
① 明确调研范围与边界指标
   - 问题是什么 / 要回答哪些子问题 / 结论给谁用
② 多源交叉验证
   - 学术论文（arXiv/OpenAlex）
   - 官方文档（官网/帮助中心/API 文档）
   - 权威媒体/实测（博客/杂志/社区实测）
   - 至少 2-3 个独立来源确认同一事实
③ 标注数据时效性与置信度
   - 日期（信息发布/更新时间）
   - 置信度: 高（多源一致）/ 中（单源可靠）/ 低（推测）
④ 生成结构化对比矩阵 + 落地建议
   - 表格对比（维度 × 选项）
   - 明确「下一步做什么」
```

## 3. 验证与验收边界

```
✅ 每个关键结论有 ≥2 来源
✅ 报告含日期/置信度标注
✅ 输出可执行建议（不是资料堆砌）
✅ 已存知识库（knowledge/ 对应分类）
❌ 未达标准: 单一来源断言 / 无落地建议
```

## 4. 异常恢复与常见陷阱

```
⚠️ 陷阱: web_search 后端挂（Exa SSL 错误）→ 换 curl 直连 bing/百度 或走代理
⚠️ 陷阱: 海外页面被墙 → FlClash 代理 + --ssl-no-revoke
⚠️ 陷阱: 搜索结果含 AI 生成内容（2026 常态）→ 优先官方域名/权威媒体
⚠️ 陷阱: 地区限制结论（如 Gemini 大陆可用性）→ 按入口拆开分析（网页/API/App 规则不同）
⚠️ 修复: 信息冲突 → 以官方文档 + 最新日期为准，标注冲突
```
