# SOP-006: AI 代码审查协作流程（Gemini 第二意见）

- **ID**: SOP-006
- **Category**: DEV（开发）
- **状态**: Active
- **维护者**: k

## 1. 前置条件与触发上下文

- **触发**: 项目代码需要深度审查 / Gemini 网页当第二意见 / 大模型交叉验证
- **前置**: Gemini 网页版（Pro 订阅）/ 目标代码可提取 / 本地测试环境
- **适用**: Sims4 联机协议、墨题等本地项目

## 2. 确定性执行步骤

```
① 提取核心代码:
   选协议/核心模块（500-1000 行最佳，1M 上下文内）
   生成「提问包」（md 文件: 背景说明 + 针对性提问 + 代码全文）
② 设计提问（关键——决定审查质量）:
   明确审查维度: 并发安全/协议健壮性/安全问题/逻辑 bug/性能
   要求输出格式: 按严重程度分级 + 【描述】【影响】【修复建议】+ Top3 总结
③ Gemini 审查（用户粘贴到网页执行）
④ 我逐条验证（关键步骤——防 false positive）:
   对照源码 line 号确认每个问题是否真实
   标记: 真·严重 / 真·中等 / 合理·低优先 / 误报
⑤ 修复（按优先级）:
   P0 安全/业务锁死 → P1 稳定性 → P2 优化
   每个修复: patch → 冒烟测试 → commit
⑥ 回归验证:
   网络层实测（真实连接测试关键流程）
   全过 → push
```

## 3. 验证与验收边界

```
✅ Gemini 发现逐条对照源码验证过（无盲信）
✅ 修复后冒烟测试全过（单测 + 网络层实测）
✅ 提交到 git（小步提交 + push）
✅ 备份原文件（.bak-日期）
```

## 4. 异常恢复与常见陷阱

```
⚠️ Gemini 也可能误报: 测试预期错误 ≠ 代码错误（先验证再修）
⚠️ commit message 提到但没改的修复 → 立刻补上（言行一致）
⚠️ 路径遍历修复要点: basename + 后缀白名单 + .. 检查
⚠️ 并发写 socket: 每连接独立锁（全局锁会死锁）
⚠️ 状态机修复注意: 单人房间可自测（non_host 空）vs 全员 ready（房主也要 ready）
```
