# 知识赋能方法论（Skill Engineering 2026）

> 2026-08-22 | 搜索引擎研究 | 来源：SoK Agentic Skills + Arize 6 规则 + Google ADK + Red Hat ACE + SKILL-KD
> **核心结论：好技能 = 紧凑的程序性专家知识 + 渐进披露 + 配对评估门控——不是越长的 SKILL.md 越好**

## 一、六大数据驱动规则（Arize，有实验数据）

| 规则 | 数据/依据 | 落地 |
|:---|:---|:---|
| 1. 人类专业知识为源 | 模型起草必须 eval 门控 | 知识底座（手册/复盘）→ 技能，不是凭空写 |
| 2. **紧凑优先** | compact +19.0 / standard +21.5 / 详尽文档只 +0.7 分 | **SKILL.md 主体紧凑，细节放 references/（渐进披露）** |
| 3. 加载最小相关集 | 1-3 技能最佳，多了掉精度 | 触发词精准，别堆技能 |
| 4. 测每个 model-harness | 文件可移植 ≠ 行为可移植 | 赋能后验证能跑通 |
| 5. 针对程序性缺口 | 惯例/工作流/脆弱 API 最值钱 | 复盘/踩坑笔记 = 最高价值底座 |
| 6. **配对 eval 门控** | with-skill vs without-skill 对比 | 每次赋能变更都评估提升 |

## 二、渐进披露架构（Google ADK / agentskills.io 规范）

```
L1 元数据 (~100 tokens/技能): name + description（常驻，技能菜单）
L2 指令 (<5000 tokens): SKILL.md 主体（按需加载）
L3 资源 (按需): references/ scripts/ templates/（需要才读）
```
**收益**：10 技能从 10000 tokens 基线 → 1000 tokens（90% 节省）
**落地**：我们已做对的——src-bug-hunting 主体紧凑 + scripts/ 分离 + 笔记外链

## 三、Red Hat 实战法则

1. **领域知识 > 能力补丁**：编码工作流/制度知识（RCA 流程/部署清单）= 持久价值；补模型缺口的技能（工具调用模式）会过时
   → **我们赋能的方向对**：知识库手册/复盘 → 技能（领域知识）
2. **混合架构**：scripts 做机械层（取数/格式化/验证）+ SKILL.md 做推理层（主观分析）——降 26% 成本
3. **L1 描述 = 搜索优化摘要**：具体做什么/输入/输出，加负面约束（"do NOT use for X"）
4. **L2 < 500 行**：超了拆 references/（SkillOpt 可自动压缩 90.4%）
5. **评估数据集是最宝贵资产**：真实案例集 + 期望输出（我们已有：DVWA/复盘/T3 案例）

## 四、技能生命周期（SoK）

```
发现 → 实践/精炼(Reflexion 反思循环) → 蒸馏(轨迹→可复用过程) → 存储
→ 组合 → 评估(监控漂移) → 更新(修订/退役)
```
- **SKILL-KD 对比蒸馏**：老师-学生轨迹对比 → 提炼行为差距 → 补丁验证 → 漂移感知合并
- 供应链安全：技能包要签名/依赖审计/版本固定（ClawHavoc 1200 恶意技能教训）

## 五、我们的赋能流程（v2.0 增强版）

```
① 发现: 扫描知识库 → 找「有手册/复盘但技能缺实战沉淀」的领域
② 评估基线: 记录技能当前能力（能做什么/缺什么）
③ 蒸馏: 知识底座(手册/复盘/踩坑) → 提炼可执行程序性知识
   规则: 紧凑优先(主体) / 细节外链(笔记路径) / 脚本分离(scripts/)
④ 注入: patch 技能加入「实战案例库/武器库/联动」章节
⑤ 验证: 技能可读 + 关键动作可执行（如 PCB 案例能复刻）
⑥ 记录: 完成清单 + 收益说明
⑦ 定期: 新复盘/笔记 → 自动考虑赋能（可持续循环）
```
