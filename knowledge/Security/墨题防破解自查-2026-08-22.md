## 二、v9.31 修复内容

```
① explanations.py deep-explain:
   - 挂 maybe_require_user（EPM_AUTH=1 时强制登录）
   - force_refresh 仅多人模式未登录拒绝（AUTH_ENABLED and user is None → 401）
     → 单用户模式（EPM_AUTH=0）user 恒 None，加 AUTH_ENABLED 条件保持原有体验
   - 防局域网匿名刷 force_refresh=true 无限触发 AI 生成烧 key
② ai.py /test: 挂 maybe_require_user（防匿名触发真实 AI 调用）
③ ai.py /profiles: 挂 maybe_require_user（防未登录读 AI 配置面）
验证: security_regression_smoke 11/11 + smoke2 22/22 全过
```

## 三、残余风险（建议后续 v9.32）

```
🟡 /chat + /speaking 无配额限制:
   多人模式（EPM_AUTH=1）下登录用户可无限对话/口语 → 烧 AI key 成本
   方案: ai_usage 表按 user_id 记录每日调用次数 + config 配置上限
   （/usage 已有月度聚合表结构，扩展为配额判断即可）
🟢 离线 APK SecureStorage key 可被逆向提取:
   攻击者提取 APK → 拿 SecureStorage 密钥 → 解密用户自配的 AI key
   方案: 提示用户 key 只存服务端（在线模式），离线 key 属本地信任边界
```
