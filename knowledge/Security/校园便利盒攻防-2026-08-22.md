## 二、攻击面清单（可绕过点，按风险排序）

### A. 数据库直连 fallback（最高风险面）
```js
// fetchPostForShare: 云函数失败 → 直接读数据库
wx.cloud.database().collection("posts").doc(u).get();
wx.cloud.database().collection("comments").where({postId:e, status:"active"}).limit(100).get();
wx.cloud.database().collection("market_goods").doc(a).get();
wx.cloud.database().collection("market_comments").where({goodsId:e}).limit(100).get();
```
**风险**：云开发数据库集合默认权限若为「所有用户可读」→ 未登录即可读全库（帖子/评论/商品含手机号等隐私字段）。分享场景特意做了 fallback = 开发者意图让匿名可读。
**验证**（SRC 授权下）：小程序控制台/开发者工具直接 `wx.cloud.database().collection("posts").limit(10).get()`，看是否返回数据。

### B. 云函数敏感 action 服务端校验（未知，需动态验证）
```js
// 管理/敏感 action（客户端仅前端判断 role==="admin"，真正校验在云函数服务端，包里不可见）
banUser / toggleTopPost / createAnnouncement / publishAnnouncement
endActivityZone / saveActivityZone / deleteAccount / deletePost / deleteMarketGoods
```
**风险**：若 dbOperations 服务端对以上 action 未校验 `role==="admin"` 或 openid 所有权 → 任意用户可封禁他人/置顶/发公告/删他人帖子。
**验证**：登录态下直接 `callFunction({name:"dbOperations", data:{action:"toggleTopPost", data:{postId:目标}}})` 看是否成功。

### C. 内容审核绕过（客户端关键词列表，可绕过）
```js
// checkContent 在 app.js 客户端实现（100+ 敏感词列表：政治/色情/赌博/毒品/违禁）
// 图片审核走 contentCheck 云函数，但文字审核纯客户端
```
**风险**：文字审核 = 纯前端过滤。直接调用云函数 `addPost`（绕过 Page 层）可发任意违规内容。
**验证**：构造违规文本直接 callDB("addPost")。

### D. 管理员 role 下发（login 云函数，若可伪造=全站管理员）
```js
// userInfo.role 由 login 云函数返回，客户端只读
// adminPanel 云函数（generateEmployeeQrcode/saveEmployee）——员工邀请体系可能成为提权入口
```
**风险**：若 adminPanel 的 saveEmployee/generateEmployeeQrcode 无服务端 role 校验 → 自建员工/生成邀请码 → 提权路径。员工绑定（bindInviteEmployee）链路值得测。
**验证**：普通用户调 adminPanel saveEmployee 看是否被拒。

## 三、动态验证方案（仅 SRC 授权下）

```
[1] 数据库直连: 控制台 wx.cloud.database().collection("posts").limit(10).get()
    → 有数据 = 高危越权读（截图留证）
[2] 敏感 action: callDB("toggleTopPost", {postId: 任意}) 看是否成功
    → 成功 = 越权提权（先申请测试号，不碰真实数据）
[3] 审核绕过: callDB("addPost", {content: "违规词", ...}) 看是否入库
    → 入库 = 审核可绕过（低危，仅证明）
[4] adminPanel: callFunction adminPanel saveEmployee（自建员工）
    → 成功 = 提权链
[5] 分享越权: 分享链接中 postId 遍历 → doc().get() 读他人私密帖
```

## 四、加固建议（若为自建/客户产品）

```
① 数据库权限收紧: 所有集合改「仅创建者可读写」+ 云函数代理读写（禁客户端直连）
② 云函数统一鉴权: 每个 action 开头校验 openid 所有权 + role 白名单
   （敏感 action 必须服务端判 role，不能信客户端 userInfo）
③ 文字审核上云: checkContent 移到云函数（客户端关键词列表可绕过）
④ 管理员 role 服务端管理: login 只下发基础信息，role 每次从 DB 读（防缓存/伪造）
⑤ adminPanel 加服务端校验: saveEmployee/generateQrcode 必须 admin
⑥ 敏感字段脱敏: 帖子/用户返回时剥离手机号/openid 等
⑦ 订阅消息模板 ID 属敏感配置: 放云函数端，不下发客户端
```
