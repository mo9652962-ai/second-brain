# 漏洞报告格式规范（补天 2026-07 公告）

> 来源: 补天漏洞响应平台《漏洞报告提交格式规范》
> 影响: 所有提交到补天的报告（30+ 平台同类标准通用）

## 一、漏洞归属证明（必须）

```
① 漏洞 URL: 缺陷所在的完整网址
② 入口证明（按漏洞类型选择）:
   Web端   → 首页截图（含完整网址栏信息 + 页面内容）
   小程序   → 小程序图标 + 备案截图
   App端   → 应用名称 + 版本信息
截图须清晰可辨，包含完整网址栏信息及页面内容
```

## 二、完整过程 + 细节截图 + 文字描述

### 2.1 漏洞功能点来源截图
```
前端漏洞 → 提供前端 JS 地址及截图
Fuzz 发现 → 提供具体模糊过程和参数构造来源
注: 截图须完整，包含网址信息 + 整个页面
```

### 2.2 漏洞测试数据包与 POC（文字形式完整提供）
```
至少包含: 接口、主机、参数
示例格式:
  GET /favicon.ico HTTP/1.1
  Host: xxxxxxx
  Cookie: ...
  User-Agent: Mozilla/5.0 ...
  Accept: image/avif,...
  （完整请求头）
涉及多个数据包 → 数据包+截图逐对提交
```

## 三、验证结果证明及文字描述

```
漏洞验证存在证明 = 截图 + 文字说明（缺一不可）
```

## 四、其他注意事项

```
① 附件仅作辅助参考！所有报告内容必须完整写在漏洞细节中，不可仅依赖附件
② 截图须注明、完整，包含必要的网址、页面元素等信息
③ 文字描述须逻辑清晰、步骤完整，审核人员可依据报告复现漏洞
④ 不符合格式 → 平台要求补充完善，影响审核优先级和奖励发放时效
```
