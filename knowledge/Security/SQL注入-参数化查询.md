# SQL 注入：参数化查询铁律（程序员Orion · 抖音 2026-08-21）

> 来源：抖音 @程序员Orion（创业中）《你以为他在搜名字？他其实在删你的库！别再手动拼接...》（1:XX）
> 转写 461 字（SenseVoice）

## 事故

```
WHERE name = ' + 前端名字  (手动拼接)
攻击者输入: ' OR 1=1 -- → 免密绕登录后台
+ DROP TABLE → 数据库灰飞烟灭
```

> 你以为他传的是参数，其实他扔的是炸弹。

## 保命打法

```
① 绝对禁止手写字符串拼接 SQL
② 参数化查询: 变量换成问号占位, 数据库驱动处理转义
③ ORM 也不是免死金牌: 原生 SQL/模糊查询/动态排序都要单独防
```

> 铁律：用户输入永远不可信——能从前端传进来的东西，都默认他带着刀。

## 落地检查

```
□ 全仓搜字符串拼接 SQL（f"...WHERE..." / + 拼接）
□ 所有查询参数化（? 占位 / prepared statement）
□ 模糊查询 LIKE 用参数绑定 + 转义 % _
□ 动态排序字段白名单（防 order by 注入）
□ SRC 视角: 单引号/OR 1=1 测试授权目标
```
