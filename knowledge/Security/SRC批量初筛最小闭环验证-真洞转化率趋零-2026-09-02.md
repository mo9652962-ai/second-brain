# SRC 批量初筛最小闭环验证：真洞转化率 ≈ 0%

> 结论先行：**「Flash 批量初筛产出可疑点 → 人工确认赚小钱」这个假设被数据证伪。**
> 这不是坏消息——最小闭环的意义就是用最小成本验证 ROI，现在数据出来了，可以决定不继续投入。

## 一、验证过程（真实执行）

| 步骤 | 动作 | 结果 |
|:---|:---|:---|
| 1. 资产测绘 | `recon_pipeline.py lenovo.com --no-subenum` | 392 子域 / 201 存活 |
| 2. 目标提取 | 高价值四类（API/认证/管理后台/代码仓库）| 55 个目标 |
| 3. 批量初筛 | `batch_triage.py`（只读 GET + Flash 提取）| 26/55 成功 |
| 4. 结果统计 | 34 个可疑点 | 见下 |

## 二、核心数据

| 指标 | 数值 |
|:---|:---|
| 分析成功目标 | 26/55（29 个 SSL 失败/超时）|
| 可疑点总数 | 34 |
| **high** | **0** |
| **medium** | **1**（内部上游主机名泄露）|
| **low** | 33 |
| hardcoded_secret | 1（误报，见下）|

## 三、关键发现

### 1. 真洞转化率 ≈ 0%
34 个可疑点里，0 个 high、1 个 medium（`x-upstream-host` 内部域名泄露，补天对这类低危接受度极低）、33 个 low。**没有一条能拿去提交换赏金。**

### 2. Flash 有误报——BOOMR_API_key 是假秘密
唯一的 `hardcoded_secret` 是 `passport.lenovo.com` 响应里的 `BOOMR_API_key`。但 BOOMR（Boomerang）是 Akamai mPulse 的 RUM 性能监控 key，**本来就是设计成暴露在前端 JS 里的，不是秘密**。Flash 把它当成了硬编码密钥——印证「AI 产物必须人工审核」铁律。

### 3. 瓶颈不在模型，在信息泄露类低危本身
Flash 能跑、能提取（脚本全程跑通），但「信息泄露」这个类别在 SRC 里的赏金价值本来就低。真正值钱的「越权/未授权访问」类逻辑漏洞，需要**人工理解业务逻辑 + 构造请求**，批量初筛覆盖不到。

## 四、结论与决策

**负结果：批量初筛流水线 ROI 不成立，不继续扩大。**

| 假设 | 验证结果 |
|:---|:---|
| 「每天自动产出可疑点赚小钱」 | ❌ 证伪——34 条 0 条能换钱 |
| 「瓶颈是模型能力」 | ❌ 证伪——瓶颈是低危类别本身 |
| 「6-8 周大架构」 | ❌ 没必要——先跑最小闭环的决定是对的 |

### 下一步（如果还要继续 SRC）
**从「批量初筛」转向「定向深挖」**：
- 不铺开扫 55 个，而是盯住 1-2 个具体目标（如 `passport.lenovo.com` 认证链路、`baiyingmalladminsec` 管理后台）
- 做业务逻辑测试：越权、未授权访问、水平越权（IDOR）
- 这类洞需要人工构造请求，不是喂响应包能发现的
