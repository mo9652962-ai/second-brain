# 验证码接口防护：限流+熔断（程序员Orion · 抖音 2026-08-21）

> 来源：抖音 @程序员Orion（创业中）《AI写的验证码接口，差点刷光客户的短信余额》（1:42，页面章节要点）
> 系列：接口安全第五视角（①前端隐藏≠安全 ②接口三件套 ③IDOR ④文件上传 ⑤**验证码/限流**）

## 实测演示

测试环境连续请求几十次验证码 → 后台短信调用次数疯狂上涨 → 差点刷光客户短信余额。
**根源**：后端接口没做限流。前端 60 秒倒计时只能限制正常用户——**真正的保护必须放后端**。

## 后端 4 层保护

| 层 | 保护 | 防什么 |
|:---|:---|:---|
| ① 频率限制 | 手机号/IP/设备维度发送频率+次数 | 单点狂刷 |
| ② 拒绝异常 | 异常请求直接拒绝 | 批量脚本 |
| ③ 增加验证 | 人机验证（滑块/行为）| 自动化工具 |
| ④ 预警+熔断 | 每日发送上限 + 费用预警 + 自动熔断 | 成本失控 |

**验证码本身**：设置有效期 + 使用限制——旧验证码失效、验证失败过多锁定（防爆破）。

## SRC 挖法（攻防一体）

```
短信轰炸测试清单（授权目标）:
① 正常发一次验证码 → 抓包
② 绕过前端倒计时: 直接重放请求 (curl/脚本 循环)
③ 观察: 是否每次都能收到短信 (后端无频率限制 = 漏洞)
④ 验证码爆破: 4 位码无失败锁定 → 10000 次尝试
⑤ 验证码重用: 已用过的码还能不能用
```
- 短信轰炸 = SRC 常见中危漏洞（成本攻击：短信费/邮箱费）
