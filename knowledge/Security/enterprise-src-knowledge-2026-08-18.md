# 企业 SRC 系统性知识（2026-08-18 五轮千轮研究）

> 覆盖：平台全景 / 挖洞策略 / 审核规则 / 实战案例 / 合规成长
> 定位：企业自营 SRC（阿里/腾讯/字节/美团/京东等）专项作战手册

## 一、平台全景与偏好

### 各家收录偏好（同类漏洞 A 厂中危 B 厂不算！）
| 平台 | 高分漏洞 | 低分/忽略 | 奖励特色 |
|:---|:---|:---|:---|
| 腾讯 TSRC | 越权/支付绕过/权限绕过/小程序逻辑 | 孤立存储XSS/静态泄露 | 逻辑漏洞为王 |
| 阿里 ASRC | SQLi/命令执行/批量隐私数据 | 反射XSS/局部小bug | 高危权重拉满 |
| 字节 ByteSRC | 批量泄露(手机号/资料) | 单账号影响/非核心子站 | 批量>单点 |
| 百度 BSRC | 高质量高危 | 小bug | 1币=5元;月度前三5000/3000/1000;严重额外4-50万 |
| 京东 JSRC | 核心业务数据泄露 | 降级场景多 | 1积分=5元;成长守卫高危额外50-150%;特殊1-50万 |
| 小米 MiSRC | 核心系统权限 | 锁定时间内不收录 | 1贡献币=10元;季度LV1-3 |
| 360 SRC | 实际业务影响 | 测试环境0.1系数 | 点赞币=安全币;同系统3月只收3接口同类型 |

### 4 类全大厂通吃漏洞
```
① 业务越权（全平台通吃, 新手最优赛道, 改 ID 传参处）
② 敏感信息泄露（批量数据高收录）
③ 权限绕过（登录/付费限制）
④ 配置失误文件泄露（核心配置稳过初审）
```

## 二、挖洞策略

### 三大核心技巧
```
① 深耕边缘资产: 子域名/小程序/APP内嵌H5/旧版系统/新业务
   主站=别人啃过的骨头, 边缘=还没人碰的蛋糕
② 关注新上线业务: 漏洞率是旧业务3倍+, 有窗口期
   发现渠道: SRC公告 + 企业官方动态 + 子域名监控对比
③ 多看公开报告: 每天30分钟拆解1篇(还原信息收集/理解触发逻辑/迁移)
```

### 挖掘优先级
```
APP > 小程序 > Web（先小程序再 APP 再 Web）
新业务 > 旧业务；边缘 > 主站
```

### 8 大避坑
```
不看规则/报告模糊/伪漏洞/急于求成/泄露数据/重复提交/工具不熟/心态浮躁
```

## 三、审核规则与奖励机制

### 各家降级/忽略场景（提交前自查）
```
SQLi 无敏感数据 → 降级
RCE 在 VPC 动态容器 → 降级
需受害者交互 → 降级
影响范围极小(少量注册用户) → 降级
触发条件苛刻(特定浏览器XSS) → 降级
用非本人账号测试 → 降级/违规
测试环境数据 → 0.1系数(360)
通用漏洞锁定时间: 客户端3月/服务端1月(小米), 公开前10工作日(360)
修复中状态再提交 → 不收录(京东)
```

### 报告质量 = 额外收益
```
360: 点赞币(1:1 安全币)
小米: 详细报告 10-200 贡献币额外奖励(100-2000元)
京东: 高质量报告奖 500 元/月 3 名
字节: 成长体系单个漏洞额外 1200-9000 元
```

### 申诉机制
```
京东: 报告详情页「一键沟通」+ 申诉模板(定级评分/申请复测/历史评分差异)
银联: 一周内申诉 + 内部仲裁委员会(5 技术专家)
360: 评论区反馈 + security@360.cn 邮箱仲裁
小米: 官方邮箱沟通
通用: 简洁明了的沟通内容有助于快速解决
```

## 四、实战案例与技巧

### 案例库（真实可复用）
| 案例 | 漏洞 | 核心手法 |
|:---|:---|:---|
| 无限抽奖币 | 中危 | 分享赚币接口 points=15 → 改大数值；穷尽所有功能点 |
| 可控优惠券 | 中危 | 低价订单接口 token 替换为高价值券 token |
| 双小程序越权 | 高危 | A 查学号 → B 绑定 → 改 studentId 越权改他人信息 |
| sessionkey 任意登录 | 高危 | 快捷登录泄露 sessionkey/IV → 伪造任意手机号 |
| 云函数 openid 硬编码 | 严重 | adminConfig.js 硬编码管理员 openid → 伪造调用全云函数 |
| 弱类型绕过 | 高危 | 650000 vs 650000.0 绕过发货地区校验 |

### 关键技巧
```
① 信息串联: 多系统共用用户体系(A/B/官网/App)
   → 收集各种 ID(学号/userId/studentId/openid)
② 修改接口 > 查询接口(修改才决定影响)
③ 参数不只测值: 类型/格式/空值/小数/科学计数法
④ 云函数挖掘: 搜 admin → cloud → openid → 云函数名
   命名规律: getAllUsers_prod_v2 (后缀 _prod/_v2/_test)
⑤ 小程序反编译: 字符串常量不会被混淆, 关键词搜索有效
⑥ 不测试完所有功能点不放弃
```

## 五、合规与成长路径

### 职业化思维（业余 vs 职业）
```
业余: 碰运气找高危
职业: 目标驱动/过程可重复/时间成本/投入产出比
   (花100小时巨头挖中危 vs 花20小时中型挖同等级)
```

### 三层漏洞策略
```
底层: 低悬赏(练手, 批量自动化, 不耗核心时间)
中层: 标准赏金(收入基石: 存储XSS/越权/逻辑漏洞)
高层: 组合型(RCE/SSRF内网/认证绕过链, 价值倍增)
   "SSRF + 内网未授权Jenkins = SSRF→RCE 完整链条"
```

### 三个成长方向（阿里 ASRC 官方建议）
```
① 深度: 漏洞方向专精(读官方文档找设计缺陷>fuzz)
② 横向: 跨领域(web/app/iot 都往高危看)
③ 转向防御: 安全开发生命周期/企业防御专家
```

### 收入参考（真实）
```
陈广(全职猎人): 累计 300 万+ 赏金, 腾讯 Top 3
阿里王牌A计划: 黑桃A=月入30万能力/红桃A=5万/方块A=2万
先知顶尖白帽: 年入百万
→ 自由职业挖洞是长期主义(每年数百新项目上线)
```

### AI 挖洞定位（2026 行业共识）
```
AI 降低基础挖洞门槛, 但无法替代人工逻辑判断
厂商拒收 AI 报告根源: 幻觉/质量不稳定
人机协同: AI 处理重复工作, 人工做逻辑判断+验证
新人不可直接依赖 AI 入门, 需夯实网络/协议基础分辨幻觉
```
