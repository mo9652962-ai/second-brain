# 2026 CAD 千轮研究增强

> 2026-08-22 | 搜索引擎研究 | FreeCAD AI + CADIR + build123d 确认 + CAD-as-code 趋势
> **核心结论：2026 CAD 自动化三件套 = FreeCAD AI 工作台（自然语言出模型）+ build123d（CAD-as-code 首选）+ CADIR（跨后端可编辑）；接单场景自然语言出模型成为现实**

## 一、FreeCAD AI 工作台（ghbalf/freecad-ai，433★，2026-02）

```
功能: 聊天界面自然语言 → 3D 模型（Plan/Act 模式）
   Plan = 先审查代码再执行 / Act = 自动执行
工具调用: 50 个结构化 FreeCAD 操作（比裸代码安全可靠，undo 事务包裹）
支持 20 个 LLM provider: DeepSeek/Qwen/MiniMax/Gemini/Ollama 本地...
技能系统: 可复用指令集（enclosure/gear/紧固件孔/草图转图）
Skill optimizer: 自动测试-评估-修改循环改进技能
错误自纠正: 失败代码回传 LLM 重试（最多 3 次）
安全: 静态验证 + 子进程沙箱 + undo 事务
MCP: 可暴露为 MCP server（任何 MCP 客户端驱动 FreeCAD）
```

**接单价值**：客户一句话描述 → 出模型草稿 → 人工精修 → 交付。以前是「从空白画」，现在是「改草稿」。

## 二、CADIR（arXiv 2608.00891，跨后端可编辑中间表示）

```
问题: LLM 生成的 CAD 程序是后端特定的，跨软件不可编辑
CADIR: 115 个建模操作 + 构造图（记录操作/参数依赖/约束/拓扑选择）
   + Geometric Signature Matching（跨后端识别对应边面）
跨后端重建: FreeCAD/SolidWorks/Fusion 360 原生可编辑特征历史（NRR 1.0）
检索: 构造图检索（文本/图像查询，复用建模子结构）
实测: IoU +4.9% / 执行成功率 1.0（vs CQ 0.915/build123d 0.985）
```

**意义**：AI 生成 CAD 从「一次性脚本」走向「可编辑工程资产」——接单交付的可编辑性要求有望被 AI 解决。

## 三、CAD-as-code 2026 格局（fileformat 指南）

| 工具 | 范式 | 最适合 |
|:---|:---|:---|
| **build123d** | Python BREP（代数建模 obj += sub_obj） | 新零件首选、AI 驱动设计 |
| CadQuery | Python BREP（链式） | 遗留代码、配置器 |
| FreeCAD | 图形 + Python 脚本 | 约束驱动 + 装配 + 自动化 |
| OpenSCAD | CSG 脚本（mesh 输出） | 程序化/布尔树 |
| OpenCASCADE | C++ 几何内核 | 工业级 CAD 应用 |

```
AI CAD 管线（确认模式）:
自然语言 → AI → CAD 参数/代码 → CadQuery/build123d/FreeCAD
        → 几何内核（确定性验证）→ STEP/STL/3MF
关键: AI 生成指令仍需要确定性几何处理（LLM 只管意图，几何内核管正确性）
```
