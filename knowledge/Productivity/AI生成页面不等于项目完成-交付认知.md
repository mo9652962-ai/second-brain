# AI 生成页面 ≠ 项目完成：交付认知（程序员Orion · 抖音 2026-08-21）

> 来源：抖音 @程序员Orion（创业中）《AI几分钟生成一个软件页面，就代表项目已经做完了吗？》（1:25）
> 转写 503 字（SenseVoice）
> 定位：产品化/系统化交付主线的认知课（接「论文套餐」方案）

## 核心认知

> **页面出来了 ≠ 软件做完了**
> 软件定制真正花时间的：把「谁能看什么 / 谁能改什么 / 重复操作怎么办 / 异常数据怎么处理 / 上线后谁维护」全部变成清楚的规则

## AI 生成项目的 3 类真实问题（对照验证）

| AI 产物「看着做完」| 实际问题 | 对应沉淀 |
|:---|:---|:---|
| 两用户同时预约 | 并发重复预约成功 | 接口三件套（幂等）|
| 员工看别的门店数据 | 越权 | IDOR/后端鉴权 |
| 取消预约 | 退款/库存/通知全缺 | 业务闭环（软删除/状态机）|

## 报价逻辑（客户说「AI 免费做」怎么回）

```
客户买的不 = 几千行代码（AI 免费生成）
客户买的 = 稳定使用 + 出问题有人处理 + 业务变化还能改的系统
回应: "AI 可以生成代码, 但项目交付必须有人负责"
```

## 接单定价三层

```
① 代码费（AI 已打薄）→ 不值钱
② 规则设计费（权限/并发/异常/闭环）→ 核心价值
③ 维护负责费（上线后）→ 持续收入
```
