# 🃏 知识卡片 · 被保留的工具返回会被重复计费：单会话输入最高放大 14,293 倍

> **来源**：arXiv 2609.28585（Persistent Billable State）· 官方 abs 页 curl 直连逐项复核（2026-09-26，数字与速览笔记完全一致）· 全部数字来自论文摘要（官方源）
> **一句话**：多步工具调用 agent 的宿主运行时会把**上一轮的工具返回原样带进下一轮模型输入**，provider 就再计费一次——一个已被准入的恶意工具不需要你的凭据、不需要本地权限，就能把不可信数据变成**由你反复付费**的算力消耗；243 次实测中，单会话累计输入最高达首轮调用的 **14,293 倍**。

---

## 核心洞察 / 影响

| 维度 | 内容 |
|------|------|
| 新概念 | **persistent billable state（持久计费状态）**：被跨轮保留、并因此被重复计费的内容；宿主「是否/如何让它进入后续计费上下文」被形式化为 **persistent billable-state boundary** |
| 攻击面 | 六类 denial-of-wallet 向量，**无需受害者凭据、无需本地运行时权限**——工具在准入之后才发作（post-admission） |
| 放大实测 | 243 次执行：单会话累计输入最高 **14,293×** 首轮输入 |
| 成本归因 | 控制变量重跑：**保留原始历史使平均有效会话成本 +21.2%~35.9%**；压缩策略在依赖历史的任务上成功 **10/12、11/12**，而**删除只有 2/12** |
| 生态现状 | 扫描 **3,830 个公开 MCP server/transport 仓库**，只有 **71 个**暴露任何代码可见的防护代理，且**无一覆盖全部四类防护** |
| 防御落点 | 确定性历史变换 + **四条宿主侧不变量**（prompt 质量 / 上下文增长 / 递归机会 / 累计花费），在**再入上下文之前**拦截 |

## 关键数据 / 对 sora 的影响

1. ⚠️ **这条是「quota 危机」的成本侧解释**：k 的 cron 与 Hermes 会话天然长期保留工具返回（搜索结果、网页正文、文件内容、abs 摘要）——这正是「持久计费状态」的定义域。本次 429 配额事件里，**成本不只来自调用次数，也来自历史堆叠的重复计费**；9/28 重置前值得把「压缩后再入下一轮」当默认动作
2. ✅ **不要靠删除历史来省钱**：实测删除在依赖历史的任务上只有 2/12 成功，压缩才是 10/12、11/12——省成本的正确姿势是**压缩**不是**清空**（与 09-25 收录的 2609.29875「历史推理在状态外化后可安全遗忘，token −25~33%」同向互证）
3. ⚠️ **MCP 生态基本无防护**（3,830 → 71，且无一覆盖四类）：k 若接入第三方 MCP server / 工具链，**默认按「无防护」对待**，防护写在宿主侧而不是指望工具方
4. 💡 **可观测指标**：把「单会话累计输入 ÷ 首轮输入」当作一个可记录的成本异常信号——放大到两位数就是异常
