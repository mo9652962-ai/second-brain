# 🃏 知识卡片 · 批准的动作 ≠ 执行的动作：装前扫描不够，唯一可用边界在执行时

> **来源**：arXiv 10-04 速览「Agent 技能供应链：投毒、审计与授权」整节 8 篇 · **官方源**：arxiv.org abs 页（2609.38983 摘要原文已由 k 于 2026-10-04 curl 直连逐句核对）
> **一句话**：harness 的安全边界建立在一个几乎没人验证的假设上——「人类批准的 A = harness 执行的 A'」。这篇把它**系统性证伪**了，并给出六类静默替换；结论是：只在「工具调用那一刻」做字段校验，抓不住其中两类。

---

## 核心洞察 / 影响

| 维度 | 内容 |
|------|------|
| ① 假设被证伪 | **Approval Laundering**（[2609.38983](https://arxiv.org/abs/2609.38983)，Yang Wang，09-30 提交）：六种失败模式——**Scope（范围）/ Argument（参数）/ Temporal（时序）/ Tool（工具）/ Delegation（委派）/ Semantic（语义）**洗白，描述 harness 如何在批准后**静默把 A 替换成 A'**。作者直接 instrument **Claude Code 的 PreToolUse** 中介点做受控重复测量（每类 N=19–20 次，评分者一致性 kappa=1.0） |
| ② 防御的诚实边界 | 原型 **Approval Token** = 带密钥的能力 `Hk(principal, agent_id, session_id, tool, arguments, scope, expiry)`，由**永不把密钥交回 agent** 的中介签发；118 次 paired before/after replay（McNemar 精确检验）：**完全消除 Delegation 洗白**，对种入的会话身份不匹配构造也消除 **Temporal**（p<10⁻⁵）——但 **Scope 洗白按设计不受影响**、**Argument 洗白无显著下降（p=1）**。原因：这两类**不改变任何被记录的 dispatch 字段**，分歧发生在比「字段级验证器」能观测的**更深一层** |
| ③ 执行时授权三连 | **ActionGuard**（2609.39450）：把「生成上下文」与「授权上下文」**分离**——Reviewer 不接收可能被投毒的原始技能文本，只看「技能画像 + 近期 Tool Call + 本地脚本」，在 before-tool-call 拦截；ASR 相对既有守护降 **35.54–46.11 个百分点**、相对无守护降 **70.44 个百分点**。**ToolFence**（2609.37196）：把授权粒度从「审内容」改成「审**效果/能力**」，编译带类型授权蓝图；AgentDojo + Qwen3-max 上 ASR 降到近零、干净效用仅降 **3.80 个百分点**。**PACE**（2610.01349）：证明准入证据不可区分 → 唯一可用边界在**执行时** |
| ④ 权限最小性可测 | **Aletheia**（2609.39678）：「逐项撤权看还能不能过」——把规则请求的权限翻译成带类型语言，每次只去掉一项权限、跑未改动的规则与任务；仍能过 = 该权限**可省**（可弃性见证）。314 个 AIShellJack 攻击输入全部检出，5 个良性模板零告警，80 条人工核验的良性规则仅 **3 个误报（3.75%）** |

## 关键数据 / 对 sora 的影响

1. ⚠️ **「sora 说可以，k 照办」≠「k 执行的就是 sora 批准的那件事」**：六类洗白里最隐蔽的是 **Argument 与 Semantic**——批准「更新笔记」却顺手改了配置。可落地：审批记录写成**「对象 + 参数 + 范围 + 有效期」四元组**，执行前**回读比对**，不一致就停下重新确认
2. ⚠️ **只在工具调用那一刻做字段校验，天生抓不到两类洗白**：论文的 negative result 很硬——Approval Token 对 Scope/Argument 无效（p=1），因为它们不改任何被记录的 dispatch 字段。教训：门禁不能只看「调用了什么」，还要看「这一步被用户请求的哪部分证成」
3. 💡 **「谁做决定」和「谁审这个决定」必须分开**：ActionGuard 的杀手锏是 Reviewer **不看原始技能文本**（否则被投毒的文本会同时污染生成侧与审查侧）。可直接抄进 k 的工程结构——高风险工具（写文件 / 发网络请求 / git push）前挂一个独立 Reviewer
4. ✅ **「我觉得它安全」可以换成「逐项撤权它还能过」**：Aletheia 给了一条干净、可生成审计证据的判据——比静态读规则文本可靠得多，3.75% 误报率说明可实用

## 行动项

- [ ] 把**审批记录**升级为「对象 + 参数 + 范围 + 有效期」四元组，执行前回读比对（对应 Argument / Temporal 洗白）
- [ ] 高风险工具调用前加**独立 Reviewer**：不接收原始技能/规则文本，只依据「用户原始请求 + 近期调用 + 本地脚本」判定
- [ ] 给 k 自己的高风险脚本做一次**权限最小性自查**：每去掉一项权限跑一次功能测试，能过就删掉该默认授权
- [ ] 装前扫描结果**只当信号不当准入判决**（Pretext 已证明扫描器可被绕过：对冻结检测器 97%、对协同自适应检测器 77%）

## 为什么重要

- **直击 k 自身**：k 的 cron 链、审批语义、`skill_manage` 安装流程正是这条攻击链的三个环节；10-02 卡片讲的是「**装的时候**危险（扫描/链式攻击）」，今天这张补上「**装完之后、执行时**危险（批准≠执行）」——两半合起来才是完整边界
- **不是孤证**：同窗口 8 篇独立工作（分类法 / 上下文分离 / 授权粒度 / 证据不可区分 / 权限最小性）互相印证，且都带可复现的量化结果
- **内容选题**：「你点的那下『同意』，agent 真的照做了吗？」——六类洗白 + p=1 的诚实负结果，是能讲清、有出处、反直觉的实战题材（AI 博主工程向）
