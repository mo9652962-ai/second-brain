# 🃏 知识卡片 · 0.8B 决策模型能跑在本机：一次前向给概率，22ms 出一个判断

> **来源**：GitHub `firelex/jeff` README + Hugging Face 模型卡（**官方源**，2026-09-29 经 r.jina.ai 直读原文核对）· HN 428 分 / 160 评论（Algolia 官方 API）· GitHub API 实测 **583★ / 19 fork**（2026-09-28 建仓，09-29 仍在推）
> **一句话**：把「选择」从大模型逐 token 生成里剥出来——0.8B 小模型用**一次前向传播**给每个选项一个校准概率，1.7 GB 权重、本机可跑，类别不用出现在训练数据里。

---

## 核心洞察 / 影响

| 维度 | 内容 |
|------|------|
| 是什么 | 在 Qwen3.5-0.8B/2B、Gemma 4 E2B 上微调的**零样本分类器**，沿用 Jev（TypeSafe System One）的请求格式，**不生成文本、不用解析** |
| 怎么用 | 自然语言描述情境 + 列出选项 → 返回每个选项的概率 + 选中项 + 置信度；三种题型 `choice`（≤26 选项）/ `noul`（是/否概率）/ `score`（你描述的分值） |
| 与 Jev 的关系 | 同格式、**非官方**（不隶属 TypeSafe）；训练代码基于开源 AutoJev 配方 |
| 边界（作者自述） | 它是**分类器不是规划器**：让它预测「两回合后有车来」这类推理，表现等同随机；英文文本限定；≤26 选项（第 27 个之后基本永不被选中） |
| 生态位置 | 2026「语义决策模型」新范式的开源一环：Jev（闭源）→ SemIf / Laya / OpenJev / Ollaya（开源）→ **Jeff（首次给出可自训的小模型权重 + 完整训练管线）** |

## 关键数据 / 对 sora 的影响

1. ✅ **硬件门槛极低，正好落在 RTX 4060 8GB 的量级**：0.8B 权重仅 **1.7 GB**（fp16）；官方实测 RTX PRO 6000 上 **22ms**、Apple M4 Max 28ms、**纯 CPU（32 线程）463ms**。⚠️ 官方未公布 4060 数字，别照抄 22ms——4060 上按「几十~一两百毫秒」预期，CPU 兜底也有半秒级
2. ✅ **准确率对得起体积**：5 个公开基准平均 **79.1%（0.8B）/ 83.1%（2B）**，对照 Jev 公布值 83.0；但在推理重的 BBH/JudgeBench/JevBench 上远低于大模型（0.8B 在 BBH 64.0 vs Jev 94.3）——**只在「选项已列清」的场景用**
3. ✅ **校准是真的**：ECE 校准误差 **0.049（0.8B）/ 0.028（2B）**，所以那个概率可以当真阈值用，不是装饰
4. 💡 **自训 30 分钟就能翻倍**：官方示例——语音导航场景用约 11k 条自有样本微调，留出集准确率 **31.7% → 95.8%**，单卡半小时（0.8B 全量训练约 2 小时）
5. 💡 **许可干净**：代码 MIT、**权重 Apache-2.0**，HF 上 `mstrasser/Jeff-Qwen3.5-0.8B` 可直接下——商用/接单项目无授权风险
6. ⚠️ **别把它当安全边界**：09-25 arXiv 2609.28613 已实测「Decision Hijacking」——恶意内容能移动 Jev 的动作概率，自适应攻击把目标选项概率翻倍（成功率 1.8%→3.5%）。**schema 约束改不了注入面**；决策模型只做路由/分类，权限判断仍留在模型之外

## 为什么重要

- **接上了库里一直在追的那条线**：Jev（09-16 HN）→ SemIf（09-20）→ Ollaya（09-26）→ Jeff（09-29），前四篇只入库没落地；这次首次出现「可自训的小模型权重」，把「本地决策层」从观察变成能动手的东西
- **成本结构上真有用**：一次前向 = 一个判断，比「让小模型写 JSON 再解析」省掉整个生成阶段，延迟低两个数量级，且提示词不出设备
- **内容选题**：AI 博主「蓝海工程」向的好素材——「不用 GPU 集群，0.8B 在本机做决策」是能讲清、能演示、能复现的实战题材
