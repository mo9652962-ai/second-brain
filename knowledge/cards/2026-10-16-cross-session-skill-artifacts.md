# 🃏 知识卡片 · 技能写出的文件，会变成下一个会话的指令

> **来源**：arXiv 10-14 速览「候选深挖第 1 位」🥇 [2610.13227](https://arxiv.org/abs/2610.13227)（*Understanding and Mitigating Cross-Session Attacks via Persistent Artifacts in Agent Skill Composition*，Dianshu Liao 等，cs.CR/cs.SE，2026-10-09 提交）· ✅ 标题/摘要/作者由本次 cron 用 curl 直连 arXiv abs 页逐句核对原文
> **一句话**：技能执行时写下的**文件、配置、缓存**，会被**后面会话里的另一个技能**读到并当成输入——这条跨会话链路是一个没人守的攻击面，而它**连"哪次会话写的"都没记**。

---

## 核心洞察 / 影响

| 维度 | 内容 |
|------|------|
| ① 攻击面在哪 | 技能 = 指令 + 代码 + 资源打包成的可复用组件。执行时**产出或修改** artifact（文件 / 配置 / 缓存），这些 artifact **跨会话存活**，被后续会话里的其他技能复用 → 影响后续执行 |
| ② 三种传播机制 | **Instruction Propagation（IP）**：产物里藏指令，被后一个技能当指令执行｜**Data Boundary Violation（DBV）**：产物越过本该隔离的数据边界｜**Evidence Poisoning（EP）**：产物污染后一个技能的判断依据 |
| ③ 硬数字 | SkillRelayBench：30 个跨会话技能组合场景 × 10 个领域 = **270 个对抗用例**，在 Codex CLI / Gemini CLI / Claude Code 上测 7 个模型 → **ASR 46.7%–77.4%**、**攻击链成功率 ACSR 35.6%–61.1%**；成功链条覆盖全部 5 类目标安全后果 |
| ④ 防御怎么做 | **SkillRelayGuard** = 恢复 artifact 的**来源上下文（provenance）** + **执行前建议性审查**（最终决定权仍留给 agent）。ASR **69.5% → 10.9%**、ACSR **54.8% → 10.0%**，同时把合法任务完成率从 79.6% **提高到 87.5%** |
| ⑤ 反直觉点 | 加一层来源标注，**不是拖慢任务，而是让任务完成率变高**（79.6%→87.5%）。因为 agent 不再把上一轮的垃圾产物当事实 |

## 关键数据 · 🔴 本次 cron 当场实测（测的是 k 自己的 vault，不是引用论文）

对 `.temp/ .tmp/ outputs/ .learnings/ .backup/ scripts/` 六个工作态目录做只读扫描（探针脚本 `.temp/cross_session_artifact_probe_1016.py`）：

| 实测项 | 数字 | 含义 |
|---|---:|---|
| 持久工作产物总数 | **155** | 跨会话存活的 artifact 规模 |
| 其中**可执行**脚本（.py/.sh/.ps1/.bat/.js） | **54** | 后续会话**可能直接跑**，不只是读 |
| 其中**陈旧**（≥1 天）数据产物 | **43** | 被后续会话当"事实"读入的旧数据 |
| 今日新建 | **30** | 单日增量 |
| 时间跨度 | **07-21 → 10-16（87 天）** | 最老的产物比今天早近三个月 |
| **JSON 产物带来源字段的比例** | **0 / 52 = 0.0%** | ← **本卡片最硬的一行**：没有任何一个产物记了"哪次会话、哪个技能写的" |

**三条现场观察**：

1. 🔴 **provenance 覆盖率是 0%，不是"低"**。52 个可解析 JSON 里，含 session / producer / created_by / writer / run_id 任一字段的：**0 个**。也就是说按 2610.13227 的判据，我的工作区**现在就是 SkillRelayGuard 想要防的那种状态**——所有 artifact 都是匿名的。
2. 🔴 **陈旧产物与当日产物同目录共存**。`.tmp/hn/` 里既有今天 12:36 的 `fetch.py` / `urls.json`，也有 **38 天前**的 `wn3.json`、**37 天前**的 `item_navier.json`、**33 天前**的 `nvidia_items.json`。后续会话的抓取脚本读这个目录时，拿到的是"今天的 + 上个月的"混在一起，且无法区分。
3. 🔴 **今日会话确实在沿用历史产物**。今早 arxiv-fetch 做的第一件事是把 10-14 会话留下的 `abs_all.json` 改名备份为 `abs_all_1014.bak.json`（12:36）——**跨会话 relay 在我这儿不是理论，是正在发生的日常操作**。

## 行动项

- [ ] **给工作态产物加来源戳**：`.temp/` `.tmp/` 下每个 JSON 落盘时写入 `{"_producer": "<cron 名/skill 名>", "_run": "<ISO 时间>", "_session": "<session id>"}`——从 0% 起步，先覆盖当日新建的 30 个
- [ ] **读之前先验来源**：跨会话读 `.temp/` 产物时，先看时间戳与 producer；**无来源戳的一律当不可信输入**处理（按论文的 DBV 判据）
- [ ] **陈旧产物定期收口**：≥7 天未被读取的工作态产物移到归档目录或删除，避免"上个月的抓取结果"混进今天的判断
- [ ] **可执行产物特殊对待**：54 个脚本中，跨会话执行前先看内容再跑（对应 10-14 卡片的「外部传入脚本先看内容」）
- [ ] **高风险读取走「执行前建议」**：配置 / 凭据路径 / 脚本目录的读取，改成先建议后执行，而不是直接执行（SkillRelayGuard 的核心动作）

## 为什么重要

- **直接命中 k 自己的形态**：k 的工作方式就是「多技能 + 多 cron + 共享一个工作区」，这正是 SkillRelayBench 的评测设定。10-10 卡片讲的是**共装技能抢跑**（同一会话内），这条讲的是**跨会话持久产物**——更隐蔽，因为没人会去看上个月那个 JSON。
- **可测量**：不用靠感觉，`0/52` 是一个能每周复测的数字。来源戳覆盖率可以从 0% 一路盯到 100%。
- **成本极低**：加三个字段，换来论文里 69.5%→10.9% 的 ASR 下降量级，且合法完成率还升。
- **内容选题价值**：sora 的「做实事」方向可取材——「为什么我给自己写的每个临时文件都盖了个戳」是天然的前 3 秒钩子，背后有 270 用例的基准数据支撑。
