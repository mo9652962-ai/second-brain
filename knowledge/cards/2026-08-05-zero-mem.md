# Zero-Mem: 零 Token 记忆操作（2607.29377）

> 2026-08-05 · HN 头版 · 与 Second Brain 记忆体系直接相关

## 一句话

**结构化记忆访问不需要生成中间表示**——保留原始轨迹为唯一记录源，记忆操作零 LLM 调用、零 token 消耗，只有最终 QA 才调用 LLM。

## 核心机制

```
原始交互轨迹（唯一记录源，不生成摘要）
    │
    ├─ 实体-上下文图（entity-context graph）→ 跨交互连接
    ├─ 时间层级（temporal hierarchy）→ 保会话局部性与会话状态
    │     T(H) = Uturn ∪ Uwindow ∪ Uepisode ∪ Ulocal（四粒度）
    │
    ├─ 查询时：两视图加权 → 从两个视图检索 → 沿结构恢复支持关系/上下文
    ├─ 确定性校准 → 先丢弃冲突证据 → 答案接地于检索到的轨迹
    └─ 仅最终 QA reader 调用 LLM
```

## 关键数字

| 指标 | 值 |
|:-----|:---|
| 记忆操作时间成本 | **-57.6%**（vs 最快基线，同 reader + 上下文预算）|
| LLM 调用 | 仅最终 QA 1 次（记忆操作 0 次）|
| LLM token 消耗 | 记忆操作 0（encoder 计算单独记账）|
| 基准 | 长记忆 + 长上下文 QA 基准 |

## 落地建议

1. **知识卡片保留原始出处**（source 字段）——不生成摘要后丢原文（当前已做 ✅）
2. **查询优先走确定性检索**（Obsidian 全文搜索/标签）——别每次让 LLM 重读全部记忆
3. **冲突检测**：新知识若与已有卡片矛盾 → 先标记不覆盖（对齐确定性校准）
4. **长期**：Hermes memory 注入的 token 成本 = 每次对话固定开销——Zero-Mem 思路是"记忆不该是生成负载"，可评估 context compression 之外的确定性检索路径
