# DeepSeek 视觉方案实证研究 · 2026-08-08（应用篇）

> 来源：小黑盒帖子「DeepSeek视觉插件实际应用」（08-02）+ 评论区暴论 + 本地实测验证。learn→research→apply。

## 核心结论

**视觉 wrapper（文本传递）方案确实打不过原生多模态**——信息瓶颈理论验证（视觉 token 直接进 LLM 是 90% 多模态架构；经文本中转 = 摘要压缩，细节不可逆丢失）。sora 的 Hermes 配置方向正确（auxiliary.vision = minimax-m3 原生多模态），但**当前所有视觉候选都不可用**——实测暴露 4 个断点。

## 事实（验证后）

### 评论区暴论（有理论依据）
- 「需要图片细节的工作（界面设计/生图判误），强文本模型+多模态描述 **不如直接用劣等多模态模型**（mimov2.5/m3）」——信息瓶颈：视觉→文本是摘要压缩，像素级信息不可逆丢失；且两模型间有信任问题（九折券实测：AI 顺杆爬）
- 帖子作者实测：DeepSeek flash 自制工具 + vision 插件自检 → 识别"辛酸"但"比没有强"

### 理论验证（搜索）
- 90%+ MLLM 是 LLM-中心架构（视觉编码器 → 视觉 token 直接进 LLM）——**原生融合**
- Q-Former/DeCo 论文：视觉连接器做"压缩 + 摘要"——压缩就有信息损失；文本中转是**二次压缩**
- 结论：wrapper 方案的本质限制无法通过换更强的文本模型解决
