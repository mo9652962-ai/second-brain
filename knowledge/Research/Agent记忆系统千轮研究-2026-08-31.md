## 一、核心结论（三方交叉）

### 记忆四层（我们都有，但可强化）

| 层 | 我们的实现 | 强化方向 |
|:---|:---|:---|
| 工作记忆 | Hermes context + session | — |
| 情景记忆 | tencentdb L0-L2 + session DB + memory/2026 | 写时标 precursor_id（因果接地）|
| 语义记忆 | Obsidian knowledge/ + consolidated | 语义去重 consolidation |
| 程序记忆 | skills/ | 结构化 triplet 晋升 |

### 关键量化数据（WorkBuddy 补充）

- **write-path filtering**：add-all 2400 条 13% 准确率 vs 主动管理 248 条 39% —— **存更少反而 3x 性能**
- **dedup consolidation**：语义去重 99.3% 压缩案例（7327→51 token）
- **forgetting**：FSFM 四类遗忘（passive/active/safety/adaptive），信噪比 +29.2%
- **跨会话一致性**：MemoryArena 显示多会话任务模型性能暴跌至 40-60%——未解决
- **consolidation 短板**："能抽象但不知道抽象何时够好到保留"——promotion 阈值无校准

## 二、落地建议（已采纳 8 项）

### 近期可做（低成本高价值）

1. **crystal 蒸馏链升级**：prose summary → 结构化 triplet + dual-buffer 试用期晋升（hot buffer → 质量检查 → LTM）
2. **write-path filtering**：知识库写入前过滤/去重/优先级打分（对标"248 条 > 2400 条"）
3. **语义去重**：memory-crystal-consolidation.py 加 dedup 步骤（99.3% 压缩案例）
4. **遗忘系统化**：四类遗忘（passive decay / active deletion / safety / adaptive）替代硬过期
5. **因果接地检索**：tencentdb 写记忆时让 LLM 标 precursor_id，检索时遍历因果链

### 中期

6. **记忆可观察性**：session DB + 知识库建 regression test suite（precision@K / stale rate / contradiction rate）
7. **SSGM 治理**：多 agent 共享记忆 RBAC（角色访问控制）

### 暂缓

8. **AgeMem RL 学习记忆**：训练成本高，范式跃迁但非当前需求
