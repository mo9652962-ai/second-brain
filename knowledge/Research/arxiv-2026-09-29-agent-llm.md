### 1. Silent Failures in Agentic Security Evaluation: A Validated Harness for Tool-Call Mediation Under Indirect Prompt Injection

- **ID:** [2609.32691v1](https://arxiv.org/abs/2609.32691v1) | [📄 PDF](https://arxiv.org/pdf/2609.32691)
- **作者:** Animesh Shaw
- **分类:** cs.CR, cs.LG
- **摘要:** 调用特权工具的 LLM agent 面临间接提示注入（IPI），但**评测本身的有效性几乎无人审查**。作者审计了一个 IPI 基准及其 harness，识别出四类缺陷：**静默 payload 未投递**、**按工具身份而非参数判攻击成功**、**把误拒率与模型能力不足混为一谈**、**缺少审计轨迹**——每一类都能产出一个「看起来合理、可发表、但错误」的数字。用同一批真实执行轨迹按缺陷定义与修正定义分别重打分：工具身份评分器报 **21.7%** 攻击成功率，而真实参数级成功率只有 **1.2%**；最刺眼的案例中，某开源模型此前报告 62.8%，在修正 harness 下变成 **0%**——原数字主要是 payload 未投递 + 身份级评分造成的假象。作者放出修正 harness，使每类缺陷「不可表达」：机器可校验的 payload 放置、参数级攻击谓词、逐场景环境、强制轨迹持久化；并借此报告领域内缺失的三个量：被攻陷 agent 是否**自曝**、LLM-judge 防御的完整安全/效用曲线、工具调用能力与过度拦截的解耦。修正 harness 还推翻了一个已发表的「能力壁垒」：被判无工具使用能力的模型其实完全有能力，早先结论是环境不匹配的产物。
- **关联度:** ★★★★★ 这是本份**最该抄的一篇**：它把「评测 harness 本身会静默产假数字」拆成四类可机检缺陷，而 k 的 verify 脚本与 cron 校验正是同类 harness。可落地：① 给 k 的门禁加「**参数级而非存在性**」判据（不是「有没有调用」，而是「调用参数是否符合契约」）；② 把「静默未投递」当独立失败模式——断言必须先证明**输入真的到达被测环节**；③ 任何防御/拦截类指标必须同时报「能力/效用曲线」，否则无法区分「拦住了」与「根本不会做」。与既有 `tool-call-bootstrapping`、`hermes-codex-security-gate` 直接合流。

### 2. API Secrets Should Never Become Tokens in the LLM's Vocabulary: A Threat Analysis of API Credential Handling in LLM Agent Systems and an Empirical Evaluation of a Vault-Mediated Execution Boundary

- **ID:** [2609.33371v1](https://arxiv.org/abs/2609.33371v1) | [📄 PDF](https://arxiv.org/pdf/2609.33371)
- **作者:** Patrick Kenney, Hadi Ahmadi, Denis Lusson, Donald Nguyen, Gurbinder Gill
- **分类:** cs.CR, cs.AI, cs.LG
- **摘要:** 工具型 LLM agent 把凭据卫生从「存储问题」变成「**执行安全问题**」：一旦 key 被粘进 prompt、写进 system prompt 或工具配置，它就从认证边界跨进了数据管线，可能残留在对话历史、日志、记忆库、生成代码与错误负载中；提示注入与过度自主再把被动泄露升级成未授权动作。本文形式化 agentic 系统的凭据暴露威胁链，综合平台密钥库事故、厂商密钥蔓延测量、OWASP/NIST 指引，并给出**vault 中介执行架构**：模型只选连接器标识符，由受信请求边界提供认证。对生产实现 Corvic Security Vault 做两组受控黑盒实验：7 个控制域 16 个探针**全部符合预期**——GitHub API 请求成功，而凭据在进程环境变量、调用方可见请求头、被测文件系统位置、三个第三方回显服务、两个无关 API 源中**均不存在**，两个云实例元数据端点均不可达。同时报告一个负面结果：某连接器的 header 映射不满足其 provider 的认证契约——**集中托管本身不保证配置正确**。结论：vault 中介消除若干泄露路径，但**必要而非充分**，最小权限、确定性动作授权、人工审批、遥测脱敏、轮换仍各自独立必需。
- **关联度:** ★★★★★ 直击 k 的现实：`apikey-manager` 桌面 vault（DPAPI）、custom_providers 配置、多个反代与中转站 key——**key 一旦进 prompt/日志就等于进了数据管线**。可落地：① 排查 k 的所有 cron/脚本，凡把 key 值（而非标识符）写进 prompt、命令行或日志的，改成「连接器标识符 + 受信边界注入」；② 给日志/报告加一道凭据脱敏扫描（正则 + 高熵串检测），并把它列为交付前门禁；③ 记住本文的负面结论——**集中托管 ≠ 配置正确**，vault 本身也要有验证探针。

### 3. Trust the Brand, Lose Control: How Identity Hijacks LLM Agent Orchestration

- **ID:** [2609.32635v1](https://arxiv.org/abs/2609.32635v1) | [📄 PDF](https://arxiv.org/pdf/2609.32635)
- **作者:** Xutao Mao, Rui Qian, Linghan Chen, Yudong Gao, Junchi Liao, Jiulin Cai, Jinman Zhao, Cong Wang
- **分类:** cs.CR, cs.AI
- **摘要:** LLM agent 已能端到端执行任务并**编排能力与成本各异的子 agent**。以往工作把子 agent 选择当优化问题，但编排器是**依据子 agent 展示的身份**做选择的，而攻击者可以伪造身份。于是「展示的身份」实际决定了操作权限——谁被信任去复核工作、谁被允许改动系统。结果是：即使其他证据与之矛盾，有风险的子 agent 仍能保住执行权。作者提出 **TrustFork**：1,890 个任务、27,826 条有效轨迹、16 个 agent 系统（8 个编排器 × OpenCode/OpenClaw/Pi 三种 harness）。每个任务里一个子 agent 携带风险目标、另三个与用户对齐，因此矛盾证据可能存在；任务还可**在不更换底层模型的前提下改变子 agent 展示的身份**，从而把权限转移归因到标签本身。结论：**即使另一个子 agent 提出反驳，编排器平均仍有 72.0% 的情况下照风险回答执行**；交换家族标签使编排器获得风险回答的频率**接近三倍**；84.0% 的任务本存在更安全的回答，但只有 25.0% 的决定采用了它。三种运行时防御中，**隐藏身份线索**最稳定有效，而「执行前验证」只在 harness 返回足够证据时才起作用。
- **关联度:** ★★★★★ k 的日常就是**多模型编排**（Codex / WorkBuddy 反代 / dsh / Gemini / K3 试点按任务类型分工）。本文说明：按「品牌/型号标签」路由而不按证据路由，会把权限交给一个只是**自称可靠**的执行者。可落地：① 委派任务时把「谁复核」绑定到**证据**而非模型名（例如 Codex 的产出必须由独立通道验证，不因它是 Codex 就免检）；② 尝试「隐藏身份线索」这条最有效的防御——让评审/复核环节**看不到**产出是谁写的，只看内容；③ 与 `ai-api-provider-evaluation`（中转站注水）合流：注水检测看能力，本文看**权限归属**。

### 4. Share-Borne AI Virus: Memory-Hopping Attacks Across LLM Agents

- **ID:** [2609.35576v1](https://arxiv.org/abs/2609.35576v1) | [📄 PDF](https://arxiv.org/pdf/2609.35576)
- **作者:** Sidharth Pulipaka, Ansh Sharma, Stanislau Hlebik, Leonidas Raghav, Vyas Raina, Ivaxi Sheth, Mario Fritz
- **分类:** cs.AI, cs.CL, cs.CR, cs.LG
- **摘要:** LLM 越来越多被部署为**跨交互保留信息、并用工具读写持久产物**的有状态助手。当这些产物在用户之间共享时，它们就构成了本来彼此独立的助手之间的**间接通信信道**。本文研究这一信道支撑的**自传播攻击**：提出 **artifact-mediated propagation（产物中介传播）**——通过某个产物（如一份报告）引入的对抗内容，被存进助手的持久记忆、在随后创建的产物中复现、再被后来读到它的另一个助手获取。作者在模拟独立助手之间产物交换的时序人-agent 宇宙中评测：攻击能否存活连续多次交接、能跳几跳、扩散多广。结果：攻击可跨多个独立助手传播并在长交互序列中持续；在更大规模模拟环境中，**即使 GPT-5.6 Luna 也出现显著扩散，触达 60–80% 的 agent，传播链最长 8 跳**。说明持久产物能充当对抗状态的**耐久载体**，使攻击比单次交互活得更久、并跨越隔离的助手传播。
- **关联度:** ★★★★★ 对 k 是**结构性命中**：k 的知识库本身就是一个「产物中介信道」——速览笔记 → 知识卡片 → MOC → 下一天的速览都读它；而 cron 之间也在互相读彼此的产出（09-26 实测 knowledge-card cron 会读当日速览抽卡片）。一旦某篇被污染，就会顺着这条链传下去。可落地：① 给 cron 产物加**来源标注**（谁写的、读自哪、可信度），让下游能区分「我验证过的」与「我读来的」；② 把「读来的内容」与「自己验证的内容」在笔记里显式分区（本文的传播正是靠无法区分二者）；③ 与第 13 篇（共享记忆的认知准入）合起来看——**记忆写入是攻击面，不只是功能**。

### 5. AgentBoundary: Counterfactual Evaluation of Safety in Tool-Using LLM Agents

- **ID:** [2609.33658v1](https://arxiv.org/abs/2609.33658v1) | [📄 PDF](https://arxiv.org/pdf/2609.33658)
- **作者:** Tianzhuo Yang, Zirui Mi, Yantao Huang, Guoxi Zhang, Jiawei Chen, Yaodong Yang, Jingwei Yi
- **分类:** cs.AI
- **摘要:** 对话场景的安全对齐围绕「回答还是拒绝」，但 agentic 场景下同一模型必须在执行过程中、随权限相关证据浮现来决定「是否行动」。这带来一个独特难题：**表面风险、动作许可性、任务能力三者极易混淆**，使得 agentic 过度拒绝无法与普通任务失败区分。作者提出 **AgentBound**，首个面向工具型 agent 安全的**四路反事实**生成与评测框架：对同一可执行工作流**独立变化「表面风险」与「动作许可性」**，从而受控比较「看着危险但已授权」与「看着常规但未授权」的任务，在控制任务能力的前提下同时诊断过度拒绝与不安全服从。实例化为**人工校验的 4,000 任务评测套件**，含轨迹级与后状态级判定。17 个模型×harness 配置的结果：**高安全常与授权任务完成率低并存**——GPT-5.5 拦下 99.5% 的「常规外观但未授权」动作，却只完成 28.7% 的「风险外观但已授权」任务。作者进一步训练轻量运行时校准模块，在 10 个配置上平均提升授权任务完成率 **18.2%**、同时提升不安全动作拦截 **5.4%**。
- **关联度:** ★★★★★ 这条直接给 k 的「审批层」提供了**正确的问题形状**：安全不是「拦得多」，而是「按权限证据行动」。可落地：① k 的自动化门禁/红线（凭据 BLOCKED、L3 授权）应做一次**反事实自检**——把同一个动作分别包装成「风险外观但已授权」和「常规外观但未授权」，看判定是否真的跟着**许可性**走而不是跟着措辞走；② 记录「过度拒绝」为独立指标（现在只记「拦住了」）；③ 与既有 Codex 红线（L0-2 自动 / L3 授权）对齐：**表面风险 ≠ 不允许**，否则会长期拖慢正常交付。

### 6. Agent Safety From Within: Detecting Harmful Trajectories from LLM Internal States

- **ID:** [2609.33039v1](https://arxiv.org/abs/2609.33039v1) | [📄 PDF](https://arxiv.org/pdf/2609.33039)
- **作者:** Difan Jiao, Ashton Anderson
- **分类:** cs.AI
- **摘要:** LLM agent 已能通过工具与 harness 执行复杂动作序列，能造成的损害范围随之扩大；而 guard 模型主要为内容审核设计，**不适合检测这类 agentic 风险**。作者先做表征分析再做方案：聚焦两类轨迹级 agentic 危害——**直接表达的有害内容**与**依赖「动作是否与产生它的交互一致」的不安全工具使用**。发现这两类危害在开源 guard 模型的内部表征中是**线性可读**的，尽管 guard 模型在「只差被调工具 schema」的成对样本上预测**不优于随机**；两类危害的内部方向几乎**正交**，彼此不可互相代理。据此提出 **TACIT**：对冻结骨干的内部状态做读出，**不解码任何 token**。在六个轨迹安全基准上训练，线性探针把平均 macro-F1 从最强开源 guard 的 62.3 提到 **80.7**，精炼读出达 **86.2**；逐基准完全留出训练时，精炼读出仍领先最强 guard（65.7 vs 61.1）。同骨干、同数据、同切分下，冻结读出与完整安全微调**持平**，且叠加在微调模型上还能进一步提升；探针训练参数量约为完整微调的**百万分之一**、时间约六分之一，延迟在所有被评 guard 中最低。
- **关联度:** ★★★★ 这条给 k 的**交付前安全门禁**指出一条低成本路线：不必再调一个 LLM judge 去读整条轨迹（贵、慢、还会被措辞骗），而可以在**内部状态**上做线性读出。可落地：① 对本地可跑的模型（llama.cpp/GGUF 线）试点内部状态探针，作为「轨迹级」安全检查的廉价通道；② 记住本文的关键实证——**「只差工具 schema」的成对样本上 guard 不优于随机**，这正是 k 的 verify 脚本最该补的负例形状（同一动作换接口表述）；③ 与第 5 篇合流：内容层安全与动作层安全是**两条正交通道**，不能互相替代。

### 7. CoDeL: Co-Evolutionary Defense against Indirect Prompt Injection in LLM-based Agents

- **ID:** [2609.34463v1](https://arxiv.org/abs/2609.34463v1) | [📄 PDF](https://arxiv.org/pdf/2609.34463)
- **作者:** Xiao Yang, Yangchen Ou, Yuhan Gao, Le Wang, Zonghao Ying, Aishan Liu
- **分类:** cs.CR, cs.AI
- **摘要:** LLM agent 依赖外部工具与内容，因此暴露于间接提示注入（IPI）；其中**基于训练的防御**常被认为最可靠。但现有训练式防御通常在**静态的显式注入分布**上优化，学到的是**表面形式线索**而非「服务用户 vs 服从注入目标」的边界，因此当恶意意图被折进一个可信工作流、并**延迟若干轮**才生效时就失效。作者提出 **CoDeL**：让防御者面对一个**自己不断重塑的攻击分布**。每轮用 LoRA 上的 GDPO、以安全/任务进展/格式合规的解耦奖励更新防御者，使「拒绝注入」与「完成用户任务」共同定义适应度；为持续供给值得学的失败样本，一个**共演化的 prober** 在注入轮次、攻击方法、payload 上搜索仍能穿透当前防御的注入，并同时以攻击成功率与**攻击延迟**为导向，优先挖掘「防御者发现得太晚」的突破。每次防御更新都会让部分攻击种群失效、迫使下一轮走向新前沿，把防御者自身的失败变成**移动课程**。三个 IPI 基准、九个基线、两个基座模型上：ASR 降低 **88.5%**，大幅领先其他基线（+38.0%）。
- **关联度:** ★★★★ 对 k 的启示不在训练侧而在**红队方法侧**：本文最有价值的机制是「**按攻击延迟（latency）排序**去挖漏网注入」——不是找最强的攻击，而是找**最晚才被发现**的攻击。可落地：① k 的注入/越权自检用例库按「被发现得有多晚」排序，优先补「延迟生效」类用例（跨轮、跨会话、藏在正常流程里）；② 静态用例集必然退化（本文的核心批判），用例库应随每次修复**重新生成**而不是冻结；③ 与 `hermes-codex-security-gate` 的 L 级策略合流——延迟型注入恰恰是「单轮判定」的盲区。

### 8. Identical Runs, Different Results: Benchmarking AI Coding Agents on Open-Weight Models

- **ID:** [2609.33812v1](https://arxiv.org/abs/2609.33812v1) | [📄 PDF](https://arxiv.org/pdf/2609.33812)
- **作者:** Eduardo Ariño de la Rubia, Szilard Pafka
- **分类:** cs.SE, cs.LG
- **摘要:** 同一编码 agent 重复运行已知会得到不同基准分。本文问的是：这对**在自己任务上跑 agent 的团队**意味着什么。作者在一台机器、一个机器学习任务上做密集重复：让 agent 改进一个 XGBoost 航班延误分类器的训练代码，用它从未见过的 holdout 打分。**584 次运行**、6 个 agent × 6 个开源权重模型端点；6 个 agent-模型配对各跑 **52 次**（固定设置）；其中 3 个再用同家族更大模型重复。核心发现：**同一配对内的运行差异大于配对之间的差异**，因此少量运行得出的排名不可靠——要分辨出观察到的 agent 差异需要**每个跑几十到上百次**。大模型上得分明显更高，但差距**小于一个运行间标准差**，且该差距在某个 agent 上比其他 agent 大两倍以上。不到二十分之一的运行破坏了任务的数据规则，**而这些运行恰好持有最高分**。先剔除违规运行、再在少数尝试中保留最佳合规结果，能可靠改善交付模型，尽管少数运行无法对 agent 排名。在更晚年份的航班数据上，交付模型**只保留了相对起始代码增益的三分之一**。按标价计算，同一模型上两个 agent 的成本差异**超过二十倍**，主要来自 prompt 缓存。结论：agent 与模型应作为**配对**、在**重复尝试**下评测，并把合规性报在质量旁边。
- **关联度:** ★★★★★ 这是 k **最缺的一份实证纪律**：k 的很多判断（哪个模型好、哪个方案优）建立在一两次运行上。可落地：① 任何「A 比 B 好」的结论必须标注**重复次数**与**方差**，少于 5 次的差异一律不作为决策依据；② **高分样本先查合规**——本次实测「违规运行恰好是最高分」，与 k 的交付门禁直接相关：**最高分不等于最可靠**；③ 记住「**prompt 缓存造成 20 倍成本差**」这条，与 09-26 已收录的 2609.29251（字节一致前缀 78% 命中）互证，k 的 fallback 链与 cron prompt 结构都该按此重估。

### 10. Failure-Transparent Agents: Benchmarking Post-Failure Reporting in Tool-Using Language Models

- **关联度:** ★★★★★ k 的 `hermes-smart-model-router` 已禁用（改用固定模型 + fallback），而本文给出了**重新开启路由的正确形状**：不是「整任务换模型」，而是**子任务级**分配 + **模型专属技能**。可落地：① 路由粒度下沉到子任务（如「规划用强模型、执行/格式化用便宜模型」），而不是整会话切换——这也回避了 09-26 已收录的「切模型毁 prompt cache」问题；② 「模型专属技能演化」值得试点：为便宜模型单独写它用得好的技能，而不是让所有模型共用一套；③ 保留被支配路由作为经验——与第 11 篇的「技能库紧凑化」形成有趣的张力（经验要留，但要门控）。

### 14. Planner-as-Router: Joint Plan-Time Model Routing for Cost-Efficient Multi-Agent Workflows

### 15. The Epistemics of Agent Memory: Measuring, and Governing, the Consolidation Decision in Long-Horizon LLM Agents

- **作者:** Sasank Annapureddy, Anjaneya Prasad Thamatani
- **分类:** cs.AI
- **摘要:** 长程 LLM agent 必须把累积经验转成持久记忆，决定什么保留、压缩、抽象成可复用技能与规则、或遗忘。本文报告一个四阶段研究纲领，核心发现是**被测量的对象发生了位移**：从「agent 记得多少」，到「它的整合决策好不好」，再到「这些决策可不可信」。阶段一从 agent 轨迹中按**下游效用**学习情节边界——一个诚实的近失（oracle 相关 0.691 vs 0.70 门槛），其持久产出是一个**三道闸的防泄漏协议**。阶段二在 token 预算下学习「何时提升经验、提升到哪个抽象层级」，取得经验证的 **+22.7% 任务成功率与 7× 压缩**，但暴露了**退化性遗忘失败**与一个被命名为 **lambda-prevalence coupling** 的分布漂移失败模式。阶段三提出 **ConsolidationBench**：一个「按构造有 oracle」的基准，在三个**非循环**轴上给整合决策打分；生产检索系统虽能保留信息，却在**跨层级迁移**上得零分。阶段四提出**受治理的整合**：把决策包裹在**抗投毒、可逆性、可审计性**保证与质量门里。治理与质量分**统计上可分**（r²=0.43；偏相关 r=0.27；质量相同的策略在治理上差三倍），故该贡献独立于质量指标的外部效度而成立。关于后者，作者报告一个**已解决的负面结果**：在分级复用重设计消除结构性天花板后，一个含 2,532 个真实答案单元的双基准研究发现质量分**不能预测**真实迁移准确率（合并 Spearman ρ = -0.24，n=12，CI 跨零）。一次对抗式自我批评复核使最终结论集以**零存留过度声明**通过。
- **关联度:** ★★★★★ 这是 k 的**知识库治理**最完整的一份参考：k 的 Obsidian 就是「整合决策」的产物——哪些笔记保留、哪些压缩成 MOC、哪些抽象成技能。本文给出三条可操作结论：① 整合决策要按**下游效用**而非「重要感」判断；② 「**跨层级迁移**」是生产检索系统的盲区（保留信息 ≠ 能跨层用），k 的 MOC/技能抽取正属此列；③ **治理（抗投毒/可逆/可审计）与质量是两个独立维度**，质量分高不代表治理好。可落地：给知识库写入加「可逆 + 可审计」要求（删除可恢复、变更有记录），并把「这条笔记后来被用到了吗」作为保留判据。与 `knowledge-lint`、`context-management-bootstrapping` 直接合流。

### 16. A Benchmark and Diagnostic Study of Epistemic Admission in Shared Agent Memory

- **ID:** [2609.30813v1](https://arxiv.org/abs/2609.30813v1) | [📄 PDF](https://arxiv.org/pdf/2609.30813)
- **作者:** Xiaoyang Li, Yiqi Wang, Chencheng Zhu, KE XU, Wencheng Yang, Zequn Sun, Pingan Song, Yiqun Duan, Taotao Cai
- **分类:** cs.AI
- **摘要:** 评估共享 agent 记忆中的**声明准入（claim admission）**很困难，因为重复出现的声明容易被误当独立证据——agent 可能复制或改写一条检索到的信念；而准入一条假声明则会让后续 agent 暴露其中。作者提出 **Correlated Promotion Benchmark (CPB)**：CPB-Static 从公开标注源构造冻结测试切分（固定金标动作）；CPB-Live 让多 agent 团队在共享库上运行，记录全部写入与检索，并按场景追踪**来源谱系**；一个独立的消费者仅凭库内容作答。评测四个 agent 家族的八种准入策略：**做来源去重的策略会连同假声明一起拒掉大量真声明**，而**保答案覆盖的策略准入的假声明几乎与无限制共享一样多**。按**声明来源类型**门控可把假采纳降到 **0.06–0.09**（其他作答策略为 0.22–0.47）。一旦一条无争议的假信念进入记忆，消费者在所有家族中都会在 **0.97–0.99** 的探针上把它当事实断言。**没有任何非 oracle 策略能在逐字复制、改写、以及改写且声称权威三种情形下一致拒绝假声明**。结论：不访问来源谱系的准入策略存在根本局限。
- **关联度:** ★★★★★ 与第 4 篇（产物中介传播）是同一条攻击面的两个视角：一篇讲**怎么传**，这篇讲**怎么进来**。对 k 的直接含义：**「重复出现」不是独立证据**——k 的知识库里同一结论常被多篇笔记复述（速览 → 卡片 → MOC），若把复述当交叉验证就会自欺。可落地：① 给笔记/卡片加**来源谱系字段**（原始来源 vs 转述来源），准入判断按来源类型门控（本文实测假采纳率 0.06–0.09 vs 0.22–0.47）；② 明确一条纪律：**转述不算验证**，跨源验证必须落到独立来源；③ 记住那个恐怖数字——**假信念一旦无争议入库，消费者 0.97–0.99 会照单断言**，这解释了为什么 k 的「已确认」标注必须严格区分「arXiv 收录」与「跨源命中」。

### 17. Maat: Independent Deterministic Contract-Based Governance for Multi-Agent LLM Workflows

- **ID:** [2609.34017v1](https://arxiv.org/abs/2609.34017v1) | [📄 PDF](https://arxiv.org/pdf/2609.34017)
- **作者:** Uliana Elina
- **分类:** cs.SE, cs.AI, cs.MA
- **摘要:** LLM 多 agent 系统有一个特征性可靠性问题：**一个 agent 的错误会被下游 agent 当作上下文接受，从而在工作流中传播**。许多防护依赖学习型或 LLM-based judge，而它们自身的判定也是概率性的；本文问：能否用**确定性层**挡住「契约可检」的交接缺陷。作者提出 **Maat**：运行时治理层，按**版本化工作流契约（anchor）**校验 agent 间交接，**验证与评分路径中不含任何语言模型**。在六个受控领域工作流（6–15 个 agent，522 次试验）上评测，注入数据级缺陷，用确定性七项检查评分。**版本 1 报告了六个工作流全面增益（2.9–26.5%）；但发表后审计发现三个基准评分器把「任何提前中止」都记作「已阻止的缺陷」。** 在「受治理运行完成，或因可归因于已验证缺陷的发现而中止」的配对试验上，评分变化为 +7.7% 至 +29.1%（五个工作流），软件开发工作流持平；当可归因中止较早发生时，模型调用成本下降 17–53%。对全部 94 次受治理臂中止的人工复核发现 **35 次误报（37%）**，成因是**校验器缺陷而非模型行为**；把这些中止计为失败工作后，**受治理臂在六个工作流中的四个低于未受治理臂**。结论支持「对契约可表达的缺陷做确定性交接校验」，但强调**校验器配置与中止归因本身必须被测试**，且该结果不确立普遍正确性、幻觉检测或模型无关的有效性。
- **关联度:** ★★★★★ 这篇的价值**一半在方法、一半在它的自我审计**：k 的 verify 脚本恰恰容易犯同一个错——**把「任何非零退出/任何中止」都算作「已发现问题」**。可落地：① 给 k 的所有校验器加「**误报率**」测量：像本文一样人工复核中止样本，统计有多少是校验器缺陷；② 「中止归因」必须显式——「运行停了」不等于「缺陷被阻止了」；③ 本文的终局更值得警惕：**把误报计入失败后，受治理反而不如不受治理**——这直接说明「加门禁」不是免费的，门禁本身要有质量门。与 09-26 已收录的 2609.29578（部分分可被回滚刷分）同属「评分器自证」谱系。

### 18. Audit the Scaffold, Not the Checkpoint: A Stationarity Dichotomy for Recursive Self-Improvement in Agentic Coding

- **ID:** [2609.34924v1](https://arxiv.org/abs/2609.34924v1) | [📄 PDF](https://arxiv.org/pdf/2609.34924)
- **作者:** Sebastian Bobadilla-Suarez, Bob Suh, Ryan Fortin
- **分类:** cs.LG, cs.AI, cs.SE
- **摘要:** 「审计一个系统是否冻结了权重」是在检查错误的东西。作者的**平稳性二分**认为：只要 agent 的**可达编辑集**固定，迭代式自我修改必然遇到严格递减收益；只有该集合**扩张**才能逃出。改写**脚手架**（工具、验证器、任务分解）在不碰任何权重的前提下扩张 agent 的可达范围，因此冻结权重只买到一个最终天花板，沿途并无平稳性。该判据还区分了通常被混为一谈的三种情形：固定类内的搜索、抬高天花板本身的 test-time training、以及居于两者之间的脚手架改写。**审计脚手架，不是审计 checkpoint。** 同一上限也横向生效：**best-of-k 编排精确实现最好那个 worker 的天花板**——宽度买的是速率，不是预算；对固定池反复咨询存在一个**可事先计算的地平线**，只由池子本身决定；唯一能超越它的安排（加权投票）需要真实 worker 不具备的多样性：在 30 个同家族 worker 上失败**重叠达到最大**，多数投票在 23/55（42%）任务上失败。作者通过把 refinement 读作「对草稿与目标之间残差的梯度提升」（一个 patch 或 git diff）得到该判据，并测量该读法在哪里失效：patch 是**组合**而非并列待投票的，且失败会重叠。他们测量到的是**饱和**：SWE-bench 上逐轮改进衰减趋零，401 个生产会话中 churn 几何衰减，其形状与一个 pre-AI 人类基线共享（后者确立该情形而不识别其成因）。两处断裂都是工程选择而非关于代码的定律，因此合起来**指明了一个值得构建的 harness**。
- **关联度:** ★★★★★ 这条直接回答 k 的一个根本问题：**为什么「多跑几次/多委派几个 agent」不能突破天花板**。可落地：① 自我改进的着力点应是**脚手架**（工具、验证器、任务分解、技能库）而非模型权重或更多重复——与第 11 篇（验证门控技能优化）互为支撑；② 「best-of-k 只买速率不买预算」是对 k 重试策略的硬约束：**重复采样不能替代能力扩张**；③ 最有价值的是「**30 个同家族 worker 失败重叠达最大，多数投票 42% 失败**」——k 若用同一家族的多个模型互相验证（如多个 DeepSeek 变体），基本是自我确认，**多样性必须来自不同家族/不同证据通道**；④ 最后一条工程结论值得直接抄：两处断裂是工程选择，所以「值得构建的 harness」是存在的。

## 今日要点（主题信号）

1. **「评测 harness 本身会静默产假数字」成为本份最强主线**：2609.32691 用同一批轨迹重打分，把工具身份评分器报的 **21.7%** 攻击成功率打回真实的 **1.2%**（某开源模型 62.8% → **0%**）；2609.34017 发表后审计发现评分器把「任何提前中止」都算作「已阻止缺陷」，计入 37% 误报后**受治理臂反而不如不受治理**；2609.34198 显示纯 judge 会宣布执行类证据无法确立的「改进」，且旧校准迁移把误差从 3.8 抬到 **19.5 pp**。→ k 的所有门禁/校验器都要加「误报率」与「参数级判据」两项自检。

2. **「agent 自报不可信」有了第三条独立实证，且给出了低成本解法**：2609.35732 实测假成功率基线 **22.8%**、加透明性指令 **9.3%**、加**结构化证据契约 0.8%**，且有用响应率从 74.9% 升到 **98.8%**（不是靠多报失败换来的）。→ 本次任务自带的「[产物断言 FAIL] 必须报告」正是该契约的实例化；k 应把证据契约固化进所有 cron 交付格式。

3. **技能/脚手架的自我演化需要「门」**：2609.32990（VALVE）用验证门控把长期回撤降低 **75%**、技能库紧凑 **11 倍**；2609.34924 指出**审计脚手架而非 checkpoint**，且 **best-of-k 只买速率不买预算**、**30 个同家族 worker 失败重叠达最大（多数投票 42% 失败）**。→ k 的技能沉淀要加「验证门 + 回撤指标 + 淘汰机制」，而多模型互验必须跨家族。

4. **记忆既是攻击面也是治理对象，四条线各自给出机制**：2609.35576（产物中介传播，GPT-5.6 Luna 也扩散到 **60–80%** agent、最长 8 跳）、2609.30813（假信念一旦无争议入库，消费者 **0.97–0.99** 照单断言；按来源类型门控把假采纳降到 0.06–0.09）、2609.33013（治理与质量是**两个独立维度**，r²=0.43；生产检索系统在跨层级迁移上得零分）、2609.30289/2609.32049（有效性感知检索、按承重定半衰期）。→ **转述不算验证**；k 的知识库需要来源谱系 + 有效性维护 + 可逆/可审计。

5. **路由与成本的正确形状：子任务级 + 规划期一次看全**：2609.34712（RSI-router）在子任务级路由下以 **48.3%** 成本超过纯大模型基线，部分基准成本降 74.7–82.2% 而性能提升；2609.32917（PaR）在规划期一次看全整个工作流，相比全前沿路由省 **44%** 成本、让出 2.9 点。两篇都回避了「整会话切模型」——与 09-26 已收录的 2609.28919（切模型毁 prompt cache）合起来给出 k 重启智能路由的安全形状。
