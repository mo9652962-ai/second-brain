# 《用 AI 搞科研必须避开的天坑：文献检索里暗藏的雷》— 吃太饱骑士

> 来源：小黑盒文章 · 2026-07-31 · 已吸收

## 核心内容

### 坑 1：Token "爆炸"，钱包"飞走"

- 文献检索 = 大量网络搜索 + 数据库检索 → AI 接收海量信息 → token 消耗巨大
- **认知悖论**：文献检索"任务难度低" ≠ "成本低"（成本与难度不挂钩，与信息量挂钩）
- 解决思路：付费模式选择

| 付费模式 | 代表 | 特点 | 适合 |
|---------|------|------|------|
| 订阅制"无限"使用 | ChatGPT/豆包会员、千问/DeepSeek 免费 | 不计单次 token 成本 | 高频文献检索 |
| 按次付费 | Trae、次数包 | 成本直观 | 低频用户 |
| 按 token 计费 | API、第三方 | 灵活但受文本长度影响 | 开发者/批量场景 |

### 坑 2：上下文"污染"，AI 回复"变异"

- 检索获得的信息未必都有帮助，无关信息会干扰 AI 判断
- 检索通常是**大任务的起步动作**（接下来：精读目标文献 / 总结归纳 / 解决实际问题）
- **解法：信息隔离（干湿分离）**
  - 文献检索 → AI 回复 → 让 AI 总结必要信息 → **复制总结到新对话**继续下一步
  - 好处：① 节省上下文 token ② 上下文纯净，回复质量高

## 我们的落地情况

| 坑 | 我们已有的护栏 | 本次新增 |
|----|--------------|---------|
| ① Token 爆炸 | ai-cost-guardrails 5 层护栏（预算/熔断/重试/可视化/路由）+ Coding Plan 订阅制 + 错峰 | ✅ 已覆盖 |
| ② 上下文污染 | 规则 #15 跨天会话管理（粗粒度） | ✅ **规则 #21「检索-提炼-再行动」**（任务内细粒度干湿分离） |

## 吸收要点

1. **订阅制优先**验证了我们 Coding Plan 路线的正确性（高频使用场景订阅最划算）
2. 新增规则 #21：检索→提炼（3-5 条结构化要点）→再行动，原文按需定向 web_extract
3. light-literature-search skill 天然践行此模式（产出 findings.json 而非原文列表）
4. 文章提到的"幻觉问题今年大模型很少出现" — 与我们 OSReward/评估器可靠性规则 #17 互为印证（评估器偏见比幻觉更值得警惕）

## 结论

- 文章面向"小白"，观点基础但**两个坑的底层逻辑与我们的成本/上下文治理完全同构**
- 已落地：规则 #21（v1.16.0），其余护栏已存在
