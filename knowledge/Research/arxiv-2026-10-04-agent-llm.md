### 1. Pretext: Defeating Malicious Skill Detection Frameworks for AI Agents

- **ID:** [2609.39607v1](https://arxiv.org/abs/2609.39607v1) | [📄 PDF](https://arxiv.org/pdf/2609.39607)
- **作者:** Tobias Kaisar, Aritra Dhar
- **分类:** cs.CR, cs.AI
- **摘要:** 技能通过把指令与信息注入上下文来扩展 agent 能力，被 OpenClaw、Claude Code 等广泛使用；既有工作已证明第三方市场托管恶意技能，可让攻击者直接影响受害者的 agent。新兴防御在安装前扫描技能——确定性静态检查 + LLM 语义裁判（如 NVIDIA 的 SkillSpector）。本文证明这类防御在**知道检测器的攻击者**面前会失效：白盒 LLM 攻击器 **Pretext** 迭代构造既逃避检测、又投递 payload、同时完成良性任务的技能——把 payload 从代码搬进自然语言（让静态分析失去着力点），把它包装成技能的**正当用途**，再把指令拆到多个文件（让 LLM 阶段低于其拦截阈值）。在三个开源模型上，对冻结检测器最高 **97%**、对协同自适应检测器 **77%** 的攻击成功率，暴露当前技能扫描器的重大缺口。
- **关联度:** ★★★★★ 这是「装前扫描」这类防御的**直接反证**。k 的 `skill_manage` 若只依赖单层静态+LLM 扫描，等于把安全押在一个已知可被绕过的检测器上。可落地：① 把扫描结果当**信号**而非**准入判决**，与 10-02 速览的「跨 Skill 依赖链检查」叠加；② 对「把指令拆到多文件」的形态做专门检测（现有扫描器逐文件看，天然漏跨文件拼装）；③ 装后仍保持运行时授权（见第 3、4 篇）。

### 2. SKILLLITE: Evidence-Guided Malicious Skill Auditing with Compact LLMs

- **ID:** [2609.36879v1](https://arxiv.org/abs/2609.36879v1) | [📄 PDF](https://arxiv.org/pdf/2609.36879)
- **作者:** Haoran Ou, Gelei Deng, Xuanye Zhang, Wenbo Guo, Tianwei Zhang, Kwok-Yan Lam
- **分类:** cs.CR, cs.AI
- **摘要:** Agent Skill 把任务相关指令与可执行组件、辅助资源打包，第三方技能的普及引入新的供应链攻击面：恶意技能可嵌入有害行为，滥用 agent 权限并破坏执行环境或可访问资源。既有 LLM 恶意技能审计方法表现不错，但**依赖强商业 LLM**；如何在安全敏感、资源受限的环境中用**紧凑、可本地部署**的模型做有效审计，此前基本未被探索。作者发现紧凑 LLM 难以识别隐藏在复杂技能包中的恶意行为——原因既有行为的隐式性，也有紧凑模型推理能力的限制。据此提出 **SKILLLITE**：证据引导的 agentic 框架，先抽取安全相关行为并**推断技能的预期功能**，再让紧凑 LLM 基于「观察到的行为 + 功能上下文」判断恶意性。跨多个紧凑骨干优于代表性审计基线，泛化到行为已被确认的野外恶意技能，同时保持低推理延迟。
- **关联度:** ★★★★☆ 与第 1 篇互补：Pretext 打的是「扫描器可被绕」，SKILLLITE 补的是「审计不必依赖云端大模型」。对 k 的实际价值在**本地化**——把技能审计做成本地可跑、低延迟的例行检查，而不是每次都调外部模型。可落地：给 `skill-vetter` 类流程加一层「先抽行为、再推预期功能、最后判恶意性」的证据链，输出可复核的判定依据而非单一分数。

### 3. ActionGuard: Tool Call Authorization under Poisoned Skills

- **ID:** [2609.39450v1](https://arxiv.org/abs/2609.39450v1) | [📄 PDF](https://arxiv.org/pdf/2609.39450)
- **作者:** Jihun Han, Yejin Jang, Byung Il Kwak, Mee Lan Han
- **分类:** cs.CR, cs.AI
- **摘要:** 在**本来良性**的技能里插入恶意指令，就能让良性用户请求触发危险 Tool Call（数据外泄、删文件、未授权代码执行）。**ActionGuard** 在 Tool Call **即将执行前**检查它：把目标 agent 的动作生成上下文与守护者的授权上下文**分离**——目标 agent 仍可用原始技能做规划，但 Reviewer **不接收**可能被投毒的原始技能文本，而是依据「平衡技能画像 + 当前与近期 Tool Call + 本地脚本内容」判断每个动作是否被**可信用户请求**所证成。在 OpenClaw 的 before-tool-call 阶段拦截，按 fail-closed 策略执行 ALLOW/DENY。评测用 139 个上下文注入 + 180 个明显注入，对比 Dynamic Guardian 与 SkillGuard，三种开源 + 两种商用 Reviewer 模型，每条件重复三次：ASR 相对既有守护降 **35.54–46.11 个百分点**、相对无守护降 **70.44 个百分点**，同时保持高良性任务完成率。
- **关联度:** ★★★★★ 「授权上下文与生成上下文分离」是可直接抄进 k 的工程结构——**别让做决定的那个 agent 自己审自己**。这与既有 `hermes-codex-security-gate` 的「派活前门禁」同源，但补上了执行边界（before-tool-call）这一环。可落地：高风险工具（写文件、发网络请求、git push）前加一个**不看原始技能文本**的独立 Reviewer，只依据用户原始请求 + 近期调用 + 本地脚本判定。

### 4. ToolFence: Fine-Grained Authorization for Secure Tool-Using LLM Agents

- **ID:** [2609.37196v1](https://arxiv.org/abs/2609.37196v1) | [📄 PDF](https://arxiv.org/pdf/2609.37196)
- **作者:** Yanjie Li, Xiangyu He, Xuelong Dai, Bin Xiao
- **分类:** cs.CR, cs.AI
- **摘要:** 工具使用 agent 易受间接提示注入，根源是**可信指令与不可信观察共享同一上下文**，恶意内容因此能反过来操纵输入过滤式防御。多路共识防御仍有高 ASR，因为它们检查内容或聚合输出、而非**授权效果**，尤其对「**工具内攻击**」无效（工具不变、参数被操纵）。CaMeL 式数据流控制保证更强，但延迟高到限制部署。**ToolFence** 在执行前编译**带类型的授权蓝图**，用确定性监视器执行；蓝图不完整时**请求授予新能力**，而不是逐个裁决具体调用。两个关键优势：① 细粒度、溯源感知的授权能区分**用户授权值**与**不可信观察**，有效治工具内攻击；② 确定性快路径 + 能力级运行时授予大幅降低昂贵 judge 调用频率。AgentDojo + Qwen3-max 上把 ASR 降到接近零，干净效用仅降 **3.80 个百分点**，运行时开销可控。
- **关联度:** ★★★★★ 与第 3 篇同属「执行边界授权」，但机制不同：ActionGuard 换**上下文**，ToolFence 换**粒度**（从「审内容」改成「审效果/能力」）。k 的教训很直接——**参数级**攻击（同一工具、不同参数）是纯内容过滤的盲区，必须授权到「这个参数值是不是用户给的」。

### 5. PACE: Provenance-Aware Capability Enforcement for Tool-Using LLM Agents

- **ID:** [2610.01349v1](https://arxiv.org/abs/2610.01349v1) | [📄 PDF](https://arxiv.org/pdf/2610.01349)
- **作者:** Fengpeng Li, Qizhou Wang, Yuke Hu, Kemou Li, Jun Liu, Haiwei Wu, Jiantao Zhou, Di Wang
- **分类:** cs.CR, cs.AI
- **摘要:** 工具使用 LLM agent 把生成文本变成**真实副作用**，因此被投毒的工具元数据、检索页、记忆与可复用技能都能引导下一次调用。关键在于：**准入前审查解决不了这个问题**——一个安全变体与一个泄漏变体可以产生**相同的准入证据**，于是健全的门禁对二者都不能放宽。本文把这个条件形式化，指出这留下了部署端唯一还能行动的边界。**PACE** 在每次工具调用**即将执行前**做中介：路径限定对表征出的影响路径做**可执行切割**；能力与效果验证把 schema 定义的效果对照**由已认证请求编译出的权限**。并把「经认证的执行契约」与「被评估配置」区分开（后者可在提议拦截后恢复一次已授权调用，或施加声明式修复）。8 个可执行 agent 安全基准 × 3 个目标模型族：被评估配置在 79 个合格攻击列中 **62 列取得最低 ASR**、14 列持平；完整基准原生效用最多损失 **3 分**。1167 对配对消融显示安全增益主要来自**效果验证**，而拒绝控制来自边界自适应；缩小规模的自适应搜索对越权目标 **0/30** 成功。
- **关联度:** ★★★★★ 这篇给出了三篇「执行边界授权」中最强的理论陈述：**准入证据不可区分** ⇒ 唯一可用边界是执行时。可落地：k 的权限模型从「安装时白名单」升级为「**调用时对效果做能力核验**」，并把「已验证契约」与「当前配置」显式分开记录——否则修复一次拦截后无法说明凭什么放行。

### 6. MMSkillRisk: Can Agents Stay Safe When Multimodal Skills Become Traps?

- **ID:** [2609.35912v1](https://arxiv.org/abs/2609.35912v1) | [📄 PDF](https://arxiv.org/pdf/2609.35912)
- **作者:** Lingqi Jiang, Jialuo Chen, Jianan Ma, Xinhao Deng, Xiaohu Du, Sibo Yi, Yuqi Qing, Zhenguang Liu, Qinming He, Shiwen Cui, Changhua Men
- **分类:** cs.CR, cs.AI
- **摘要:** 多模态技能在程序性指令、工具与示例之外**额外包含视觉参考**，agent 执行时会检索并查看这些图。因为图会引导动作，攻击者可以把恶意指令伪装成**本来合法技能内的普通视觉指引**。既有技能安全研究主要看文本载体攻击或扫描器检测，图像承载攻击的**运行时效果**评估不足。本文提出 **MMSkillRisk**——据作者所知首个面向多模态技能图像承载攻击端到端安全评测的公开基准。攻击面实例化用 **NCVA（Native-Context Visual Attack）**：把恶意指令伪装成教学图的**原生组件**（标注、界面标签），配套辅助指引把 agent 引向相关视觉区域而不明说恶意操作。基于 28 个精选干净技能，含 36 个攻击包、108 个可执行用例、覆盖五类攻击目标，攻击成功与良性任务完成**分开检查**。9 个模型-harness 配置在隔离沙箱中**全部**被诱导出未授权操作：池化 ASR 达 **43.1%**，比匹配的文本载体基线高 **16.4 个百分点**（9 个配置全部更高）；攻击成功与良性任务完成在 **36.5%** 的用例中同时发生，GPT-5.6-sol + Codex 达 **72.2%** → **任务成功本身不构成技能使用安全的证据**。
- **关联度:** ★★★★☆ 给「任务成功 = 安全」这一默认假设又补了一刀，且补的是**多模态**盲区。k 处理图片类素材（截图、产品图、PPT 截图）时，图里的文字同样是注入面。可落地：① 从外部拿到的图片素材进入 agent 上下文前，视为**不可信文本**处理；② 验收报告里「任务完成」与「未发生越权操作」分两栏，别合成一项。

### 7. Approval Laundering: Systematizing Approval–Execution Binding Failures in AI Coding-Agent Harnesses

- **ID:** [2609.38983v1](https://arxiv.org/abs/2609.38983v1) | [📄 PDF](https://arxiv.org/pdf/2609.38983)
- **作者:** Yang Wang
- **分类:** cs.CR, cs.AI, cs.SE
- **摘要:** 现代 AI 编码 agent harness（Claude Code、Codex CLI、Cursor）把安全边界建立在一个**几乎无人审查的假设**上：人类批准的**动作 A** 就是 harness 执行的**动作 A'**，其中 A 由「范围授予 / 会话级批准」的既定策略固定。本文证明该假设**系统性且可复现地**失败，并给出 **Approval Laundering** 分类法——六种失败模式，描述 harness 的执行机制如何在批准后**静默把 A 替换成 A'**：Scope（范围）、Argument（参数）、Temporal（时序）、Tool（工具）、Delegation（委派）、Semantic（语义）洗白。与既有「用静态语料评估风险分类器」或「推断隐式意图」的工作不同，本文直接审计批准与执行之间的绑定关系。
- **关联度:** ★★★★★ 这条直接命中 k 的**审批语义**：sora 说「可以推」，k 推的是不是同一个东西？六类洗白里最危险的是 **Argument 与 Semantic**——批准「更新笔记」却执行了「更新笔记 + 顺手改配置」。可落地：把审批记录写成「批准对象 + 参数 + 范围 + 有效期」四元组，执行前**回读比对**，不一致就停下重新确认，而不是「差不多就办了」。

### 8. Aletheia: Permission-Minimality Testing for Coding-Agent Rules

- **ID:** [2609.39678v1](https://arxiv.org/abs/2609.39678v1) | [📄 PDF](https://arxiv.org/pdf/2609.39678)
- **作者:** Jieke Shi, Yuchen Chen, Junda He, Yue Liu, David Lo
- **分类:** cs.CR, cs.SE
- **摘要:** 仓库指令文件指导编码 agent，同时也把它们暴露于提示注入：恶意规则可以一边让 agent 产出**正确的补丁**、一边索取凭据访问或数据外传。本文提出 **Aletheia**，做**权限最小性测试**：把规则请求的权限翻译成带类型语言，并合成可执行沙箱配置；先在完整权限下、再在**每次只去掉一项权限**的独立限制下运行**未改动的**规则与任务。若在严格削减的权限下仍能通过独立功能测试，就得到该权限**可省**的「可弃性见证」，Aletheia 结合任务上下文把它解释为可疑请求的诊断依据（并形式化了这一判据）。在共享重构任务上，Aletheia 对全部 **314** 个 AIShellJack 攻击输入都执行并检出，5 个良性模板零告警；在 80 条人工核验的良性 GHAgentFiles 规则中只产生 3 个误报（**3.75%**）。
- **关联度:** ★★★★☆ 提供了「**逐项撤权看还能不能过**」这一干净的可执行判据——比静态读规则文本可靠得多。可落地：给 k 自己的高风险脚本做一次权限最小性自查（每去掉一项权限跑一次功能测试），把「其实不需要的权限」从默认授权里删掉。这也天然生成一份**可审计证据**，比「我觉得它安全」有说服力。

### 9. MCRI: A Four-Dimensional Framework for Analyzing and Evaluating Agent Skills

- **ID:** [2610.01506v1](https://arxiv.org/abs/2610.01506v1) | [📄 PDF](https://arxiv.org/pdf/2610.01506)
- **作者:** Zongrui Yang, Li Xintong, Runchen Xu, Zhongsheng Wang, Zhedong Lin, Haoyuan Li, Jiamou Liu
- **分类:** cs.AI, cs.SE
- **摘要:** 随着 agent 从单工具系统演化为模块化复合架构，技能正成为能力开发与分发的重要机制，但学界缺乏系统分析/评估技能的**结构化框架**。作者基于**信息增益**与**行为约束**提出四维 **MCRI 框架**，并操作化为基于 LLM 的 **MCRI-Eval** 评估方法。用 OpenClaw Skill Hub 的 **63,812 个公开技能**、跨 BigCodeBench / BFCL-Fundamental / Mind2Web 的 **58,275 次**技能条件化模型执行来评估。MCRI-Eval 分数与社区热度信号**正相关**，在被评估方法中下游排序一致性最高；top-1 技能选择在三个基准上分别把下游性能排名推进 **17.7 / 22.8 / 19.6 个百分点**。结论是它提供了执行前筛选信号，可在昂贵执行式评估之前优先化有希望的技能。
- **关联度:** ★★★★☆ 直接把「技能库爆炸后怎么挑」变成可打分问题——与第 10 篇同源但更偏**评估框架**。对 k 的价值：技能库越装越多时，需要一个**执行前**的优先级信号，而不是逐个试跑。可落地：给 k 的技能目录加一列 MCRI 式四维评分（信息增益 / 行为约束），作为「这条技能值不值得进默认加载集」的初筛。

### 10. SkillSeek: Revisiting Agent Skill Retrieval at Marketplace Scale

- **ID:** [2609.38822v1](https://arxiv.org/abs/2609.38822v1) | [📄 PDF](https://arxiv.org/pdf/2609.38822)
- **作者:** Guanqun Yang, Wenlong Zhang, Tian Shi, Ping Wang
- **分类:** cs.IR, cs.AI, cs.MA

### 13. SAGE: A Statistical Acceptance Gate for Self-Evolving Agents

- **ID:** [2609.36043v1](https://arxiv.org/abs/2609.36043v1) | [📄 PDF](https://arxiv.org/pdf/2609.36043)
- **作者:** Yihao Wang, Linhan Xia, Rui Liu, Zhaofeng Zhang, Hongyu Wu, Yang Yang, Jinglu He, Yu Guo, Kai Lei
- **分类:** cs.AI
- **摘要:** 基于 LLM 的 agent 越来越多通过编辑一个**持久技能文档**（编码其工作流、工具使用规则、决策逻辑）来自我演化，这个循环有两步：优化器提议候选编辑，门禁接受或拒绝。既有工作集中于优化器，而门禁仍沿用朴素规则——**保留任何提高聚合验证分的编辑**。本文证明该规则有两种失败：① 允许**永久回归**，因为一次编辑可以抬高均值却破坏技能本来已解决的项；② 易受 **Optimizer's Curse** 影响，因为有限且带噪的验证集上的最优观测分是**向上偏**的。据此提出 **SAGE**：逐项配对比较（在同一批验证项上评当前技能与编辑后技能，暴露被聚合分掩盖的回归并**非对称惩罚**）+ 单边配对检验（只有当收益相对损失在统计上可靠时才提交编辑，否则**弃权**）。SAGE 是标准门禁的保守精化，在边界设置下精确退化为基线。五个基准 × 四个骨干、等预算协议下：20 个设置中 **19 个降低回归率**、余下一个持平（DeepSeek-V4 上 LiveMath 从 36.5% 降到 0%、OfficeQA 从 42.8% 降到 0%），并在**全部 20 个设置**取得最高最终分（LiveMath 34.15 → 48.78）。
- **关联度:** ★★★★★ 这是本批对 k 最**可直接落地**的一篇：`skill_manage` 的技能自演化正缺一个合格门禁。可落地：① 技能改动的验收从「聚合分变好」改成**逐项配对**（同一批用例上跑旧版与新版），专门抓「修了新问题、弄坏老能力」；② 加**弃权**选项——统计上不显著就不改，宁可不动；③ 记住「回归率」是比「平均分」更该盯的指标。

### 14. Self-Evolving Harness on Multiple Tasks with the Agent as Its Own Optimizer

- **ID:** [2609.38372v1](https://arxiv.org/abs/2609.38372v1) | [📄 PDF](https://arxiv.org/pdf/2609.38372)
- **作者:** Qiankai Xu
- **分类:** cs.AI, cs.LG
- **摘要:** harness 是围绕语言模型 agent 的代码——组织提示、调用工具、管理上下文、控制执行。随着模型变强，近期工作开始让 agent **改进自己的 harness**（self-evolving harness）。但多数既有方法里，是一个独立 proposer 在**人类设计的 harness 上**修改 solver 的 harness，且**每个基准单独演化一套** harness；而现实任务来自多个领域，演化与评估都应覆盖多样化任务。本文提出一个接近**递归自我改进**的框架：**同一个冻结模型、同一版本的 harness**，先作为 solver 解题，再作为 proposer 读**完整运行记录**并直接编辑运行它的那份 harness。每个演化批次从五个不同领域的基准抽任务；训练与留出严格分离，另在五个演化中从未使用的分布外基准上评估。把演化过程类比深度学习训练的两阶段（多任务预训练 + 持续训练）：从 **49 行**种子 harness 出发，第一阶段结束时在分布内基准平均 **+4.48 分**、分布外 **+12.64 分**（前者超过 Codex，后者追平）；第二阶段在 Claw-Eval 上继续演化，从 66.17 提到 **68.06**，超过 Codex。文末还分析了演化中涌现的机制：输出截断、历史压缩、独立复核。
- **关联度:** ★★★★★ 「同一模型既当 solver 又当 proposer」去掉了对独立优化器的依赖，工程上更省；涌现出的三项机制（截断/压缩/独立复核）恰好是 k 长会话里最需要的东西。可落地：把 k 的 cron/长任务骨架当 harness 来迭代——用**完整运行记录**（不只最终输出）当输入，按「多任务预训练 → 单任务持续训练」两阶段改，并盯住 OOD 分数是否真涨。

### 15. EngramBench: A Capability-Grounded Benchmark for Skill-Evolution Harnesses

- **ID:** [2609.39284v1](https://arxiv.org/abs/2609.39284v1) | [📄 PDF](https://arxiv.org/pdf/2609.39284)
- **作者:** Zhixuan Tan, Pengjie Gu, Zhao Li, Yihan Hu, Xu He, Dong Li, Jianye Hao
- **分类:** cs.SE, cs.AI
- **摘要:** 尽管 LLM 在孤立代码生成上成绩亮眼，真实的软件工程需要持续推理、复杂状态管理与跨领域抽象。但当前对自主 agent **技能演化**的评测存在严重的**可识别性问题**：把真正的能力抽象与**死记硬背式解法泄漏**（从历史训练数据抄高度相似的代码）在结构上混为一谈。为破解此问题，作者提出 **EngramBench**，由严格公理「**能力重叠但解法不重叠**」约束：含 30 个多样化学习任务与 13 个未见迁移任务，用 LLM 模拟用户在交互式、**多小时的开发周期**中挑战 agent。48 条多小时执行轨迹（并有人类专家验证）给出一个关于程序性记忆的深刻结论：**静态技能库并不能神奇绕过「最后一公里」的精确代码实现**——那仍受基座模型固有推理能力的瓶颈限制；但技能库是**不可或缺的执行罗盘**：把 agent 从灾难性、烧 token 的试错中引开，真正的能力抽象能砍掉冗余上下文膨胀并把整体编码时间**减少 55% 以上**。EngramBench 把评测范式从琐碎的模式匹配转向对深层跨领域能力迁移的可验证测量。
- **关联度:** ★★★★★ 「技能库不替你做最后一公里，但能当罗盘」——这是对 k 技能体系**最诚实的定位**。可落地：① 别指望装了技能就自动变强，技能的价值在**减少试错与上下文膨胀**；② 评估技能效果时用「能力重叠但解法不重叠」的任务，否则把「背过答案」当成「学会了」。

### 16. CounterSteer: Suppressing Indirect Prompt Injection with Activation Steering

- **ID:** [2609.36570v1](https://arxiv.org/abs/2609.36570v1) | [📄 PDF](https://arxiv.org/pdf/2609.36570)
- **作者:** Mark Russinovich
- **分类:** cs.CR, cs.AI
- **摘要:** 间接提示注入让 LLM agent 把不可信检索文本**当成指令**。本文提出 **CounterSteer**——一个在**模型内部**抑制该行为的推理时防御：对每个模型，用五步配方从「仅在于是否遵循嵌入指令上不同的配对情节」拟合一个残差流方向，并且**只有当它通过预设的因果与能力门**才保留。部署时，在每个工具结果 token 的 prefill 阶段**减去**该方向。该编辑**始终开启**（因此没有可被规避的检测决策），不需要微调、辅助模型或额外 token，只需白盒服务与工具结果 span 边界。五个开源权重模型（8B–106B，五个厂商谱系）：留出攻击成功率从无防御的 0.21–1.00 降到 0.00–0.17，AgentDojo 沦陷率从 0.10–0.49 降到 0.006–0.079，良性效用保持 93–100%（排版归一化）；对需要推理被 steer 内容的场景有更大任务相关代价。基准级自适应攻击者（无防御 0.67–0.73）在两个深评模型上被压到约**四分之一**。在已测的强模型防御中，那些取得更低沦陷率的要么损失 22–89% 良性效用、要么微调了被服务的权重。白盒梯度攻击最多攻陷 52 个情节中的 2 个，2052 次重放的人类红队攻击无一成功。但**参数操纵**（合法调用中的攻击者选定参数）只被部分抵抗（18 个中 13 个）→ 作者主张需要参数溯源控制。
- **关联度:** ★★★★★ 三个可直接迁移的判断：① **「始终开启」比「先检测再拦」更难被规避**——因为攻击者没有可优化的检测面；② 作者自己承认的边界（参数操纵只部分抵抗）恰好与第 4 篇 ToolFence 的动机吻合，两篇应合读；③ 「防御代价要连良性效用一起报」应成为 k 验收任何安全改动的标准格式。

### 17. Backdoor in the Loop: Compromising Agentic Search via Malicious Retrievers

- **ID:** [2609.37468v1](https://arxiv.org/abs/2609.37468v1) | [📄 PDF](https://arxiv.org/pdf/2609.37468)
- **作者:** Beining Xu, Peichun Hua, Yunming Xiao
- **分类:** cs.CR, cs.AI, cs.IR, cs.LG
- **摘要:** agentic RAG 在推理与反复检索之间交替，使**检索器**同时影响 agent 看到的证据与它后续的搜索决策。本文研究利用这一反馈回路的**检索器后门**，并**反向利用弱后门净化**来掩盖自身：攻击者只提供被污染的检索器 checkpoint，**不改**搜索 agent、也不改部署语料；在没有语料写权限的情况下，攻击者仍可抑制有用证据、持续检索某个选定的既有文档、或把 agent 引向长时间搜索（抬高检索、上下文与延迟成本）。为躲过检测，作者提出一个受控的**注入-移除循环**：刻意注入一个更弱的后门再把它遗忘（unlearn），该过程削弱检测器可见的特征、让后门检测器产生「**已被净化**」的错觉，同时保留恶意检索行为。结论是 RAG 系统存在系统性脆弱点——**弱防御会变成攻击者藏匿后门的工具**，即使底层语料完全可信。

### 18. SINGED: Correct Outputs Do Not Certify Safe Execution in LLM Agents

- **ID:** [2609.35889v1](https://arxiv.org/abs/2609.35889v1) | [📄 PDF](https://arxiv.org/pdf/2609.35889)
- **作者:** Xiaoyu Xu, Zi Liang, Minxin Du, Qipeng Xie, Qingqing Ye, Yuyuan Li, Haibo Hu
- **分类:** cs.CR, cs.AI
- **摘要:** 工具使用语言模型 agent 会**选择并执行第三方工件**。不同实现可以**返回所要求的输出**，却产生任务式、攻击式或选择式评测都漏掉的**隐藏执行效果**。本文研究 **functional counterfeits**：在要求的输出上与良性替代品一致、却额外产生任务契约所禁止效果的实现。作者提出 **SINGED** 基准（5 个主任务族 + 2 个留出族），变化显示排名、证据深度、决策策略、模型版本与 agent 配置，同时用任务与过程 oracle 验证工件**与执行路径**。在 7,549 次审计试验中：随机排名研究在 rank-one 试验里 **45%（27/60）**出现 counterfeit 执行，而在更后排名中一次也没有；跨候选比较能消除浅层失败并把分层失败从 **15.7% 降到 4.2%**，但留下依赖失败，且对未见效果与公开包结构的收益不确定；更有 7 个版本在「存在良性替代品」时零 counterfeit 执行，一旦**移除替代品**，在 **55/175** 个单源单元中执行了 counterfeit。SINGED 因此暴露一个**排名/证据/选择敏感的结果-执行鸿沟**：评测必须把正确输出**连到执行路径**上。
- **关联度:** ★★★★★ 与 10-02 速览的「终态通过 ≠ 安全」同调，但换了切口：**输出对不等于执行对**。k 的验收若只看「文件生成成功」，就完全看不见「顺手多做了别的」。可落地：① 验收记录加**执行路径**（改了哪些文件、发了哪些请求、调用了哪些工具）；② 有良性替代方案时优先选替代方案，别只看输出一致性。

### 19. Cheap to Hypothesize, Costly to Verify: The Defense Surface of Agentic Vulnerability Discovery

- **ID:** [2609.35909v2](https://arxiv.org/abs/2609.35909v2) | [📄 PDF](https://arxiv.org/pdf/2609.35909)
- **作者:** Kaikai Zhang, Zihan Zhang, Yuchong Xie, Zesen Liu, Shuangjie Yao, Zhixiang Zhang, Dongdong She
- **分类:** cs.CR, cs.AI
- **摘要:** 自主 LLM agent 把漏洞发现变成**仓库级搜索**：它们生成大量漏洞假设，但在有限预算下只能验证其中一部分。本文证明自主漏洞发现存在**假设-验证不对称**——通过可达性分析、执行与 PoC 构造来验证一个候选假设，远比**形成**它昂贵。在有限资源预算下，这使自主发现成为一个**资源受限的选择性验证**过程，进而把「验证努力」本身暴露为一个独特的**防御面**。作者提出 **RedHerring**：插入**可证安全**的诱饵，把验证努力从真实漏洞上引开。每个诱饵组合一条源自 CVE 的漏洞链（吸引验证）与一座**假桥**（使其危险 sink 不可达）；一份私有证书让防御者能高效验证该性质，而**从发布的仓库确立同一事实需要解一个计算困难问题**；诱饵还会适配目标仓库，使其读起来像普通程序逻辑。在 33 个 OSS-Fuzz 项目、70 个评估实例、五个模型、预算匹配的条件下：真实漏洞发现数下降 **38.7–60.4%**；轨迹分析显示 agent 把 **30.6–51.5%** 的完成 token 与估计 **32.5–49.9%** 的运行时间花在验证诱饵上。**即使明确告知可能存在诱饵**，相对知情基线仍下降 **37.2%** → 有效性不依赖诱饵保密。
- **关联度:** ★★★★☆ 换个角度理解「验证」：验证不是免费的，且**验证预算可被攻击者操纵**。对 k 的启示偏防御性——当 sora 用 agent 做安全扫描时，「扫出来一堆高危」可能正是被诱导的结果；优先级排序要结合**验证成本**而非只按严重度。也提示：安全扫描结论应标注「验证了哪些、跳过了哪些」。

### 31. Memory Is a Derivation: The Distributed-Evidence Paradox in Long-Term Agents

- **ID:** [2609.36130v1](https://arxiv.org/abs/2609.36130v1) | [📄 PDF](https://arxiv.org/pdf/2609.36130)
- **作者:** Hongjun Liu, Chen Zhao
- **分类:** cs.AI
- **摘要:** 长期运行的 LLM agent 把过去交互压缩成持久记忆，之后可能被当作后续任务的**前提**复用 → 由此产生一个独特的**推导问题**：该记忆是否真的能从交互历史所支持的内容中推出。相关证据可能散落在更早的交互里，而压缩可能引入历史**从未确立**的关系或事件状态。因此一条有效记忆可能因为引用遗漏了相关证据而显得无支撑；反过来，各自被支持的事实也可能被组合成历史从未确立的**更强陈述**。作者用三个耦合要求刻画该问题：证据范围、组合有效性、准入可靠性，并提出 **DerivAudit**——审计一条记忆是否真被「**写入时可得的历史**」所支持。审计分离三问：支持证据是否在写入者提供的引用之外、组合后的记忆是否引入不被支持的含义、写入时准入决策如何影响后续记忆使用。在两个自然记忆语料上：用更宽的写入前历史审计，**近 60%** 从引用看无支撑的记忆被找回支撑；扩大证据后仍有 **17–21%** 无支撑。但更宽证据本身并不能让准入可靠：无支撑记忆仍频繁被各验证模型准入，且**单靠证据扩张在两个骨干上反而更糟**。
- **关联度:** ★★★★★ 直接指向 k 的记忆机制：`memory` 里的条目是**从会话历史推导出来的**，而推导可能引入历史从未确立的内容。可落地：① 写记忆时记录**证据出处**（哪次会话/哪份文件），别只写结论；② 定期审计记忆是否有历史支持，而不是默认「记下来的就是对的」；③ 别指望「给更多上下文」自动提高准入准确率——那可能反而更糟。

- **摘要:** 多智能体系统常以「是否得出正确答案」来评判，这会漏掉一种独特的失败：即使**当下决策正确**，协作也可能留下**被污染的信息状态** → 作者称之为 **off-query failure**。为研究这种失败，作者提出 **OffQuery**，在协作决策支持中分别评估**证据验证（T1）、共享状态重建（T2）、任务解决（T3）**，覆盖两个高风险场景（医疗与灾害响应）。在 GPT、Gemini、Qwen 模型上，标准协作的**任务表现远强于状态可靠性**：21 个模型-场景组合平均 T3 达 **64.7%**，而 T1 与 T2 仅 **14.3%** 与 **43.1%**。作者把这一鸿沟追溯到**选择性信息使用**：当前查询常常**绕过**被污染的事实，而这些事实在后续任务需要时才变得关键。为此提出 **ReGround**：解决冲突证据、验证共享事实、重建可信状态、并在该状态上推理。七个模型三个族在**每个**评估设置上都改善全部三项能力，T1/T2/T3 平均相对增益为 **309.0% / 82.9% / 17.6%**。结论：可靠协作既需要正确决策，也需要为未来推理保留可信的共享状态。

### 33. Worse Together: How Performance Breaks Down in Multi-User Multi-Agent Teams

## 今日要点（主题信号）

1. **「技能安全」这一主题在本窗口爆发成完整攻防链，本份又补上六篇**：攻击侧有 Pretext（**知道检测器就能绕**，对协同自适应检测器仍 77%，且明确提到 OpenClaw 与 Claude Code）、MMSkillRisk（**图像承载**攻击，9 个配置全部被诱导，ASR 43.1%，任务成功与攻击成功同时发生达 72.2%）；审计侧有 SKILLLITE（紧凑模型本地审计）；执行边界侧有三连——ActionGuard（换上下文）、ToolFence（换粒度）、PACE（**证明准入证据不可区分，唯一可用边界是执行时**）；工程侧有 Approval Laundering（**批准的动作 ≠ 执行的动作**，六类洗白）与 Aletheia（**逐项撤权看还能不能过**）。合起来对 k 的结论很硬：装前扫描**不够**，必须叠加**执行时授权 + 授权-执行绑定校验**。

2. **「技能自演化」这一主题从「能改」推进到「改得对」**：SAGE 指出朴素门禁两种失败（永久回归 + Optimizer's Curse），用**逐项配对 + 单边检验 + 弃权**把 20 个设置中 19 个的回归率降下来（两例降到 0%）；Self-Evolving Harness 用「同一模型既当 solver 又当 proposer」从 49 行种子长出超过 Codex 的 harness；EngramBench 则给出诚实的边界——**技能库不替你做最后一公里，但能当执行罗盘**（编码时间 −55% 以上）。三篇合读 = 技能演化该有「**逐项验收 + 弃权 + 诚实的能力边界声明**」。

3. **「验证与评测的可靠性」继续被系统性拆解，且本份新增四条独立证据**：Agent Evaluation Reliability 证明**更多任务救不了 scaffold 覆盖不足**（模型排序可靠性仅 0.148–0.841，无限加同类任务最多 +0.097）；SINGED 证明**输出对 ≠ 执行对**（rank-one 45% 出现 counterfeit 执行，移除良性替代品后 55/175 单元格执行了 counterfeit）；Do Agent Benchmarks 的契约审计发现 34 个工具中 7 个缺陷、且 33 个计分漏报里 29 个「契约有条款但没有探针」；WebArena-Lite 的人工审计则直接纠正了自动评测器的**假阴性**。→ k 的验收格式该统一升级：**结论 + 可靠性区间 + 执行路径 + 未覆盖项**，四件套缺一不可。

4. **长时程上下文管理出现「从压缩转向状态」的共识**：FOCUS 把压缩目标改成**因果决策保持**（免训练，峰值上下文 −48%、依赖 −73%、成功率 +8.9 分）；AutoCompact 把「何时压缩/保留什么/如何继续」训成策略（SWE-bench Verified +9.2%）；PoS 主张**显式信念状态**（世界状态 + 未完成要求，并检测 Belief Trapping）；Memory Is a Derivation 则从审计角度指出记忆是**推导产物**，近 60% 看似无支撑的记忆在更宽历史下被找回支撑，但仍有 17–21% 无支撑、且证据扩张单独会**更糟**。→ k 该从「记住聊过什么」升级到「**显式维护当前状态 + 未完成项 + 证据出处**」。

5. **多智能体协作被两篇实证从「正确性」和「群体收益」两侧证伪**：Right Answers, Wrong States 发现任务解决 64.7% 而证据验证仅 14.3%、共享状态重建 43.1%（off-query failure：当前查询绕过被污染事实，后续才发作）；Worse Together 发现多用户多 agent 团队**每个环境**都劣于单协调者，无通道时两个环境完全崩溃。→ 委派前先问「是不是一个 agent 干更好」，多 agent 必须配显式流程与「提交前先读同伴消息」。
