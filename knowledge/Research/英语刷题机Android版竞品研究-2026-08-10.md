# 英语刷题机 Android 版竞品研究（千轮研究）

> 参考项目：wssfk12138/android-english-multiple-choice-practice-machine（英语刷题机 Android——我们项目的独立发行版——为竖屏/大屏重新设计）

## 核心结论

**参考项目不是"桌面缩小"而是"移动端重新设计"**——窗口宽度驱动交互密度（平板横屏双栏/手机竖屏/分屏）。这是我们的 Capacitor 版最该借鉴的方向。

## 参考项目关键设计（可借鉴）

### 1. 响应式布局
- 平板大屏：横屏双栏（左文章/右题目）
- 手机/窄窗口：竖屏信息架构
- 支持平板分屏

### 2. 四项底部导航（功能重组）
- **首页 / 笔记 / AI / 设置**
- 错题本 + 单词本 → 笔记入口
- 导入、回收站、更新、帮助、模型配置 → 设置

### 3. 首页按题库动态显示
- 顶部切换题库
- 只显示当前题库**实际存在**的听力/完形/阅读/Part B 入口（无听力不显示听力）
- 试卷列表只显示名称；词汇回顾五秒一组上下翻页

### 4. 竖屏练习上下分区
- 上方文章/听力控制区 + 下方题目/选项区——**独立滚动**
- 中间**分隔条可拖动**（调整上下占比）

### 5. 紧凑工具栏
- 退出/计时/答题卡/更多 = 图标按钮
- 答题卡从顶部打开抽屉
- 底部集中：单篇提交 + 整卷提交（不挤压选项）

### 6. 笔记组织
- 错题本：题库配置 → 年份 → 篇目
- 单词本：跨题库共享

### 7. AI 对话（竖屏优化）
- 填充导航栏与状态栏之间区域
- 模型选择器靠近发送按钮
- 长消息不撑宽页面

### 8. 更新机制（完整）
- `android-update.json` 清单：schemaVersion/versionName/versionCode/apkUrl/apkSha256/releaseNotes
- GitHub Release 优先 + 2 个 HTTPS 镜像回退（ghproxy.net / gh-proxy.com）
- APK 下载后核对大小 + SHA-256 → 系统安装器确认
- 固定签名（signing.properties.example——私钥本机）

### 9. 题库导入
- ESQ 1.0/1.1 导入/预览/校验/冲突确认/导出
- DOC/DOCX/PDF + MP3/M4A/WAV/OGG 听力
- 模型辅助定位题目（只改草稿——用户批准才入库）
- 智能标注（按本次/年份/全部——听力不发送）
- 扫描版 PDF 明确提示人工 OCR（不伪装成功）

### 10. 练习判分
- 稳定选项键判分（不受显示顺序影响）
- 可选计时；暂停只停计时
- 未答完阻止提交并定位第一道未答
- 单篇提交即时得分；整卷提交整卷成绩
- 听力不显示原文/不做分析/整段提交

## 尺寸与适应性修正（2026-08-10 千轮虚拟测试）

### 虚拟测试方法
- CDP 多视口自动化（360×640 / 375×667 / 390×844 / 768×1024 / 320×568 最小屏）
- 检测：水平溢出（scrollWidth vs clientWidth）、导航遮挡（elementFromPoint）、固定元素越界、白屏
- PIL 像素验证（ui-pixel-verification 惯例——图标列数检测——不信视觉模型描述）

### 测试结果
| 视口 | 结果 |
|:---|:---|
| 360×640 小屏 | ✅ 6 页面全通过 |
| 375×667 SE | ✅ 全通过 |
| 390×844 主流 | ✅ 全通过（1 次偶发时序假报——截图确认正常）|
| 768×1024 平板 | ✅ 全通过 |
| 320×568 最小屏 | ⚠️ 发现：底部导航 6 项挤压重叠（PIL 确认）|

### 修正
- styles.css：@media (max-width:360px) 底部导航紧凑——字号 11→10px、图标 22→17px、高度 60→56px、gap 3→2px
- 修正后 PIL 验证：6 项分布均匀（35→299px 不挤）；触控目标保持（flex:1——320px 每项 53px > 44px 规范）

### 移动端适配最佳实践（研究沉淀）
1. safe-area：env(safe-area-inset-bottom) + 变量兜底（Capacitor edge-to-edge 必需）
2. 高度用 100dvh（非 100vh——移动浏览器地址栏）
3. 底部导航 ≤5 项为佳（参考项目 4 项）；6 项时最小屏必须紧凑
4. 触控目标 ≥44px；flex:1 保证全宽可点
5. 水平溢出防护：max-width:100% + scrollWidth 检查（虚拟测试核心指标）
6. 视觉模型不可靠（同一截图两次 vision 说 4/6 项）——布局判定用 PIL 像素分析

## 移动端离线覆盖全链路修复（2026-08-10 千轮测试——真机验证问题）

### 年级切换（修复 763fdb0）
- 根因：/question-bank-profiles 列表、activate、/papers?profile_id 过滤、/dashboard 推荐——4 个接口离线全未覆盖
- 修复：配置列表本地返回 → 激活更新 is_default → 推荐/试卷按 profile_id 筛选（papers 表有 profile_id 关联）
- 切换后刷新：首页 @changed→loadHome，题库 @changed→loadPapers（传 profile_id）

### 离线覆盖检查清单（真机空白的通用根因）
1. 前端调用的**每个**端点都要离线覆盖（含查询参数路径 `/xxx?status=`——startsWith 或 URL 解析）
2. 返回**结构必须匹配前端期望**（如 /report 要 suggestions/total_answered——缺失字段 → 模板 .length 无可选链 → **渲染中断整页空白**）
3. 前端模板访问用可选链（`?.`）兜底
4. 数组 vs 对象（estimate results 是数组——按对象比较 known 恒 0 → 结果假 0）
5. 字段名映射（库 term vs 前端 word——离线返回要映射）
6. 数据生成（短文填空离线要本地生成 blank_sentence/options/answer——否则无短文无选项卡死）

### 竞品借鉴（词汇量自测/短文填空体验）
- 扇贝短文填词：真题句子挖空 + 4 选项（1 正确 + 3 干扰）——本地生成：contextual_meaning 挖空 + 同库随机干扰词
- 百词斩快答：进度显示 + 即时反馈——本地判分提交（practice 判分模式复用）
- 词汇量自测：认识比例 × 词库总量估算 + 等级（CET-6/考研 ≥12000 等）——竞品多为 15-20 题，我们 10 题

### 竞品移动端设计通则（借鉴）
1. **触控反馈**：百词斩/扇贝所有可点元素按压缩放（active scale .95-.98）——我们已加（.button/.cloze-option/.list-item/.mobile-nav）

3. **底部导航**：≤6 项 + 激活高亮（红色/主色）+ 按压反馈——已 6 项 + 高亮 + scale .9
4. **内容填满**：列表动态高度（100dvh - 头部）——不浪费空间（单词本 470px 固定 → 动态）
5. **安全区**：底部导航 + 页面 padding 用 safe-area-inset-bottom（edge-to-edge 必需）
