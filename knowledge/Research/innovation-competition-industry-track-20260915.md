# 中国国际大学生创新大赛（2026）产业赛道·联通命题研究

> **Draft（草拟）**: 针对联通出题的「基于大模型技术的跨学科多智能体协同学习系统」的命题拆解与技术路径。
> 来源：[中国国际大学生创新大赛（2026）产业赛道方案]、[元景万悟智能体平台开源发布]

## 1. 命题本质与商业逻辑
- **命题方诉求**：中国联通（浙江省分公司）出题，本质是推广其刚开源的企业级智能体开发平台——**「元景万悟」（wanwu）**。
- **竞赛规则**：产业赛道企业命题组，命题企业亲自做「契合度审核评价」。
- **核心对策**：必须使用**元景万悟**作为底层架构（该平台基于 Go 开发，支持工作流编排、GraphRAG、多租户，且提供 Docker 部署），不用该平台必定拿不到契合度高分。

## 2. 命题三模块与万悟能力的映射（Improve: 可执行架构）
| 命题要求模块 | 万悟平台原生能力映射 | 参赛团队需要自建的增量（护城河） |
| :--- | :--- | :--- |
| **学科智能体** | 「智能体」+「知识库 UniAI-GraphRAG」 | 各学科专属知识图谱的构建与导入，定制教学策略 Prompt |
| **协同调度引擎** | 「工作流」（wanwu-workflow，低代码拖拽） | **跨学科协同调度算法**（Plan-Act-Reflect 状态机实现），避免伪协同（串行），实现真协同（Debate/圆桌机制） |
| **认知轨迹可视化** | ❌ 平台无此功能 | **独立的前端大屏/画布**，通过调用万悟 RESTful API 获取交互日志，将思维路径渲染到图谱界面上 |

## 3. 落地坑点与规避策略（Debug: 找失败点）
1. **Docker 部署环境限制**：万悟是基于 Docker Compose 部署的（包含 BFF、数据库、ES、Redis 等多微服务）。若本机无虚拟化环境（如 sora 当前设备），则无法本地跑通。
   - **对策**：立刻验证能否申请联通元景 MaaS 云的 API key，直接调用云端大模型接口，本地仅实现前端可视化与调度控制流；或租用云服务器部署万悟后端。
2. **"真"多智能体协同**：万悟目前的 `TODO` 列表明确写了 `A2A协议`（智能体间通信）尚未实现。
   - **对策**：这是拿高分的关键点。通过万悟的工作流模块（Workflow Studio）手动编排节点，模拟一个协调者（Hierarchical）来中转不同学科智能体的对话，实现「辩论/互相质疑」机制。
3. **隐私合规**：命题要求数据隐私保护机制。
   - **对策**：万悟支持多租户隔离。在对策书中强调使用本地化/私有化部署的脱敏策略，避免使用笨重的联邦学习（经济性得分低）。
