# EU AI Act 2026-08 生效评估（Multi-Agent 场景合规）

> 每日待办落实 cron 于 2026-08-01 执行评估。结论先行：**对 sora 的闲鱼接单/个人开发场景无直接影响**，但对「接 EU 客户单 / 部署多 Agent 产品」有前置约束，需在交付时评估。

## 关键时间线

| 时间 | 事件 |
|:-----|:-----|
| 2024-08-01 | 法规生效（Regulation 2024/1689） |
| 2025-02 | 禁止性 AI 实践已生效 |
| **2026-08-02** | **Annex III 高风险 AI 义务强制执行**（风险管理系统 Art.9、数据治理 Art.10、技术文档 Art.11、防篡改日志 Art.12、透明度 Art.13、人工监督 Art.14、网络安全韧性 Art.15、QMS Art.17、上市后监控 Art.72） |
| 2026-08-02 | Art.50 透明度义务 + GPAI 执法权 + 完整处罚机制生效 |
| 2026-02 提案 | Digital Omnibus 拟将 Annex III 高风险义务推迟至 **2027-12**（未立法，勿按推迟规划） |

## 对 Multi-Agent 架构的核心影响

> **Recital 99/100 明确**：在 agent 链中，合规边界延伸至**每个执行高风险功能的 agent**。AI agent 调用 API（内部服务/第三方平台/MCP 服务器）即进入 Act 的网络安全与日志强制范围。

| 维度 | 要求（高风险系统） | 对我们的意义 |
|:-----|:------------------|:-------------|
| 风险分类 | 连续风险管理（Art.9） | 接单前先判断交付物是否属高风险场景 |
| 日志 | 防篡改日志保留 ≥6 个月（Art.12） | 若交付多 agent 系统，需内置日志 |
| 透明 | 部署者透明义务（Art.13） | 交付文档需说明 AI 使用 |
| 人工监督 | HITL 能力（Art.14） | agent 产品必须有人工干预入口 |
| 网络安全 | 韧性要求（Art.15） | MCP/API 调用层需安全设计 |
| 标记 | CE 标记 + QMS（Art.16/17） | 仅 EU 市场销售需要 |

## 评估结论（对 sora 场景）

1. **闲鱼论文/PPT/PCB 接单**：交付物为一次性文档/设计，不属「高风险 AI 系统」，**不受影响**。
2. **微信小程序/校园平台开发**：若客户面向 EU 用户且功能涉高风险（如简历筛选、信用评估），需按 Art.9-17 做基础合规（日志 + 人工监督 + 文档）；**当前校园场景大概率不在范围**。
3. **多 Agent 产品/服务**（如自建 agent 平台对外提供）：**明确进入范围**——链式 agent 每个执行高风险功能的环节都要合规；建议至少保留审计日志 + HITL 升级路径（与 MEMORY.md 中「Bounded Autonomy」最佳实践一致）。
4. **Digital Omnibus 推迟提案**：只是提案，未立法。不推迟规划，按 8/2/2026 生效准备。
