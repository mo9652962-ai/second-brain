# File is not all you need — AI 科研协作五元解耦模型研究

> 来源：小黑盒长文（吃太饱骑士，非计算机博士，2 个月 110 亿 Token 实测）
> 2026-07-31 验证 + 吸收

## 文章核心论点

**File is not all you need.**
AI 科研协作的关键不只是模型能力，而是**项目如何被表达**。
模型再强，如果看到的只是零散文件、孤立对话和混乱记忆，依然很难理解一个持续推进的项目。

## 三种交互介质的问题

| 介质 | 优点 | 局限 |
|------|------|------|
| Web 端应用 | 轻量、易用 | 数据组织单薄；对话彼此独立；记忆碎片化无项目边界 |
| 本地软件（文件夹） | 直接访问文件 | 只能表达"包含关系"，表达不了"关联/因果/版本/证据关系" |
| 索引文件（妥协方案） | 集中表达关系 | 膨胀成新垃圾场（套娃）；AI 难同时做执行者和记录者 |

## 核心模型：科研项目五元解耦

从 AI 协作视角，科研项目应解耦为 5 个部分：

| 组成部分 | 角色 | 关键洞察 |
|---------|------|---------|
| **对话** | 科研发生的现场 | 对话的价值在于产生知识，不是替代知识管理。「上下文不是仓库，更不是垃圾桶」 |
| **文件** | 承载相对稳定/体量大的信息 | 文件告诉 AI"这里有什么"，不独自承担逻辑结构 |
| **文献** | 特殊知识资源（元数据/摘要/关系/可信度） | **分层读取**：先摘要→判断相关→需要时才读全文。像人查文献一样，不整篇塞进上下文 |
| **实验资源** | 实验室真实条件（设备/耗材/软件/限制） | 没有它 AI 只会给"理论上先进实际做不了"的方案。「我要有那设备，我还研究这个？」 |
| **记忆** | 跨对话可复用的核心知识 | 需要允许新增/修订/合并/降级/失效/追溯来源。对话才能接续，而非不断重启 |

## 关键洞察（可迁移）

### 1. 执行者 vs 记录者视角分离（最重要的新认知）
- AI 执行任务时是**参与者**（当前任务怎么完成）
- 维护项目知识时需要切换成**旁观者/记录者**（这次任务对整个项目意味着什么）
- 让同一个 AI 在同一时刻做好两件事，效果并不稳定——**信息价值判断本身是独立任务**
- 类比：一次讨论产生十几个想法，真正值得长期记忆的也许只有两个

### 2. 文献分层读取机制
- 先读元数据/摘要/项目内备注 → 判断相关 → 需要时再读方法/结果/段落
- 直接映射我们的规则 #21 干湿分离（检索→提炼→再行动）

### 3. 上下文不是仓库，更不是垃圾桶
- 不加区分地堆对话/文件 = 信息越多不一定越好
- 呼应规则 #21（干湿分离）+ 规则 #15（跨天会话）

### 4. 错误结论污染知识库（评论区高价值）
- 物理博士评论：AI 框架无法深度耦合科研，最大问题是**错误结论污染知识库**
- 组会/同门讨论出的结论 AI 有极度滞后性
- 呼应规则 #13（记忆因果验证）+ 规则 #25（阴性结果登记）

## 对我们的落地

**我们已有覆盖（无需新增）**：
- 对话管理 → 规则 #15 跨天会话生命周期
- 干湿分离 → 规则 #21 检索-提炼-再行动
- 记忆验证 → 规则 #13 因果验证 + 规则 #11 价值量化
- 阴性结果 → 规则 #25 + .learnings/NEGATIVE-RESULTS.md

**新吸收 → 规则 #26（参与者/记录者视角分离）**：
- 执行任务与记录知识是两个视角，同一时刻难以两全
- 信息价值判断是独立任务：做完任务后单独设置"记录检查点"
- 解决"边执行边记录"导致的顾此失彼

**结论**：文章用 110 亿 Token 验证了我们 Second Brain 体系的正确方向——我们的 Obsidian + Hermes + .learnings 分层记忆正是"五元解耦"的实践形态。
