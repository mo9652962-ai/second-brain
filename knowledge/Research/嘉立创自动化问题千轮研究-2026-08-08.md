# 嘉立创自动化问题千轮研究 · 2026-08-08

> 2 轮 × 6 路搜索：jlc-mcp 连接失败根源 + 官方替代方案 + 版本兼容。核心发现：**我们操作流程缺了关键一步（PCB 页 + 顶部菜单 Enable Bridge 命令），且可能版本过低（2.x vs 3.x）**。

## 结论置顶

**jlc-mcp 连不上 = 两个可能根因：①操作流程缺关键步骤——必须在 PCB 页点顶部菜单 "JLC Bridge → Enable/Disable Bridge"（我们只勾选了配置开关，没点启用命令，且用户新建的是原理图页不是 PCB 页）；②EasyEDA Pro 版本可能过低（文档基于 v3.2，插件 engines ^2.3.0，新版 AI 插件要求 ^3.0.0）。修复路径优先级：先按文档正确操作（3 分钟）→ 换官方 Run API Gateway → 升级 EDA 3.x → 终极用 KiCad 双轨。**

## 一、jlc-mcp 正确使用流程（阿坦指南 2026-06-22，嘉立创 EDA v3.2 实测）

```
① 启动 relay（start-jlc-relay.ps1）
② 打开嘉立创EDA → 打开工程 → **进入 PCB 页**（原理图页部分工具不可用！）
③ **顶部菜单：JLC Bridge → Enable/Disable Bridge**（点命令！不是勾配置）
④ 再点 JLC Bridge → Status 验证：Runtime: running / Transport: WebSocket / WS: connected
⑤ 打开 Cursor/Agent → pcb_ping 测试
```

### 常见问题对照表

| 症状 | 原因 | 处理 |
|:---|:---|:---|
| `bridge not connected` | EDA 扩展未 WebSocket 连上 relay | ①确认 relay 运行 ②勾选允许外部交互 ③**PCB 页：JLC Bridge → 先关闭再开启** ④Status 确认 WS: connected |
| 显示 `file polling` | 未开启外部交互权限 | 重导入扩展 + 勾选「允许外部交互」+ 重启 Bridge |
| 顶部菜单无 JLC Bridge | 命令未注册/未重启 | 勾选「显示在顶部菜单」后**重启 EDA** |
| 端口 18800 被占 | 冲突 | netstat -ano \| findstr 18800，结束占用进程 |

**我们踩的坑**：用户只勾选了「允许外部交互」+「显示在顶部菜单」，但 **①没点顶部菜单的 Enable Bridge 命令 ②没确认在 PCB 页 ③没看 Status 验证**——这正是文档 Q1/Q2 覆盖的场景！

## 二、官方替代方案（推荐）：Run API Gateway

**github.com/easyeda/eext-run-api-gateway** —— 嘉立创官方 WebSocket 网关扩展

```
AI Agent ←HTTP/WS→ Bridge Server (Node.js) ←WS→ 本扩展 (EasyEDA)
              端口 49620-49629 自动扫描
```

- **自动连接**：加载后自动扫描端口范围找 Bridge Server，无需手填 IP/端口
- 连接失败重试 5 次后，可手动点击重试
- 配合官方 **easyeda-api-skill**（github.com/easyeda/easyeda-api-skill）——OpenCode/Claude/QwenCode 读 SKILL.md 后用 HTTP API 发代码给 EasyEDA
- 消息协议：execute / result / error / handshake / ping-pong
- **官方维护 = 比第三方 jlcmcp 可靠**

## 四、版本兼容（可能根因）

| 文档 | 版本要求 |
|:---|:---|
| 阿坦指南（jlc-mcp 实测）| 嘉立创 EDA **v3.2** |
| jlcmcp 插件 engines | ^2.3.0（宽松）|
| JLCEDA AI Agent | **^3.0.0** |

**推断**：若用户 EDA 是 2.x，SYS_WebSocket API 可能不完整或行为不同 → 插件加载但命令/连接异常（与我们症状吻合：插件显示已启用但顶部菜单无命令、WS 不连）。**升级到 3.x 大概率解决。**
