## 一、六种编排模式（定位我们的模式）

| 模式 | 结构 | 我们对应 |
|:---|:---|:---|
| Orchestrator-worker | 1 规划 + N 执行 | ✅ k 拆题 → WorkBuddy/dsh 执行 |
| Sequential pipeline | A→B→C | ✅ 研究→初稿→核验→沉淀 |
| Fan-out/fan-in | 1→N→1 | ✅ 三工具并行 + k 汇总 |
| Debate（maker-checker） | A 生成 B 校验 | ✅ Gemini 二审 |
| Dynamic handoff | 运行时路由 | ❌ 暂不需要 |
| Adaptive planning | 动态计划 | ❌ 暂不需要（我们是固定流水线） |

**失败模式对照**：orchestrator 是单点（k 必须稳）；sequential 错误级联（→ 验证门前置解决）；debate 会过度共识（→ 信息不对称解决）。

## 二、关键实证（为什么这样增强）

### 1. 幻觉雪球（arXiv 2608.14588）——验证门前置
- 幻觉在流水线逐级转化：**原始事实 → 推导 → 叙述 → 不可见**
- 检测率：Stage1 72% → Stage4 50.9%，23.7% 全程漏网
- **边界门比末端检查有效 42.2pp**；第一道门捕获 75.4%，比 Gate2+3 加起来都值钱
- → 我们：WorkBuddy 初稿回来 = 第一道门，立即质疑式核验

### 2. MARCH（ACL 2026）——信息不对称盲评
- 验证者看到生成者输出 → 确认偏差，重复错误
- **Checker 隔离验证（不给看 Solver 输出）→ 幻觉率大幅下降**
- → 我们：Gemini 二审升级为「给原始素材 + 独立问题，不让它看 WorkBuddy 报告」

### 3. Handoff 交接（geodocs 规范 + bmad evals）
- 交接是系统第一失败模式（不是模型质量）：上下文丢失 + 输出格式模糊
- 模糊指令「Apply fixes for all 4 issues」→ 下游质量崩
- **密任务包 8 槽**（Task/Why/Prior findings verbatim/Actions/Sources/Skills/Criteria/Report back）→ 交接质量 76.8% → 100%
- → 我们：研究任务书升级为 8 槽密任务包，Prior findings 原样贴不许压缩

### 4. 单 agent vs 多 agent（Princeton NLP + Nature + arXiv 2604.02460）
- **单 agent 在 64% 任务匹配或超越多 agent**；多 agent 精度 +2.1pp 但成本约 2 倍
- 多 agent 价值在：单 agent 上下文饱和 / 并行无共享状态 / 错误成本高
- 简单任务开多 agent = 纯浪费（4-220x token 消耗）
- → 我们：五问决策，快速查询只用 k

### 5. 成本护栏（OpenLegion）
- token 预算不够，还要 **step 预算**（防 ReAct 死循环 500 次）
- 编排收益 ~4 agent 封顶；上下文 ~7 handoffs 指数衰减

## 三、增强落点（已进技能 v1.1）

| 增强 | 技能章节 | 一句话 |
|:---|:---|:---|
| 交接契约化 | 密任务包 8 槽 | 派活 = 密任务包，不是聊天记录 |
| 验证门前置 | Gate 1 最值钱 | 初稿回来立即质疑式核验，不拖汇总 |
| 信息不对称盲评 | Gemini 二审升级 | 给原始素材独立作答，不喂 WorkBuddy 结论 |
| 成本护栏 | 五问决策 | 单 agent 能搞定就别开多 agent |

## 四、对联合工作的具体改变（立即生效）

1. **以后派活给 WorkBuddy/dsh**：用 8 槽密任务包（task_summary ≤500 字 + prior findings 原样贴）
2. **以后 Gemini 二审**：疑难节点给原始素材独立作答（盲评），普通问题保持轻量问题包
3. **以后核验**：质疑式——先找数字/日期/引用茬，不扫一眼说 OK
4. **以后判断要不要多 agent**：五问决策，快速查询只用 k
