# 协作架构自进化 Review（MANTA 落地）— 固定拓扑盘点 + 试点任务

> 对应 arXiv 核心贡献精选 2026-08-03 🥇 MANTA：把多智能体通信拓扑从「部署前定死」变成「运行时自演化」。

## 一、现状盘点：现有协作拓扑（全是固定）

### 1. 并行子代理拓扑（delegate_task）

```
主代理（协调者，固定角色）
  ├── 子代理 A（固定分工：研究）
  ├── 子代理 B（固定分工：编码）
  └── 子代理 C（固定分工：验证）
```

| 维度 | 现状 | 问题 |
|:-----|:-----|:-----|
| 角色分配 | 调用时由主代理一次性决定 | 任务中途发现分工不当无法调整 |
| 通信拓扑 | 星型：主代理↔子代理，子代理间不直接通信 | 相关子代理信息需主代理中转（瓶颈） |
| 信息可见性 | 主代理决定给谁看什么 | 子代理拿到无关上下文浪费 token |
| 执行顺序 | 并行（batch）或串行，由调用决定 | 无法按中间结果动态改顺序 |
| 验证路径 | 子代理自报结果，主代理最终判断 | 缺少独立验证子代理 |

### 2. Cron 定时任务拓扑（独立节点，无协作）

```
[20 个 cron 任务] 互相独立，各自读/写 vault
  ├── arxiv-fetch → arxiv-summarize（链式，固定）
  ├── daily-self-improvement → daily-review（链式，固定）
  └── 其余 17 个：孤岛（无信息交换）
```

| 维度 | 现状 | 问题 |
|:-----|:-----|:-----|
| 角色 | 每个 cron 固定职责 | 无动态改职责机制 |
| 通信 | 通过文件系统（vault）间接通信 | 无直接消息通道 |
| 顺序 | cron 表达式固定 | 无按结果动态调度 |

### 3. 外部编码代理拓扑（autonomous-ai-agents）

```
主代理（Hermes）
  └── 委派 → claude-code / codex / opencode（任选其一）
      └── 子代理返回结果 → 主代理 review
```

| 维度 | 现状 | 问题 |
|:-----|:-----|:-----|
| 角色 | 工具选择由任务类型决定（固定映射）| 无「换工具」机制 |
| 可见性 | 任务 goal 里写死上下文 | 无法中途补充关键信息 |

## 二、MANTA 的启发：哪些可以「自进化」

MANTA 核心约束：`Agents ≤ Budget`、`Mutations ≤ 1 per run`、`Operations ≤ 3 per mutation`、**保留任务接口 + agent 预算**。

### 可落地的 4 个拓扑变更维度（对应 MANTA）

| MANTA 维度 | 在 Hermes 的对应 | 可行性 | 试点 |
|:-----------|:----------------|:------:|:-----|
| **改角色** | delegate_task 时动态调整子代理分工 | ⭐⭐⭐⭐ | 研究任务中：初赛调研 → 深挖 → 验证 |
| **改通信链接** | 子代理间共享中间结果（不再全走主代理中转）| ⭐⭐⭐ | 并行研究后合并交叉验证 |
| **改执行顺序** | 按中间结果决定串行/并行 | ⭐⭐⭐ | 先搜证再写结论 vs 先写再验证 |
| **改验证路径** | 增加独立验证子代理 | ⭐⭐⭐⭐⭐ | 所有 delegation 加「验证者」角色 |

## 三、试点任务设计（第一个落地实验）

### 试点：文献调研 + 交叉验证（arXiv 周报场景）

**当前固定拓扑**（本周刚跑过）：
```
主代理
  ├── 子代理 A：检索收集（arxiv_collect.py）
  ├── 子代理 B：相关性过滤（主代理自己做）
  └── 子代理 C：交叉验证（web_search 批量）
```

**自进化拓扑（试点版）**：
```
主代理（角色：协调者，budget 固定 3 子代理）
  │
  ├── 阶段 1：调研员（检索 12 篇）
  │     └── 产出：候选池 + 每篇一句话
  │
  ├── [监控点] 主代理评估：候选池哪几篇值得深挖？
  │     └── 若发现「主题重合」→ 触发 mutation：合并调研员+验证者
  │
  ├── 阶段 2：深挖者（选 3 篇写核心贡献）
  │     └── 产出：3 篇草稿
  │
  ├── [监控点] 主代理评估：草稿是否可信？
  │     └── 若发现「证据不足」→ 触发 mutation：增加验证者
  │
  └── 阶段 3：验证者（web_search 交叉验证 + 去重检查）
        └── 产出：验证状态标记 + 回写周报
```

**关键差异**：
1. **执行顺序动态化**：根据候选池质量决定阶段 2 选几篇（当前固定 3 篇）
2. **验证路径动态化**：草稿证据不足时才加验证者（当前固定全验证）
3. **保留约束**：子代理预算 ≤3、任务接口不变（产出都是周报 + core-contributions）

### 落地触发器

```
条件：下次 arxiv-summarize cron（周日 13:00）执行时
动作：在 prompt 中增加「动态拓扑」指令：
  - 先评估候选池主题重合度
  - 重合度高 → 合并调研与验证阶段
  - 草稿证据弱 → 增加验证者子代理
```
