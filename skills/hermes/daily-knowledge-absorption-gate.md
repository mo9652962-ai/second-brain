# 每日知识吸收底线守门人

> 规则：**每一天，至少要有 1 个主动的知识吸收项**

---

## 🎯 目标

防止出现 2026-07-28 的情况：全天被突发事件占满，没有任何主动的知识输入或工具发现。

---

## 🧪 检查逻辑（daily-self-improvement cron 末尾执行）

```
检查标准（满足任意 1 项即可）：
1. knowledge/ 目录下有当天新增的文件
2. skills/ 目录下有当天的更新
3. memory/ 目录下有当天的 absorbed/learning 条目
4. 当天执行过 web_search 并有对应的知识吸收产出
5. 当天尝试过至少 1 个新工具 / 新命令

全部都不满足 → 触发「知识吸收守门员」警报
```

---

## 🚨 警报触发后的行动

```
轻度警报（当天 22:00 前未达标）：
  ├── 自动弹出 3 个快速吸收选项
  ├── 选项 A: 读 1 篇论文摘要（5min）
  ├── 选项 B: 快速看 1 个新工具（5min）
  └── 选项 C: 复盘 1 个今天踩的坑（5min）

重度警报（第二天还没补）：
  └── 写入反思日志，作为改进项
```

---

## ⚡ 快速吸收 5 分钟选项库

### 论文类
```
1. 从 arxiv 今日入库的论文中挑最感兴趣的 1 篇
2. 只看摘要和结论
3. 写 3 句话：核心思想 + 跟我的关系 + 可能应用
4. 保存到 memory/ 作为当天的 absorbed 项
```

### 工具类
```
1. 从待办的工具列表里挑 1 个
2. --help 看用法，跑 1 个最简单的测试命令
3. 写 3 句话：工具做什么的 + 我能用在哪 + 对比现有方案
4. 保存到 memory/ 作为当天的 trialed 项
```

### 复盘类
```
1. 今天踩的最大的坑是什么？
2. 为什么会发生？
3. 下次怎么避免？
4. 保存到 memory/ 作为 pitfall 项
```

---

## 📝 arxiv-summarize 增强逻辑

```
原逻辑：
  批量总结 2-3 篇论文 → 入库 → 结束

增强后：
  批量总结 2-3 篇论文 → 入库 → 自动提取 Top 1 最有启发的发现 → 写入 daily log
```

**为什么？** 论文自动总结完就躺库里了，很少再看。每天强行提取 1 个最有价值的点，确保 cron 的产出被人看到，而不是石沉大海。
