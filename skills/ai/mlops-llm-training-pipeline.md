## 2. 什么时候该微调？

### 2026 年的标准答案：**Prompt → RAG → Fine-tune → Distill**

| 技术 | 成本 | 适用场景 |
|------|------|---------|
| **Prompt 工程** | $ | 简单任务，10-100 个样本就够 |
| **RAG** | $$ | 需要注入新知识，内容频繁更新 |
| **微调 LoRA** | $$$ | 需要固定行为模式、输出格式、风格 |
| **蒸馏小模型** | $$$$ | 降低推理成本，需要部署到端侧 |

### ✅ 应该微调的场景

1. **输出格式需要 100% 稳定**（JSON Schema 等结构化输出）
2. **行为模式需要固定**（拒绝策略、安全对齐、特定语气风格）
3. **Query Rewriter** — 把用户问题转化为检索查询
4. **Reranker** — 在生产反馈数据上训练排序模型
5. **域适应** — 医疗/法律等强专业领域

### ❌ 不应该微调的场景

1. **注入事实性知识** — 请用 RAG！微调记不住事实，知识会过时
2. **任务简单到 Prompt 就能搞定** — 不要杀鸡用牛刀
3. **没有高质量数据** — 垃圾进垃圾出，100 个好样本 > 10000 个垃圾样本

## 3. LlamaFactory 快速入门

### 环境要求

```bash
Python 3.11+
PyTorch 2.6+
CUDA 12.2+ （推荐）
```

### 四步走训练流程

```bash
# 1. 安装
pip install llamafactory

# 2. 准备数据（JSON 格式 instruction-response 对）
# data/my_dataset.json
[
  {"instruction": "用户问题", "output": "期望回答"},
  // 500-5000 个样本
]

# 3. 写配置文件 train.yaml
model_name_or_path: Qwen/Qwen3-7B
dataset: my_dataset
stage: sft
do_train: true
finetuning_type: lora
lora_rank: 8
learning_rate: 1e-4
num_train_epochs: 3
output_dir: qwen3-7b-lora

# 4. 开始训练
llamafactory-cli train train.yaml
```

### 零代码 Web UI

```bash
llamafactory-cli webui
# 浏览器打开 http://localhost:7860
# 可视化配置所有参数，一键启动训练
```

## 4. Unsloth 速度优化

### 为什么用 Unsloth？

```
普通 LoRA: 基准速度
Unsloth 优化: +170% 速度，显存占用减少 30%
KTransformers: 2× RTX 4090 可以微调 1000B+ 参数
```

### 启用方式

```python
# 在 LlamaFactory 中启用 Unsloth 集成
use_unsloth: true

# 或者直接用 Unsloth API
from unsloth import FastLanguageModel
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="Qwen/Qwen3-7B",
    max_seq_length=2048,
    load_in_4bit=True,
)
```

## 5. 数据准备最佳实践

### 质量 > 数量

```
✅ 1 个完美样本 > 10 个 mediocre 样本
✅ 500 个高质量样本 ＞ 10000 个低质量样本
```

### 数据清洗检查清单

- [ ] 去除所有重复样本
- [ ] 格式 100% 一致（JSON 字段、标点符号、换行规则）
- [ ] 人工抽查至少 10% 的样本
- [ ] 用自动化脚本做格式校验
- [ ] 去掉所有低质量的输出

### 数据集大小参考

| 任务类型 | 推荐样本量 |
|---------|-----------|
| 格式对齐（JSON 输出） | 50-100 |
| 语气/风格迁移 | 100-500 |
| 域适应（专业领域） | 500-2000 |
| 完整能力对齐 | 2000-10000+ |

## 6. 训练参数配置指南

### LoRA 参数速查表

| 参数 | 推荐值 | 说明 |
|------|-------|------|
| `lora_rank` | 8-64 | 越大拟合能力越强，显存占用越高 |
| `lora_alpha` | rank × 2 | 通常设为 rank 的两倍 |
| `learning_rate` | 1e-4 ~ 3e-4 | 7B 用 2e-4，大模型稍微降一点 |
| `num_train_epochs` | 2-5 | 3 epoch 是黄金标准，不要超过 5 |
| `batch_size` | 4-32 | 能装下的前提下越大越好 |
| `gradient_accumulation` | 1-8 | 等效增大 batch size |

### 量化选项

| 量化方式 | 显存节省 | 质量损失 | 推荐 |
|---------|---------|---------|------|
| FP16 | 0% | 0% | 显存够就用 |
| 4-bit QLoRA | ~75% | 几乎不可察觉 | ✅ 绝大多数场景推荐 |
| 8-bit | ~50% | 0% | 预算充足可选 |

## 7. 模型评估与上线

### 训练后检查清单

- [ ] 损失曲线平稳下降，没有剧烈震荡
- [ ] 人工抽查 20 个生成样例
- [ ] 在测试集上做自动化评估
- [ ] 和基线模型做盲测对比
- [ ] 检查有没有灾难性遗忘（通用能力退化）

### 上线运营成本

> **重要：训练成本只是总成本的 20%！**

```
训练成本: $100-$500
    ↓
运营成本: $300-$2500/月（推理 + 监控 + 重新训练）
    ↓
一年总拥有成本: 训练成本 × 3-5 倍
```

### 版本化与生命周期管理

- 把训练配置、种子、数据集快照当作代码版本管理
- 每季度重新验证一次适配器兼容性
- 基础模型更新时要重新训练适配器
