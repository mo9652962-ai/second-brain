# 📝 关于 7/28 改进文件的命名说明

## 为什么有两份？

```
memory/2026/07/2026-07-29-reflection.md
└── 这是「次日回顾」模式生成的，内容是回顾 7/28，文件名是 7/29
    （Cron 默认的旧命名逻辑，运行日 = 文件名）

memory/2026/07/2026-07-28-improvements.md
└── 这是「即时改进」模式生成的，内容是 7/28 发生的事，当天就改进落地
    （文件名 = 事件发生日，符合新命名逻辑）
```

## 未来的命名规则（从 7/29 运行的 Cron 生效）

```
✅ 文件名 = 被回顾的那天（事件发生日）

例子：
  7月29日早上8:30运行 Cron → 回顾7月28日 → 文件名: 2026-07-28-reflection.md
```

## 背景

这是 **反馈周期加速** 的产物：
- 原来：今天发生的事 → 明天早上回顾 → 明天下午改进（24小时延迟）
- 现在：今天发生的事 → 今天下午就反思 + 落地改进（几小时闭环）

**好事！说明我们的进化速度在加快！** 🚀
