# 🎨 知识库风格指南（Vault Style Guide）

> 参考 Obsidian 创始人 Steph Ango 的建议制定——一致的风格省下数百次决策。

## 核心原则

1. **大量使用内部链接 `[[]]`**——每条笔记至少 1 个出链 + 被 1 个入链引用（孤立笔记会被每日脚本自动补链到所属 MOC）
2. **用 MOC 组织，少用嵌套文件夹**——`knowledge-map.md` 是总入口，`MOC-*.md` 按域组织
3. **日期统一 `YYYY-MM-DD`**——文件名/笔记内日期都用此格式
4. **标签复数 + 小写**——`#research` `#hardware`（不建 `#Researchs` 变体）
5. **frontmatter 必备**：`tags` / `type` / `created`（模板已内置）

## 标签归一化规范（2026-11-06 起强制）

> 背景：全库 1264 个唯一标签里有 26 篇笔记用了单复数/大小写/空格变体，检索时同一概念被拆成两个标签。以下为唯一真相表，新建笔记一律用右列写法。

| ❌ 废弃写法 | ✅ 统一写法 | 说明 |
|:---|:---|:---|
| `skill` | `skills` | 复数优先 |
| `project` | `projects` | 复数优先 |
| `tool` | `tools` | 复数优先 |
| `model` | `models` | 复数优先 |
| `benchmark` | `benchmarks` | 复数优先 |
| `research-tool` | `research-tools` | 复数优先 |
| `core-contribution` | `core-contributions` | 复数优先 |
| `ten-round` | `ten-rounds` | 复数优先 |
| `JLCPCB` | `jlcpcb` | 全小写 |
| `Edge ai` / `ai VTuber` / `prompt caching` / `GitHub Trending` | `edge-ai` / `ai-vtuber` / `prompt-caching` / `github-trending` | 禁止空格，改连字符 |

**例外（保留原样）**：专有型号/标准缩写可保留大写——`STM32` `RISC-V` `MCU` `BIM` `CAM` `EDA` `DFM` `MOC` `Home`。
**机器状态标签**（`degraded` `429` `skeleton` `auto-generated` `cron-fallback`）只允许出现在 cron 自动产出里，人工笔记禁用。

## 笔记类型与模板

| 类型 | 模板 | 用途 |
|:---|:---|:---|
| daily | `templates/每日笔记模板.md` | 每日记录/学习日志 |
| research | `templates/研究笔记模板.md` | 研究与竞品分析（结论置顶）|
| concept | 自由 | 知识概念（补 MOC 链接）|

## 命名规则

- 文件：`主题-YYYY-MM-DD.md`（研究类）或 `主题.md`（常青概念）
- MOC：`MOC-<域>.md`（如 MOC-AI / MOC-Dev）
- 避免：空格文件名、中文标点、重复语义标签

## 链接约定

- 每条笔记末尾：`[[所属MOC]] · [[Home|🏠 Home]]`
- 新笔记 → 先想"属于哪个 MOC"→ 加链接
- 每日脚本自动处理：孤立笔记 → 补链；Research 新笔记 → 加入 MOC-Research 索引
