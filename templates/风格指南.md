# 🎨 知识库风格指南（Vault Style Guide）

> 参考 Obsidian 创始人 Steph Ango 的建议制定——一致的风格省下数百次决策。

## 核心原则

1. **大量使用内部链接 `[[]]`**——每条笔记至少 1 个出链 + 被 1 个入链引用（孤立笔记会被每日脚本自动补链到所属 MOC）
2. **用 MOC 组织，少用嵌套文件夹**——`knowledge-map.md` 是总入口，`MOC-*.md` 按域组织
3. **MOC 里的链接必须带一句注解**——`- [[笔记]] — 一句话说清它是什么/为什么在这里`。裸链接只是清单，带注解才是地图（2026-11-07 起：`scripts/enrich_moc_automount.py` 自动补注解，`daily_vault_optimize.py` 新增挂载直接带注解）
4. **日期统一 `YYYY-MM-DD`**——文件名/笔记内日期都用此格式
5. **标签复数 + 小写**——`#research` `#hardware`（不建 `#Researchs` 变体）
6. **frontmatter 必备**：`tags` / `type` / `created`（模板已内置）

## 孤立率双口径（2026-11-07 起）

| 口径 | 范围 | 健康阈值 | 用途 |
|:---|:---|:---|:---|
| **知识域口径** | `knowledge/**` | **0%** | 真正的知识资产健康度，跌破即需处理 |
| **全库口径** | 去掉 `skills/` `.hermes/` `.learnings/` 等第三方与工具产物 | < 3% | 只看自家笔记；memory/ 日志与根目录身份文件天然无出链，属正常 |

> 为什么分两个口径：历史上把 180+ 篇第三方技能包 README/SKILL.md 算进分母，孤立率被稀释成 13%~15%，看着吓人但全是 vendor 文档；真实知识域是 0%。指标必须能指导行动，否则就是噪音。

## 标签归一化规范（2026-11-06 起强制）

> 背景：全库 1264 个唯一标签里有 26 篇笔记用了单复数/大小写/空格变体，检索时同一概念被拆成两个标签。以下为唯一真相表，新建笔记一律用右列写法。

| ❌ 废弃写法 | ✅ 统一写法 | 说明 |
|:---|:---|:---|
| `skill` | `skills` | 复数优先 |
| `project` | `projects` | 复数优先 |
| `tool` | `tools` | 复数优先 |
| `model` | `models` | 复数优先 |
| `benchmark` | `benchmarks` | 复数优先 |
| `research-tool` | `research-tools` | 复数优先 |
| `core-contribution` | `core-contributions` | 复数优先 |
| `ten-round` | `ten-rounds` | 复数优先 |
| `JLCPCB` | `jlcpcb` | 全小写 |
| `Edge ai` / `ai VTuber` / `prompt caching` / `GitHub Trending` | `edge-ai` / `ai-vtuber` / `prompt-caching` / `github-trending` | 禁止空格，改连字符 |

**例外（保留原样）**：专有型号/标准缩写可保留大写——`STM32` `RISC-V` `MCU` `BIM` `CAM` `EDA` `DFM` `MOC` `Home`。
**机器状态标签**（`degraded` `429` `skeleton` `auto-generated` `cron-fallback`）只允许出现在 cron 自动产出里，人工笔记禁用。

## 笔记类型与模板

| 类型 | 模板 | 用途 |
|:---|:---|:---|
| daily | `templates/每日笔记模板.md` | 每日记录/学习日志 |
| research | `templates/研究笔记模板.md` | 研究与竞品分析（结论置顶）|
| concept | 自由 | 知识概念（补 MOC 链接）|

## 命名规则

- 文件：`主题-YYYY-MM-DD.md`（研究类）或 `主题.md`（常青概念）
- MOC：`MOC-<域>.md`（如 MOC-AI / MOC-Dev）
- 避免：空格文件名、中文标点、重复语义标签

## 链接约定

- 每条笔记末尾：`[[所属MOC]] · [[Home|🏠 Home]]`
- 新笔记 → 先想"属于哪个 MOC"→ 加链接
- 每日脚本自动处理：孤立笔记 → 补链；Research 新笔记 → 加入 MOC-Research 索引

## 扫描口径（MOC 挂载范围，2026-11-07 定）

> 背景：日常报出的「孤立 36%」「孤立 12%」是**口径假象**——扫描范围把 `skills/` 第三方技能文档、根目录 meta 文件、`.hermes`/`.learnings` 都算了进去。口径不定，孤立率就永远是个吓人的假数字（2026-11-06 治理审计实测）。

| 范围 | 纳入 MOC / 孤立统计 | 理由 |
|:---|:---|:---|
| `knowledge/**` | ✅ | k 自己的知识产出，唯一该被 MOC 组织的部分 |
| `skills/**`（含第三方技能文档） | ❌ 一律视为**外部资产** | 技能自带 `SKILL.md` 索引；纳入会污染图谱且让孤立率虚高 |
| 根目录 meta（`SOUL.md` / `AGENTS.md` / `USER.md` / `PRIVACY.md` / `HOME.md` / `README.md`） | ❌ | 系统配置与入口文件，不是知识笔记 |
| `.hermes/` `.learnings/` `.dreams/` `private_knowledge/` | ❌ | 工具态 / 私有隔离区，物理上不该进公开图谱 |
| `memory/**` | ⚠️ 只入 `knowledge-map`，**不入域 MOC** | 日志性质，按年月归档即可 |

**对外报数规则**：说「孤立率」时分母必须是 `knowledge/` 的页数（当前 ~720 页），不能用全库 1587 篇——后者把 `skills/` 与 meta 都算进分母，会得出 12% 的假缺陷。
**技能文档要挂 MOC 的例外**：只有 k 自己写的技能方法论（如 `skills/hermes/*-bootstrapping.md`）可作为知识引用被 `knowledge/` 笔记链接，但它本身不进 MOC 索引。
