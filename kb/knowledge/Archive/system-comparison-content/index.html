    「体系对照表」对外发布文案（博客 + 视频双版本）¶

    创作时间：2026-07-31 · 基于体系对照研究（knowledge/Research/github-ai-selfstudy-system.md） 风格：低调务实、用事实说话、不自称第一 发布建议：视频版发 B 站（5-8 分钟），博客版发掘金/CSDN（含对照表全文）

    版本一：博客版（掘金/CSDN）¶

    标题选项¶

    1. 《把微软 18 课和 Datawhale 16 章对照了一遍，发现我早就在用里面的全部知识点》
    2. 《我用 GitHub 上的两门高星 AI 课程，验证了自己的 Agent 体系》
    3. 《70K★ 和 68K★ 的 AI Agent 课程，核心章节我都实践过了》

    推荐 #1 — 有反差感但不夸张，符合低调务实调性

    开头（钩子）¶

    最近 GitHub 上 AI Agent 学习资源热度很高，微软的 AI Agents for Beginners 已经 70K star，Datawhale 的 hello-agents 冲到了 68K star。

    我把自己搭的 Agent 自动化体系，和这两门课逐章对照了一遍。结果有点意外：这两门课讲的核心章节，我的体系里基本都有对应的实践。

    不是炫耀。恰恰相反——这个对照过程本身就是一次很好的体检：它能告诉我，哪些知识点我真的落地了，哪些只是"以为懂了"。

    正文¶

    先说结论¶

    把两门课共 34 章过一遍，我的体系覆盖了其中 8 个核心章节，全部是"已实践"状态：

    课程章节 我的体系对应物 状态
    MS 第 11 课 Agentic Protocols (MCP/A2A/NLWeb) MCP 配置铁律 + 3 个 MCP 服务器 ✅ 已实践
    MS 第 12 课 Context Engineering 跨天会话管理 + 检索干湿分离 ✅ 已实践
    MS 第 13 课 Managing Agentic Memory 记忆价值量化 + 记忆追踪脚本 ✅ 已实践
    Datawhale 第 8 章 记忆与检索 情景→参数化记忆路由 ✅ 已实践
    Datawhale 第 9 章 上下文工程 跨天会话 + 干湿分离 ✅ 已实践
    Datawhale 第 10 章 智能体通信协议 MCP 体系 + 工具集 ✅ 已实践
    Datawhale 第 12 章 智能体性能评估 评估器可靠性自检 ✅ 已实践
    MS 第 15 课 Computer Use Agents (CUA) 状态优先于渲染原则 ✅ 已实践

    8 项对照，全部命中。

    这套体系长什么样¶

    简单说，它是我日常在用的一个 Agent 自动化工作台：

    • 底层：一个能调用工具、跑定时任务、管理多模型的 Agent 框架（开源）
    • 中间层：20+ 条可执行规则，每条都是踩坑后沉淀的
    • 上层：几十个按需加载的技能模块（Skill）

    日常运行它做这些事： - 每天自动抓取 arXiv 论文并生成摘要 - 每周自动跟踪 GitHub Trending 精选项目 - 定时检查系统健康、汇报成本 - 我扔给它一篇文章/一个项目，它研究完能直接落地成规则

    对照过程中的 3 个发现¶

    发现 1：课程在教的东西，正是踩坑换来的 比如"上下文工程"这一章，讲的是 Agent 别把无关信息带进上下文。我的体系里对应的是两条规则——"跨天会话要拆开"和"检索完先提炼再行动"。前者是连续几天不拆会话、上下文被历史撑爆之后总结的；后者是搜索完带着几十 KB 原文继续分析、效果变差之后总结的。 课程把原理讲清楚了，我是拿真金白银的 token 买来的教训。

    发现 2：有一类知识，课程讲得比我做得深 比如 Agentic Memory（记忆管理）这一章，微软讲了完整的记忆分层、检索、遗忘策略。我的体系用的是简化版——按价值评分决定记不记、定期清理。课程让我看到更完整的理论框架，这部分我后续会补。

    发现 3：有一类实践，课程没讲但我在做 比如"评估器可靠性自检"——因为我发现 AI 自己判断"任务做完了"经常误报，所以定了一条规则：任何自动化评估先测误判率，关键决策留 10% 人工抽检。这类 Agent 工程里的脏活，课程很少提。

    这套对照方法，你也可以做¶

    1. 找两门高星课程（不必是最热门的，适合自己方向即可）
    2. 把目录列出来
    3. 逐章问自己：这个知识点，我有没有对应的实践？不是"看过"，是有产出的实践
    4. 命中 → 知道自己不是纸上谈兵；没命中 → 要么补课，要么明确暂不需要

    判断标准就一条：有没有对应的产出物。 规则、脚本、配置、文档，都算。只有"看过/知道"不算。

    结尾¶

    两门课都是很好的资源，star 不是刷的——微软的课程质量确实稳，Datawhale 的中文教程对国内学习者非常友好。

    这个对照不是为了证明什么，而是提供一个思路：别把收藏当学习，别把"看过"当"会了"。 拿你的实际体系去对照课程目录，10 分钟就能看出自己真正掌握的和只是"以为知道"的。

    如果这个思路对你有用，欢迎交流。

    对照过程有三个发现，比"我全都会"更有价值：

    第二，有些课讲得比我深。记忆管理那章，微软讲了完整的分层和遗忘策略，我用的还是简化版，这个我承认要补。

    第三，有些坑课程不讲。比如评估器自检——AI 自己判断"干完了"经常误报，我被迫加了人工抽检。这类工程里的脏活，课程很少讲。
