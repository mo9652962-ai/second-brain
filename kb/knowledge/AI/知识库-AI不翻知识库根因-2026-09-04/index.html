    知识库研究：「AI 为什么根本不会去翻你建的知识库」— 一只桌子¶

    来源：抖音视频 @一只桌子（2026-09-04 学习研究任务） 视频：https://v.douyin.com/vMDN7AqOOQU/ · ID 7668907787153313060 关联：我们自己的知识库体系（knowledge 篇数 + skills 数量 + MEMORY/USER）——数量以 [[knowledge/META/knowledge-sources]] 为准

    一、视频核心观点（标题全文）¶

    「你建的知识库，AI 为什么根本不会去翻？我的库一个多月长到 130 多页，翻它写它的都是 AI，我一次都没手动翻过。大部分人卡在同一步：资料塞进去了，AI 就是不动——因为差的不是资料，是最上面那层规则。」

    一句话提炼：资料（知识库内容）不是问题，最上面那层规则（告诉 AI「什么时候、怎么去翻知识库」的指令层）才是问题。作者用了 #codex 标签——他的知识库是被 AI 自动维护（翻它写它的都是 AI），但能触发 AI 去翻的关键是最顶层的规则文件（AGENTS.md 类）。

    二、多源研究验证（k 独立搜索交叉验证）¶

    为什么 AI 不翻知识库（业界共识）¶

    根因 说明 来源
    没有触发规则 Agent 不知道「遇到任务先搜知识库」——知识库存在但不主动连接 agent-memory-wiki、JitAi
    RAG 链路问题 切片/召回/重排任一环坏 → 答非所问，模型选择不依赖知识库 火山引擎、00011000.com
    规则 vs 记忆混淆 把「必须遵守的规则」放进自动记忆 = 它只是建议不是约束 Jimyag、Claude/Codex 文档
    臃肿的规则文件 600 行 CLAUDE.md ≈ 没有规则，模型选择性忽略 tianpan.co
    工具暴露 知识库模式设为「智能/禁用」时 Agent 可能感知不到查询工具 JitAi

    正确分层（多源一致的结论）¶

    规则层（AGENTS.md / CLAUDE.md）  ← 必须遵守，版本化、可 review、进 git
    ↓ 告诉 Agent「什么时候去翻」
知识层（knowledge/、memory/）    ← 可搜索的事实/经验，按需召回
    ↓ 告诉 Agent「翻到什么」
技能层（skills/）                ← 可复用流程，渐进式披露（只加载触发到的）

    关键区分（Claude Code / Codex / ADK 文档共识）： - AGENTS.md = 项目规则 → 每次会话加载，进 git，团队共同维护 - memory/ = 本地召回层 → 辅助，不能成为唯一事实源 - RAG ≠ Agent Memory：RAG 解决「从外部知识库找资料」，Agent Memory 解决「过去发生过什么、哪些状态要延续」 - Periodic Nudge 优于规则列表：外部时钟强制触发 > 依赖 Agent 主动性（agent-memory-wiki 实证）

    立即落地动作（3 项）¶

    1. 核查顶层规则：.codex/AGENTS.md / 项目 AGENTS.md / SOUL.md 是否明确写了「接手任务先查知识库/技能，不要凭空发挥」——视频的核心就是这一条
    2. 写触发规则：在全局 AGENTS.md 加一段「知识库优先」规则： ```markdown ## 知识库优先规则
    3. 遇到任何领域任务 → 先查 knowledge/ 或 skills/ 再行动
    4. 项目任务 → 先读项目 AGENTS.md
    5. 解决完新问题 → 沉淀回知识库/技能（learn→research→apply） ```
    6. 区分规则与记忆：MEMORY.md 里的「必须遵守」类条目如果只是建议性的，应上移为规则文件；动态经验留在记忆层

    5.1 为什么 AI 不翻知识库（业界根因共识）¶

    # 根因 说明 来源
    1 顶层规则缺失 AGENTS.md 才是「操作系统」——决定 Agent 是随手写总结的聊天机器人还是有纪律的维护者。差的不是资料是最上面那层规则 Diors LLM Wiki
    2 RAG 检索链路错 切片/召回/重排/查询改写任一环错 → 答非所问 → 模型放弃用知识库。5 个检索配置错误（切片太长/太短、召回数量错、没重排、范围未过滤、提示词无约束） 火山引擎
    3 没有触发机制 知识「存在但不会主动连接」——缺外部时钟/Periodic Nudge 强制触发，只靠 Agent 自觉 agent-memory-wiki
    4 规则与记忆混淆 AGENTS.md=规则层（版本化、进 git）；memory=召回层（辅助）。把规则放自动记忆=只是建议不是约束 Jimyag / Codex 文档
    5 文件太胖 600 行规则 ≈ 没有规则。32 KiB 上限，全局塞 28KiB 风格指南会把项目级指令挤掉（静默失败不报错） codegateway / ckhuang

    5.2 AGENTS.md 最佳实践（多源一致）¶

    • 三层级：~/.codex/AGENTS.md（全局偏好）→ 仓库根 AGENTS.md（项目规则）→ 子目录 AGENTS.override.md（局部覆盖，越近 cwd 优先级越高）
    • 最小规则表（8-10 模块）：Role / Principles / Directory Rules / Naming Rules / Page Templates / Ingest Workflow / Query Workflow / Lint Workflow / Conflict Handling / Reporting
    • 写什么：Codex 容易猜错的规则、代码里读不出来的约定、必须遵守的规范、技术栈版本/常用命令/项目坑点
    • 不写什么：整本设计文档（放 docs/ 给链接）、频繁变化的临时任务、无关长篇叙述、代码一眼能读出来的事实
    • 验证方法：codex exec "List active instruction sources" 让 Codex 复述当前加载的规则；模糊=文件不够明确
    • 维护哲学：「同类错误犯两次 → 写进 AGENTS.md」；不是愿望清单，是经验压缩包

    5.3 RAG 检索配置 5 大错误（火山引擎官方，2026）¶

    1. 切片太长（一个片段多主题）或太短（句子被拆开）→ 按标题/段落切 + 10-20% 重叠 + 元数据
    2. 召回数量拍脑袋 → 放宽 Top 20-50 交重排收窄 3-5 条 + 相似度下限
    3. 没有重排（Rerank）→ 向量相似 ≠ 能回答问题，加 Cross-Encoder
    4. 检索范围未过滤 → 按产品/版本/标签先过滤再做语义匹配
    5. 提示词没限制依据 → 明确「只根据知识库回答，找不到直说资料不足」
