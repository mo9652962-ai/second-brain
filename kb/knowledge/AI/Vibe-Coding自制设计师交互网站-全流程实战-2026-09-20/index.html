    Vibe Coding 自制高交互设计师个人网站：全流程实战与工程化拆解¶

    来源：抖音视频深度研读（作者：表哥懂设计 · 时长 10分44秒 · 视频 ID: 7686472712511950114） 研读整理：k · 2026-09-20 · SenseVoice-Small 逐字转写 + 工具链验证 + 工程落地提炼

    结论置顶¶

    这是一套将「AI 生图/生视频 + 交互动效组件库 + Codex/AI 编程 + 轻量 CMS 后台 + 一键部署」彻底串联的 Vibe Coding 标准交付 SOP。 1. 破除开盲盒的核心秘诀：绝不对 AI 说“帮我做个高级感网站”，而是采用 五段骨架清单 + 样式参考图 (Style Ref) + React Bits 交互动效库。 2. 3D 鼠标跟随与跨屏动画闭环：通过生图锁死一致性（只变视角，锁死服饰/背景/五官），生成“首尾帧闭环”的视角视频，再通过前端监听 mousemove 与 wheel 实现沉浸式追视与无缝滚屏。 3. 工程交付完整性：不止交付静态前台，最后一步直接让 AI 挂载轻量 CMS 管理后台（作品增删改查/排序），实现真实商业交付标准。 4. 对 sora 变现与接单的赋能：可直接打包为闲鱼「个人作品集 / 独立开发者主页」高客单服务（标价 300~800 元），交付周期由 2 天压缩至 2 小时。

    二、高交互个人网站的五段骨架¶

    绝大多数新手做 Vibe Coding 失败的原因，是上来就让 AI 全权自由发挥。必须先给出清晰的功能框架：

    ┌─────────────────────────────────────────────────────────────┐
│ 1. 头图封面 (Hero Section)                                  │
│    - 核心视觉：3D 人物鼠标追视 (Mouse-tracking LookAt)     │
│    - 交互：平滑水波扩散、轻微鼠标拖尾粒子                    │
├─────────────────────────────────────────────────────────────┤
│ 2. 个人履历 (About / Experience)                            │
│    - 滚动过渡：首屏人物下落/转身自然衔接到关于页           │
│    - 经历时间线卡片 + 技能标签云                            │
├─────────────────────────────────────────────────────────────┤
│ 3. 作品目录 (Portfolio Categories)                          │
│    - 点击展开文件夹式动效 (Folder Expand)                   │
│    - 展开后非主体适度虚化，ESC / 关闭按钮收起               │
├─────────────────────────────────────────────────────────────┤
│ 4. 项目展示详情 (Project Showcase / Grid)                   │
│    - 瀑布流 / 响应式卡片网格，消除白边保持全宽铺满          │
│    - 点击弹出 Case Study 浮层或独立路由预览                │
├─────────────────────────────────────────────────────────────┤
│ 5. 结尾页脚与联系方式 (Footer / Contact)                     │
│    - 人物坠落/挥手致意动画闭环                              │
│    - 社交链接、邮件点击复制、版权标识                       │
└─────────────────────────────────────────────────────────────┘

    三、实战避坑与工程核心细节（极高价值经验）¶

    1. 角色一致性控制（避免“变脸”与“跳帧”）¶

    • 提示词负向与正向锚定：在生成上下左右等不同朝向时，必须显式约束： 保持相同人物主体，面部特征、发型发色、服装款式与材质、画面构图比例、整体光影绝对不变，仅改变头部朝向与眼球视线。
    • 背景跳动问题：必须单独生成或提取一张纯净背景图，并在生视频工具中指定所有镜头共用固定静态背景。

    2. 3D 鼠标跟随视线闭环（Mouse-tracking Loop）¶

    • 致命痛点：如果视角视频只转了一圈没回到正面，当鼠标从右下方切回正上方时，画面会出现突兀的硬切（Cut）。
    • 解法：视频必须渲染为一个完整的环形循环（正面 $\to$ 向上 $\to$ 向右 $\to$ 向下 $\to$ 向左 $\to$ 回到正面）。在前端根据鼠标相对屏幕中心的极坐标角度 $(\theta, r)$ 映射到视频对应的帧播放时间 video.currentTime。

    3. 页面滚动与动效状态解耦（State Machine Transition）¶

    • 实测 Bug：当用户滚轮离开首屏进入个人履历页时，人物依然在被鼠标强制拉扯视角，导致进入下一段过场动画时姿态崩坏。
    • 修复指令：

      “当滚轮触发 wheel 离开首屏视口（ScrollY > Threshold）后，立刻注销鼠标视线监听事件，将人物表情与姿态平滑过渡回初始待机状态，再触发后续下落过渡动画。”

    4. “小步慢跑”的 AI 迭代修改原则（SRP 修改法）¶

    • 反模式：一次性向 AI 提出 5 个修改意见（“水波改小点、卡片放大、字体换掉、加个按钮、背景变黑”），AI 极容易改崩已满意的部分。
    • 最佳实践：一次只集中修改一类问题。
    • 第一轮：纯修排版与尺寸（如作品卡片图片出现上下白边 $\to$ 调整 object-fit: cover 与网格间距）；
    • 第二轮：纯修交互逻辑（鼠标悬停展开 $\to$ 改为点击展开，并支持 ESC 退出）；
    • 第三轮：纯修视觉细节（水波纹范围缩小、去掉黑色拖尾）。

    5. 后台管理系统（从“玩具页面”到“交付级产品”）¶

    • 在当前项目上下文直接派活：

      “在现有前台基础上，编写一个轻量的数据管理后台（/admin）。允许我可视化上传新作品（标题、封面图、分类标签、项目链接），支持拖拽调整前端展示顺序，数据保存在本地 LocalStorage / JSON 文件中，前台展示实时同步响应。”

    • 彻底解决了“客户后续要加作品只能找程序员重新改代码”的痛点。
