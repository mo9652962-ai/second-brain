    接口三件套：攻防一体（程序员Orion · 抖音 2026-08-21）¶

    来源：抖音 @程序员Orion（创业中）《学校不教的接口防傻瓜指南：重复请求、异常参数怎么稳...》（1:05） 转写 375 字（SenseVoice） 攻防一体：写接口 = 交付质量；挖漏洞 = 找三件套缺失

    核心认知¶

    学校写接口：不报错 = 成功。商业项目：接口是写给全世界乱用你的人看的

    用户会：抓包篡改参数 / 重复点击按钮 / 脚本疯狂刷接口 → 库存扣光 / 订单重复生成 / 支付异常 / 服务打爆

    商业级后端三大保命技巧¶

    ① 参数校验¶

    在接口入口就把非法参数丢掉，不让垃圾请求进来

    # ❌ 不校验
@app.post("/api/order")
def order():
    data = request.json
    price = data["price"]        # 用户传 0.01 怎么办?
    create_order(price)

# ✅ 入口校验
from pydantic import BaseModel, Field
class OrderIn(BaseModel):
    product_id: int = Field(gt=0)
    quantity: int = Field(gt=0, le=99)
    price: float = Field(gt=0)   # 服务端定价，不信前端

    ② 幂等处理¶

    同一个请求只处理一次，重复来直接返回结果

    # ❌ 重复点击 → 重复下单
@app.post("/api/pay")
def pay():
    deduct(user_id, amount)

# ✅ 幂等键：同一个 idempotency_key 只处理一次
@app.post("/api/pay")
def pay():
    key = request.headers.get("X-Idempotency-Key")
    if redis.exists(f"idem:{user_id}:{key}"):
        return cached_result          # 重复请求直接返回
    result = deduct(user_id, amount)
    redis.set(f"idem:{user_id}:{key}", result, ex=3600)
    return result

    ③ 请求限流¶

    用户疯狂点击也不能把数据库打爆

    # 简单版：固定窗口计数（Redis）
def rate_limit(user_id, limit=30, window=60):
    count = redis.incr(f"rl:{user_id}:{int(time()//window)}")
    redis.expire(f"rl:{user_id}:{int(time()//window)}", window)
    return count <= limit

    攻防对照表（同一件事两个视角）¶

    防守（写接口） 攻击（挖洞） 真实漏洞案例
    参数校验缺失 越权/注入/异常参数 改 user_id 看别人数据 / 改 price 0 元下单
    幂等缺失 重复下单/库存漏洞 并发点 2 次 → 双倍到账
    限流缺失 刷接口/薅羊毛 验证码轰炸 / 短信接口被刷 / 批量遍历 ID

    SRC 验证三连（挖洞时对照）¶

    看到「下单/支付/改密/领取」接口 → 依次测:
① 参数: 篡改 user_id/amount/status → 越权/改价?
② 幂等: 同一请求并发 2-3 次 → 重复下单/重复领取?
③ 限流: 连发 30+ 次 → 有风控吗? (无 = 验证码可刷/批量接口)
