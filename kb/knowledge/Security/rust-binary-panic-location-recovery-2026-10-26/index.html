    一、现代 Rust 逆向工程的三大核心痛点¶

    1. 符号完全剥离（Stripped Binary）： Rust 默认编译输出静态单体二进制，release 模式剥离符号后，没有符号表、没有类型导出，反编译器中充斥着成千上万个 FUN_xxx。
    2. 字符串切片无 \0 终结符（&str Fat Pointer）： Rust 字符串在 .rdata 中连续密集拼贴，反编译器的 ASCII/Unicode 扫描器由于找不到 \0，会将其合并为几十 KB 的单一大字符串块，无法进行上下文线索切分。
    3. 传统工具对未开启 cargo-auditable 的二进制完全失明： REA 的 inspect-rust-binary 仅解析 .dep-v0 段。一旦开发者（如 ripgrep 官方发布版）未配置 cargo-auditable，REA 直接报告： "No .dep-v0 section was found. Package count: 0"。

    二、技术突破原理：逆向扫描 core::panic::Location¶

    2.1 结构体内存布局¶

    Rust 标准库在触发 panic!、unwrap()、expect()、越界检查（bounds check）时，会自动传递其源码发生点。该信息由 core::panic::Location 结构体承载：

    pub struct Location<'a> {
    file: &'a str, // ptr (8 字节), len (8 字节)
    line: u32,     // 4 字节
    col:  u32,     // 4 字节
}

    在 x86_64 PE/ELF 的只读数据段（.rdata / .rodata）中，该结构体以 24 字节连续紧凑排布（8 字节对齐）： - Offset 0x00: ptr（指向 UTF-8 文件路径字符串的绝对虚拟地址 VA） - Offset 0x08: len（文件路径字符串字节长度） - Offset 0x10: line（32 位无符号整数，源码行号） - Offset 0x14: col（32 位无符号整数，源码列号）

    2.2 依赖库与版本逆向提取启发式¶

    在 Cargo 构建体系中，依赖库的源码路径具有确定性特征： - 注册表缓存路径形如：...\.cargo\registry\src\...\<crate-name>-<version>\src\... - 工作区模块路径形如：crates\<crate>\src\... 或 src\...

    通过正则引擎精确捕获 <crate-name>-<version>，即可完全无视 .dep-v0 是否存在，100% 确定性逆向还原二进制中引入的第三方依赖包名称及其具体语义化版本号！

    三、工程实现与工具套件¶

    3.1 rust-recover.exe（自建原生分析器，2.3MB）¶

    源码位置：D:\tools\rea\rustrecover\main.go - 纯原生 PE 解析，零第三方运行时依赖，秒级扫描。 - 支持三模输出： - 人类可读终端报告（含 Crate 命中频次榜、编译器 commit 链接、源码文件组织树）。 - -json：供下游 Agent / CI 机器读取的结构化契约。 - -tsv：纯坐标数据流（VA \t File \t Line \t Col），专供 Ghidra 批处理消费。

    3.2 ApplyRustPanicLocations.java（Ghidra 批处理脚本）¶

    源码位置：D:\tools\ghidra_scripts\ApplyRustPanicLocations.java - 对每个 Location VA 打上 panic_loc_N 符号标签。 - 注入 Plate Comment：Rust Panic Location: <file>:<line>:<col>。 - 自动追踪代码对该 Location 的交叉引用（XREFs），在触发 panic 的汇编处设置 EOL 注释，并将源文件坐标注入所属函数的函数说明。

    3.3 apply-rust-binary.sh（一键工作流）¶

    源码位置：D:\tools\rea\apply-rust-binary.sh - 采用 -noanalysis 模式运行 Ghidra Headless，将 4.1MB 巨型二进制的回填时间从 15+ 分钟超时缩减至 10~14 秒！ - 自动化生成持久化项目、JSON 报告、TSV 坐标表与已回填符号清单。

    4.3 未知项（边界）¶

    • 未知：若使用 nightly 编译器参数 -Zlocation-detail=none，Rust 会强制把文件名与行号擦除为 <redacted>:0:0，此时无法还原具体文件行号，仅能感知其存在 panic 桩。
