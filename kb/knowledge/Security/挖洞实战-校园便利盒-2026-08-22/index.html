    校园便利盒小程序挖洞实战报告¶

    目标：github.com/Joho6666/xiaoyuanbianlihe（微信云开发校园社区） 时间：2026-08-22 | 方法：小程序云函数专项方法论（src-bug-hunting 技能） 结果：4 个漏洞确认（高危×1 配置依赖 / 中危×2 / 低危×1）+ 12 项安全项验证通过

    一、漏洞清单¶

    🔴 [HIGH-配置依赖] 运营后台公开暴露 + 直连数据库写¶

    项 内容
    位置 hosting/admin.html（云开发静态托管，公开可访问）+ 1332 行「写操作将直连数据库」
    问题 管理后台托管在公开 hosting；CONFIG.ADMIN_WEB_SECRET 为空时后台降级为Web SDK 直连数据库写（db.collection('posts').update() 等）
    危害 若数据库权限规则宽松（read:true write:true）→ 任何人打开后台 URL 即可删帖/改角色/改公告；规则严格则此路径失效（依赖配置）
    验证 代码 1214/1243/1691 行确认直连写操作存在；实际利用取决于控制台数据库规则
    修复 ① hosting 关闭或加访问鉴权（CloudBase 安全域名/自定义登录态）② secret 为空时禁止降级直连（fail-closed）③ 数据库规则最小化（所有集合拒绝客户端直写，仅云函数操作）

    🟡 [MEDIUM] searchUsers / getUserInfo 敏感信息泄露（用户枚举）¶

    项 内容
    位置 dbOperations/index.js:1910（searchUsers）/ :1730（getUserInfo）
    问题 return { code: 0, data: res.data } / {...user} —— 返回完整用户对象（含 _openid/numericId/全部档案），无字段过滤
    危害 ① 推荐用户接口 limit(20) 循环调用 → 批量枚举全量活跃用户 openid ② 任意 openid 可拉完整档案 → 精准画像/社工/隐私违规（微信审核要求收集最小化）③ openid 泄露可配合其他接口
    攻击链 searchUsers('') 循环 → 收集 openid → getUserInfo(targetOpenid) → 全量用户数据
    修复 接口返回白名单字段（nickName/avatarUrl/college/numericId/...），永不返回 _openid/phone/studentId；仅作者本人可看自己的 openid

    🟡 [MEDIUM] getTempFileUrls 任意文件临时 URL 获取（越权读）¶

    项 内容
    位置 dbOperations/index.js:475-489
    问题 只要登录（OPENID 存在）即可传任意 cloud:// fileID 换取临时访问 URL——无文件归属校验
    危害 已知 fileID 即可读取云存储任意文件（含他人私密图片/语音）；fileID 不可枚举但可从分享/错误回显/日志泄露面获得
    修复 校验文件归属：fileID 必须在当前用户可访问范围内（消息收发双方/自己的上传记录）；或改用云调用 getTempFileURL 仅服务端场景

    🟢 [LOW] 前端硬编码云环境 ID¶

    项 内容
    位置 miniprogram/app.js:22 CLOUD_ENV_ID = 'xyblh-5gb26qrnf9d30feb'
    问题 真实部署环境 ID 提交进公开仓库
    危害 定向攻击该环境（配合其他洞）；信息收集辅助
    修复 envId 从 project.config.json/环境读取，不入库；检查 git history 移除

    二、安全项验证通过（做得好的地方）¶

    检查点 结果
    login 云函数 ✅ OPENID 全部来自 getWXContext()，无前端传参信任
    硬编码管理员 openid ✅ 无（CN-SEC 案例通病，本项目没有）
    session_key 泄露 ✅ 无 session_key 逻辑（未用 getPhoneNumber）
    对象级授权（帖子/商品） ✅ updatePost/deletePost/deleteMarketGoods 均检查 _openid !== openid
    管理操作鉴权 ✅ toggleTopPost/banUser/createAnnouncement 均 checkAdmin
    消息会话越权 ✅ getMessages 查询条件强制包含自己的 openid
    资料修改 ✅ updateProfile 白名单字段，无法改 role/status
    删号 ✅ deleteAccount 用 openid 定位自己
    Web 后台密钥 ✅ ADMIN_WEB_SECRET 环境变量校验 + admin.html 无硬编码（空值）
    匿名帖 ✅ sanitizePostsForClient 清洗 _openid（仅作者可见）
    邀请/绑定 ✅ userReferral 防自邀 + 条件更新防覆盖
    频率限制 ✅ checkRateLimit + 内容安全审核（wxTextCheck/wxImageCheck）

    三、方法论验证¶

    本次练手完整走通了「小程序云函数专项」挖洞流程：

    ① 解包/源码获取 → git clone（免解包，开源项目）
② 云函数清单盘点 → 7 个云函数 + dbOperations(3467行) 大而全
③ 权限模型分析 → getWXContext 身份链 ✅ / webSecret 双因子 ✅
④ 对象级授权检查 → 逐 action 查作者/参与者校验
⑤ 信息泄露面 → searchUsers/getUserInfo 未脱敏 ← 真实漏洞
⑥ 文件/存储面 → getTempFileUrls 无归属校验 ← 真实漏洞
⑦ 配置面 → hosting 公开 + 直连数据库降级 ← 高危配置依赖

    结论：该社区项目安全意识前 20%（身份验证框架完整），但犯了两个典型错误：接口返回未脱敏 + 管理后台过度暴露——正是 SRC 里最常见的两族洞（敏感信息泄露 / 配置缺陷）。
