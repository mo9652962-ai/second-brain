    NOIR — 用 adb 把「这台手机到底能泄露什么」变成可复现报告¶

    W45 精选（新面孔）。3,007★ / 48 commits / 3 contributors / v0.4.2（2026-11-07）/ MIT / Kotlin，8 天建仓。Trendshift 当周 Privacy / Android / CLI 三个分类的 #1 riser（作者自挂 badge，属自述）。 定位写得很清楚：审计与自我防护，面向自己的设备、自己的应用、已授权的安全研究。

    一句话定位¶

    跑在电脑上的 CLI：通过 adb 读已连接 Android 设备的应用清单、权限、APK 里的网络端点 → 分类打分 → 给出「哪类数据可能流向哪里」→ 处置建议每条带回滚命令。不联网、不上传、不需要账号、不需要 root、默认不卸载任何东西。

    它做的 8 件事¶

    1. 盘点：列出所有「有网络权限 + 敏感权限」的应用及各自拿到什么
    2. 抽端点：在设备端用 unzip + strings 从 dex 里提 URL，只回传几 KB——不把整包拉回电脑（省带宽 + 少碰数据）
    3. 分类打分：按包名/域名识别厂商（小米/Google/腾讯/高德…）与类别（遥测/广告/定位/输入法…），结合权限与上报端点算风险分
    4. 数据关联：把权限翻译成「能拿到什么」（位置/通讯录/短信/通话/麦克风/相机/屏幕/应用列表/设备标识/文件/日历/账号），再和上报域名配对 → 「哪类数据可能流向哪里」
    5. 共享 UID：识别 android.uid.system 这类共享用户，列出哪些包实际共享同一套权限并集
    6. 清单层：解析二进制 AXML AndroidManifest.xml，找无权限保护的导出组件、明文流量、备份、debuggable、targetSdk
    7. 给建议：分「可安全自动执行 / 需人工确认 / 不建议动」三档，每条生成回滚命令
    8. 深挖（可选）：deep 拉 base + split APK，用 jadx 反编译后检索 Runtime.getRuntime().exec、setApplicationEnabledSetting、DexClassLoader、MediaProjection 等高风险调用

    明确不做什么（这条最值得学）¶

    • 不联网、不上传任何数据、不需要账号
    • 不修改系统分区、不需要 root
    • 默认不卸载；只有 noir deepscan --purge 会逐个确认卸载高风险用户应用
    • 全程只问两三个 y/n，其余自动；处置前先写好回滚文件

    上手路径（sora 本机可跑）¶

    noir            # 向导：查 adb（没有就问要不要自动下到 ~/.noir/tools）→ 查设备（没有就打印开发者模式步骤，等 180 秒）→ 开始扫描 → 出仪表盘 → 问是否处置
noir doctor     # 环境自检：平台 / java / adb / 设备
    • 本机 adb 在 C:\Users\31954\platform-tools，iQOO V2352A 已连过——前置条件已满足
    • 注意：锁屏状态下 adb shell 会卡（本机已知坑），跑之前先解锁亮屏

    💎 可借鉴点¶

    借鉴 映射 落地动作
    「权限 × 端点」二维打分 比单看权限列表有信息量得多 以后评估任何 app/工具的数据风险，都问两句：它要什么权限？它往哪发？
    设备端处理、只回传结论 隐私友好的默认架构 处理 sora 私人数据（考研规划、接单记录）时，本机算完只输出结论，不上传原文
    每条处置带回滚命令 可逆操作原则 任何「禁用/删除/改配置」的建议，必须附回滚步骤，否则不给建议
    三档处置（可自动/需确认/不建议） 与 Hermes L0-L4 验证等级同构 沿用：低风险自动、中风险确认、高风险只报告不动手
    只问两三个 y/n 低摩擦交互 长流程里把提问压到最少，其余给默认值
    自证式 CLI（doctor 命令） 装完先自检 新工具接入前跑一次环境自检，别在坏环境里debug业务

    与本机的实际关系¶

    • 可直接用：审 iQOO 上装了哪些会外发数据的应用，尤其关注「输入法 / 清理大师 / 免费 VPN」这类高权限 + 多上报端点的组合
    • 注意边界：只审自己的设备；不碰真实用户凭据；不做躲检测；--purge 前必须逐项确认
    • 未知：3 人小团队、8 天 3k star，长期维护存疑；v0.4.x 属早期版本，报告准确性未独立验证——结论当线索，不当定论

    评价¶

    维度 判断
    技术含金量 ★★★★☆（AXML 解析 + 共享 UID + 端点抽取，工程扎实；jadx 深挖是加分项）
    可复用性 ★★★★★（本机 adb 现成，装上就能跑）
    风险 早期版本、小团队；误判可能导致误禁应用（有回滚兜底）
    建议 试跑一次（只读扫描，不做处置），看报告质量再决定是否常备
