    运动曲线（Easing）：动效丝滑的关键¶

    来源：抖音「设计师PPM：动效丝滑的关键就是要懂运动曲线！#UI设计」（登录墙只拿到标题，主题由 5+ 源搜索引擎研究补齐） 数据截止：2026-09-05

    核心结论（置顶）¶

    1. 写动效最容易翻车的不是时长，是曲线——同一个 200ms 位移，linear 像 PPT、ease 像网页、emphasized 像 Material App、spring 像 iOS。曲线选对 = 动效档次对。
    2. 进入用 decelerate（ease-out），退出用 accelerate（ease-in），退出永远比进入快 20-30%（Material/Apple 共识）。用户对「消失」的容忍度低于「出现」。
    3. 曲线错了调 duration 没用——「在沉船甲板上重新摆椅子」。正确曲线的 250ms 就是对的感觉，错误曲线的 250ms 怎么调都别扭。
    4. ease-in-out 是对称的，多数 UI 动效不该用它——它让动画感觉比实际时长更久。入场/离场需要的是不对称曲线（前段平后段弯 / 前段弯后段平）。

    一、CSS 五大关键字（基线）¶

    关键字 cubic-bezier 直觉 用途
    linear 0,0,1,1 机械 只留给无限循环/进度条
    ease 0.25,0.1,0.25,1 浏览器默认（1996 IE 引入），「网页味」 什么都不写时跑它
    ease-in 0.42,0,1,1 加速离开 出场
    ease-out 0,0,0.58,1 减速落地 进场
    ease-in-out 0.42,0,0.58,1 两端慢中间快 屏内移动（少用）

    注意：ease 不对称（加速比减速猛），多数团队以为它温和，实际更接近 ease-out；ease-in 把 P2 钉右上角所以末段是直线，ease-out 把 P1 钉左下角所以前段是直线。

    二、Material 3 官方四曲线（standard/emphasized × decelerate/accelerate）¶

    :root {
  /* 主导动效：页面切换、抽屉、Sheet */
  --ease-emphasized:            cubic-bezier(0.2, 0, 0, 1);
  --ease-emphasized-decelerate: cubic-bezier(0.05, 0.7, 0.1, 1);  /* 进场 */
  --ease-emphasized-accelerate: cubic-bezier(0.3, 0, 0.8, 0.15);  /* 出场 */

  /* 次要动效：按钮、芯片 */
  --ease-standard:            cubic-bezier(0.2, 0, 0, 1);
  --ease-standard-decelerate: cubic-bezier(0, 0, 0, 1);  /* 进场 */
  --ease-standard-accelerate: cubic-bezier(0.3, 0, 1, 1);  /* 出场 */
}
    • emphasized 前 20% 时间走 80% 距离——感知「利落」：用户 0.1s 看到位置变了，0.3s 收尾让眼睛跟上。Pixel/Gmail Web 视觉签名；只用于主导界面变化，hover 别用（过猛）
    • Material 2 旧 standard = 0.4, 0, 0.2, 1（曾被复制最多，但官方指引：入场 decelerate、离场 accelerate，standard 只给「既不入场也不离场」的过渡）

    三、iOS 弹簧近似（CSS）¶

    :root {
  --ease-ios-spring: cubic-bezier(0.5, 1.5, 0.5, -0.3);  /* 轻回弹：按钮按压释放 */
  --ease-ios:        cubic-bezier(0.25, 0.46, 0.45, 0.94);  /* 标准减速：通用过渡 */
}
    • iOS 13+ 系统动效基本全是弹簧（UISpringTimingParameters），不是贝塞尔；CSS 无原生弹簧（提案草案）只能近似
    • 弹簧 y 值出 [0,1]——元素必须留过冲空间（缩放 0.95→1 允许过冲到 1.05）

    四、弹性/回弹曲线（overshoot）——标点不是字¶

    --ease-overshoot:  cubic-bezier(0.68, -0.5, 0.27, 1.5);  /* 起步后退+终点回弹 */
--ease-anticipate: cubic-bezier(0.36, 0, 0.66, -0.5);    /* 仅起步前退一下 */
--ease-out-back:   cubic-bezier(0.18, 0.89, 0.32, 1.28);  /* Ant 结束回动 */
    • 适合「成功反馈」（加购/收藏/勾选）的啵叽感；每页 1-2 个弹性元素封顶
    • 禁用：高频触发（hover）、进出场动画、modal 入场（稳定减速更高级）
    • 弹性 y 出界 → 必须配 prefers-reduced-motion 降级（前庭敏感用户会眩晕）

    六、时长-曲线对照表¶

    场景 时长 曲线
    按钮 hover 颜色 100-150ms standard
    卡片轻微抬起 150-200ms standard-decelerate
    抽屉/Sheet 滑入 250-300ms emphasized-decelerate
    抽屉/Sheet 滑出 200-250ms emphasized-accelerate
    页面切换（Web） 200-280ms emphasized
    弹性反馈（点赞/收藏） 350-450ms overshoot
    • 超过 500ms 一般是动画失败（不是曲线问题，是时长太长）
    • 退出比进入快 20-30%

    七、技术实现补充¶

    • 三次贝塞尔 = 四个控制点 (x1,y1,x2,y2)，P0=(0,0) P3=(1,1)
    • 浏览器解 x(t)=X 求 t：Newton 迭代 8 次 + 二分 20 次兜底（Blink/WebKit/Gecko 同款），rAF 里稳 60fps
    • Lottie/After Effects：每个 keyframe 带 o（out 切线）/i（in 切线），标量属性可直接往返成 cubic-bezier(o.x, o.y, i.x, i.y)；矢量属性每轴独立曲线
    • 性能：只动画 transform/opacity（不触发重排）；JS 手动算曲线只用于 Canvas/WebGL

    八、对 sora 的落地（已应用）¶

    1. apple-design-web 技能 v2.1 新增「4b 运动曲线」章节——CSS 关键字表、M3 四曲线、iOS 近似、弹性曲线、Ant 库、时长对照、选择三原则
    2. 墨题/接单 PPT 落地参考：抽屉滑入 emphasized-decelerate 250ms、按钮 hover standard 100-150ms、点赞反馈 overshoot 350-450ms
    3. 配合既有 apple-design-web 弹簧参数体系（物理驱动 > 时间驱动）——曲线是「时间驱动」的最优解，弹簧是「物理驱动」的完全体，两者互补不冲突

    落地条件与触发器¶

    • 落地条件：下次做墨题前端动效或 PPT 交互稿时，按 4b 曲线表选曲线
    • 触发器：用户说「动效丝滑/过渡不自然/像 PPT」→ 先查曲线再调 duration
