    抖音学习研究：做控件如何让 AI 工具完全能听懂（AI-native 组件库）¶

    来源：抖音 @AI樟榆树《AI开发项目做控件如何让ai工具完全能听懂 200...》https://v.douyin.com/YKCgVDyKOa0/ 研究日期：2026-08-30 · 方法：千轮搜索（短链被劫持无法抓取视频本体，用标题关键词深挖主题） 关联：agent少返工-ContextEngineering（组件文档 = 给 AI 的上下文）

    视频核心¶

    "做控件如何让 AI 工具完全能听懂"——让 AI 编程工具（Cursor/Codex/Claude Code/Antigravity）在使用你的组件库时不出错、不猜错、少返工。核心不是写文档，而是把组件库本身做成 AI 原生可读（AI-native / LLM-readable）。

    成熟方法论（搜索结果验证，2026 标准）¶

    1. LLMs.txt 规范（Ant Design 官方做法）¶

    Ant Design 提供多个 AI 可消费文件，挂在站点根： - llms.txt：导航文件（所有文档链接） - llms-full.txt：完整组件文档（含实现细节和示例） - llms-semantic.md：组件语义描述（DOM 结构 + 使用模式）

    接入方式：Cursor 用 @Docs，Claude Code 加到 CLAUDE.md，Codex 加到 AGENTS.md，Gemini CLI 用 --context。 提示词模板：阅读 https://xxx/llms-full.txt 并理解组件库，编写代码时使用这些知识。

    2. 一份 SSOT 派生七种产物（SeeYouUI 做法）¶

    AI 原生组件库核心：单一数据源（SSOT）——所有 props/events/slots/示例从源码自动提取到 registry.json，一次维护、多处生成： - 🤖 MCP 服务（按需查组件 API，不占上下文） - 📄 LLMs.txt（大模型抓全站 API 概览） - 📝 Agent 规则（Cursor/Claude Code 自动读取） - 💡 IDE 补全（JetBrains web-types）

    关键：改一处源头（组件源码 + meta.ts），跑 pnpm ai:gen 同步刷新所有 AI 入口，永远不会和代码脱节。联合字面量类型内联（'primary' | 'error' | 'warning' 直接可见，无需推测）。

    3. 组件旁放 AGENTS.md（Subvisual 做法）¶

    最轻量的落地模式——组件源码旁放一个 AGENTS.md：

    项目根 AGENTS.md（registry 表）：列出所有组件 + 一行描述
src/components/Button/AGENTS.md：props + 用法示例 + 导入名
    • 用 registry/detail 模式：AI 只需要概览就知道"有什么"，需要细节再展开（渐进披露）
    • 随 npm 包发布（node_modules/@xxx/ui/AGENTS.md），消费方在 CLAUDE.md 里指路
    • 关键：AI 常常"知道类型签名但不知道该选哪个组件"——registry 一行描述解决"什么时候用哪个"

    4. JSDoc/TSDoc 完整标签（2026 标准）¶

    AI 从 JSDoc 提取组件信息，只写 @param 不够，完整标准： - Summary（一行，<80 字符）+ @remarks（为什么存在/设计权衡） - @example（真实可用示例——AI 最重要的学习材料） - @see @link（交叉引用相关组件） - 文档合同（Contract）而非实现——聚焦公共 API 面和保证

    5. Storybook AI Manifests（React 项目）¶

    Storybook 自动从 JSDoc 提取 manifest 给 agent；story 描述"为什么用"而非"演示什么"。可用 manifest 标签排除反模式示例。

    6. 国家团体标准 T/JSIA 0002-2026¶

    《面向AI编程的软件SPEC编制规范》2026-07-17 发布（江苏省软件行业协会）——功能模块构成要素标准化（模块代码/名称/所属域/描述/用户场景/业务规则/功能点/执行结果/执行约束）。说明"面向 AI 的代码文档化"已进入国家标准阶段。

    与墨题项目的直接落点¶

    墨题前端（Vue3 + Antigravity 优化）正在被 AI 工具频繁修改——组件文档化能直接减少 Antigravity/Codex 改错组件的概率：

    落点 做法 工作量
    根 registry frontend 根加 AGENTS.md，列出核心组件（答题卡/侧边栏/错题面板等）一行描述 小（30 分钟）
    核心组件 JSDoc 给 5-8 个高频组件的 props 补 JSDoc（含 @example） 中（2-3 小时）
    全局提示 AGENTS.md 加"本组件库约定"段（Vue3 组合式 API、样式变量、命名规范） 小
    MCP 查询（可选） 学 SeeYouUI 建 registry.json + MCP（墨题规模暂时不需要） 大，暂缓

    预期收益：Antigravity/Codex 改墨题前端时，不再猜组件 API、不再发明不存在的 props、不再造平行组件——直接对应视频主题"让 AI 工具完全听懂"。

    结论¶

    "让 AI 完全听懂"= 组件库 AI-native 化：SSOT + 渐进披露 + JSDoc 完整标签 + 示例优先。最轻量起步是根 AGENTS.md registry + 核心组件 JSDoc——正好补上我们给 Codex/Antigravity 注入技能但没给墨题组件本身做文档的缺口。
