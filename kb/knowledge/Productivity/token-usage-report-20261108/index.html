    四个要点：

    1. 💸 71% 成本来自一个会话：11-05「Hermes Agent 故障排查与修复报告」单会话 275 次调用、grok-4.6、3.09M 输入 + 54.1M cache 读 → 等价 $34.1。同样的 token 量换 deepseek-v4.1-flash 只要 $1.43（省 96%）。
    2. ✅ 缓存命中率 97.1% 是本周最大的省钱机制：206.4M cache 读若按正常输入价计费需 $61.9，实际只花 $1.24（deepseek cache 价 $0.006/M）。长上下文复用把单位成本压到 1/50。
    3. ⚠️ 本周前三天（11-02~11-04）用量记账缺失：56 个会话 api_call_count=0，token 全为 0；11-05 起才有数据。前半周真实用量未知，成本环比数字需打折看。
    4. 🐘 存储告急项是 state.db：941.9MB / 166,210 条消息 / 241,153 页，freelist=0（无碎片但无回收空间）。相比 8-14 快照的 313MB 涨了 3 倍。

    ⚠️ 成本口径说明（重要）¶

    1. estimated_cost_usd 不可用：DB 中该字段存在三类记录——unknown/none（106 条，合计 $20,623,260）、provider_models_api（27 条，$6,596,646）、official_docs_snapshot（8 条，$0.75）。前两类是单价单位错误导致的脏数据（把 CNY 当 USD、或 cache 单价放大），不可作环比基准。
    2. 本报告的口径：tokens × 主流供应商官方单价 = 等价成本。若你的实际付费方式是中转套餐/预充值，则现金支出 ≠ 等价成本，需以中转站账单为准（本次未核验余额）。
    3. 观察：billing_provider=custom 的 40 个会话（含 8317 中转、workbuddy-ai）cost_status=unknown，说明这些端点没有可靠计价元数据 → 只要走中转，Hermes 自己算不出成本。
