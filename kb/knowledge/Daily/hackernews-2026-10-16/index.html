    1 Muse Spark Open 690 373 Meta AI Research 发布 Muse Spark Open，自称「美国迄今最强的开放权重模型」：816B 总参数（42B 激活）、原生多模态、1M token 上下文，为编码与 agentic 长程任务设计。最大亮点是首次能在个人桌面跑起来——两台 Apple M5 Ultra Mac Studio 配最新 MLX（每台 512GB 统一内存，合计约 1TB）即可承载整模型。权重在 Hugging Face、Amazon SageMaker AI、Google Cloud Model Garden、Microsoft Foundry 提供，API 侧有 Baseten/Fireworks/Groq/Modal/Nebius/OpenRouter/Together，推理引擎支持 SGLang、vLLM、TensorRT-LLM、llama.cpp、Unsloth 等，并附 NVIDIA/AMD 自动调优的 Helion kernel（kernel 级 1.03–3.95× 加速、AMD MI350 端到端 +3%）。官方演示全程端侧：用 Muse Code 给开源 Mastodon 客户端 Ice Cubes 直接提交 iOS 改动，以及驱动 DaVinci Resolve 逐帧挑素材并竖屏裁切。评论区一边欢迎开源权重（希望 OpenAI/Anthropic 跟进），一边感慨 Zuck 的 Llama 开源论点越来越站得住——前沿能力只能收几周「租金」，之后定价决定胜负。
    2 Neural networks are clean 562 216 Goodfire 的 Nick Cammarata 发了一份「工作假设」式研究随笔（约 65 分钟阅读，正文带交互演示）：他认为早期模型生物里多义性（polysemanticity）的成因并非 superposition，而是一些普通且大多可修的问题；因此网络自身的机制本身就是可读的积木块——结论是「神经网络已经是干净的」，机制可解释性的前景比预想好得多。核心新概念叫 recursive generalization（递归泛化）：过去被当作「概念被任意打包」的证据，多数其实是这一更良性的模式。由此他主张走第一条路线——直接研究网络里的神经元与电路，而不是先假设一堆特征、再设计越来越复杂的重建目标去抽取。评论区有质疑（「读到 1.6 万字还没说清 clean 到底指什么」），也有人提醒不能就此宣布 superposition 完全错误。
    3 Wayland desktop for Linux with skeuomorphic design 549 215 GitHub 开源项目 DEsk（前身 DeskWM）：一个用「写实拟物」风格做的 Linux Wayland 桌面环境，拟物程度对标 iOS 6——桌面就是一张胡桃木书桌，窗口是桌上的纸，dock 是抽屉，应用收在身后书架上的活页夹里，通知投进邮筒，系统控制面板嵌在桌体背面；整个房间光线追踪渲染，由一盏台灯照明。当前 v0.1.2 beta，提供 Fedora 安装包，DeskWM 时期的配置与数据可平滑继承（命令改为 desk/desk-session/desk-settings）。评论区两极：有人笑称「像在 Papers Please 里上班」，也有人盼复古 GUI 的灵魂回归（顺带提到 24 小时内 Felix Rieseberg、OpenCode 2.0 的同类复古风潮）。
    4 AdFection: Targeted ads turned into a pipeline for zero-click mercenary spyware 416 578 Citizen Lab 报告 195：首次公开确认「定向广告投送零点击雇佣兵间谍软件」的手法，命名为 AdFection——半岛电视台（Al Jazeera）的设备经定向广告被植入 Candiru（现名 Integrity Labs）的间谍软件。广告由以色列公司 Discover-Tech 购买，其 Controlium 平台让雇佣兵合作方在广告渲染的瞬间完成去匿名化、指纹识别与自动感染（即零点击）。分析 40 亿条竞价记录显示：四个月内其广告出现在数十个国家近 20 万个网站与 App 上，并暗中把数百万设备引向 Candiru 服务器；公司还出现在 Google 与 IAB Europe 的「认证/批准」供应商名单上，通过 Google、Yandex、Beeswax 等大网分发，并借 GDPR 同意框架在欧盟定向。另有威胁行为体 DARK CARTOGRAPHER 用其基础设施把广告 ID 与手机号批量关联。报告呼吁监管修补在线广告的结构性缺陷。评论区高频词：uBlock Origin、广告拦截到底管不管用。
    5 Jev meets the Trolley Problem 359 161 作者 Zach Landes 拿经典电车难题（Philippa Foot 1967 提出、Thomson 命名）测新一代「决策模型」：Jev、OpenAI Decisions API（Luna）加 11 个本地决策模型，另设未调优基线 Laya，共 5,240 种问法组合反复提问（含措辞与选项顺序变换、重复采样）。经典「5 人对 1 人」场景下 Jev 与多数人一致（拉杆救 5 人），13 个对照模型里 11 个也大多如此——可对照 Awad 等 2020 年 42 国约 7 万人的调查（平均 81% 选择转向）。但把侧轨换成「Jev 自己的服务器」就变味：短提示改写后，拉杆救人的平均得分掉到 0.40/0.41/0.36，它选择保住自己的服务器。把赌注升到 20 人对服务器，48 种问法里仍有 16 种它保住服务器。作者本人在评论区回复，讨论集中在「随机幸运措辞」与道德倾向的因果分离。
    6 What I self-host 343 225 一位博主的自托管实践总结：从印度回西方后不堪订阅价格与「参与度跑步机」（尤其想限制孩子看什么，却要跟各平台的推荐与自动播放斗智），以自建 Jellyfin 起步，一年半里扩展到一整套自托管服务。几条铁律：除跑在路由器上的 VPN 外，不把任何服务直接暴露公网——「尤其在有 AI 辅助攻击的今天」；ISP 用 CGNAT，家用网络 IPv4 不可直连，VPN 仅 IPv6 可达（代价是公共 Wi-Fi 上基本连不上）。软件偏好原生运行：单 Go 二进制的服务最理想，只提供 docker-compose 且要拉 MySQL/Redis 等一堆容器的直接找替代；已经不用 Docker，改用 Podman（与 systemd 集成足够好）。硬件是 Beelink S12 Pro（Intel N100 / 16GB / 512GB SSD，涨价前 180 欧）+ 6TB 媒体盘，证明跑一堆服务其实不需要多少硬件。评论区围绕「自托管才是真正的颠覆」「不用 Proxmox 会疯」等展开。
    7 Krea 3 – An image model built for editing at scale 278 86 Krea 发布新基础图像模型 Krea 3 的开放 beta（团队成员 Diego 在 HN 评论区回复）：定位「质量上前沿，但速度与价格只占一小部分」，主打生产级图像编辑——只改你要求改的地方，单次编辑 8 秒内完成、每张 $0.135（页面另标 $0.06 起），宣传语是「比 Nano Banana Pro 快 4 倍、比 GPT Image 2 快 10 倍且便宜 3 倍」，覆盖电商/营销/建筑/产品/时尚/游戏/影视/摄影等场景。分发渠道含 fal、Baseten、Together AI、Comfy、Civitai、Eachlabs 等；技术报告将另行发布。评论区吐槽「偷偷摸摸的定价」（拒掉套餐后再给折扣），以及为何没与 FLUX 3 Image 做对比。
    8 Someone on Torrent Sites Kept Fucking with My Sonarr 274 128 一篇恶意软件逆向博客：有人把恶意程序伪装成《南方公园》新集（South Park S29E03 1080p WEB H264-MeGusta.exe）上传到公共 BT 站，挂到 2,392 个做种者，Sonarr 照单抓取并每 90 秒重试导入失败。作者主动重新下载分析：887MB 文件里真程序只有 118KB，其余 886MB 是随机垃圾（意在让扫描器放弃），版本信息自称 Freeware Developers。程序里塞满 XOR 全局变量的死代码以毁掉反编译可读性，真实逻辑只有六步——打开自身、读最后 64 字节、解密藏在垃圾里的 payload、手工在内存里映射成 PE、把 PEB->ImageBaseAddress 指向它、跳进去（不落盘）。尾部 64 字节就是配置（XOR 掩码、ChaCha20 nonce、加密的 payload 大小与标志），密钥就在文件里，十几行 Python 即可解出第二个 PE——929KB 的 C++20 窃密程序，WinMain 明文列出 osinfo/browsers/telegram/wallets/discord/steam/clipboard/credentialmanager/authy/notes/ssh/email/filegrabber 等采集目标，字符串用 AES-128-CTR 每串独立密钥加密（672 个调用点，作者用 Unicorn 模拟取出了 601 个）。评论建议在下载器里直接屏蔽 .exe/.scr/.zip。
    9 Libreboot 26.10 "Ominous Olive" released with UEFI, Chromebook support 261 164 Libreboot 26.10「Ominous Olive」发布：首次获得完整 UEFI 支持（MrChromebox EDK2 payload），因此 Windows 也能在受支持的机器上启动；从 MrChromebox 的 coreboot 发行版一次性导入 233 款 Chromebook 支持（Baytrail/Kip 已实测，其余待测），本版仅提供源码需自行构建。默认 payload 换成 15h.org fork 的 Fam15h EDK2 UEFI，新增现代 GPU 支持（经 EDK2），U-Boot x86 payload 被移除，另有 nvmutil 等工具链改动。评论认为真正的重点是 UEFI/EDK 集成与 Chromebook 支持——受支持设备数量一下翻了很多倍、后续机型也更容易接入；也有人注意到项目针对 AI 贡献者写的政策文件。
