    2026 后端开发千轮研究增强¶

    2026-08-22 | 搜索引擎研究 | FastAPI 生产实践 2026 + AI 应用模板 核心结论：FastAPI 2026 关键 = lifespan 替代 on_event + response_model 防泄漏 + async 不阻塞 + SQLite WAL 生产优化；AI 应用标配 = JWT refresh + WebSocket 流式 + 可观测性

    一、FastAPI 生产最佳实践 2026（对照 EPM 项目）¶

    必须做的（EPM 直接适用）¶

    ① lifespan 替代 @app.on_event("startup")（已废弃，将移除）
   @asynccontextmanager async def lifespan(app): yield 前=启动 后=关闭

② response_model + status_code 每路由必设
   → 防 ORM 内部字段泄漏（User.hashed_password！）+ 正确语义（POST→201）

③ 业务逻辑进 services/（路由只接收请求→调 service→返回）
   → 数据库查询写路由 = 难测试难复用

④ DI 注入 DB session（Depends(get_db)）——禁止全局连接
   session: AsyncSession = Depends(get_db_session)
   异常回滚 + 请求结束自动关闭

⑤ async def 只用于真 async I/O；同步操作（time.sleep/CPU）会冻结事件循环！
   → 用普通 def（FastAPI 自动丢线程池）或 run_in_executor
   ⚠️ async 里 time.sleep(2) = 所有并发请求卡 2 秒

⑥ BackgroundTasks（<1-2 秒轻量）vs Celery/Arq（>5 秒/重任务/需重试）

    SQLite 生产优化（EPM 就是 SQLite！）¶

    engine 事件监听注册 pragmas:
  PRAGMA journal_mode=WAL       # 并发读写大幅提升
  PRAGMA synchronous=NORMAL     # WAL 下安全且快
  PRAGMA busy_timeout=5000      # 写锁等待（不报 database is locked）
  PRAGMA cache_size=-64000      # 64MB 缓存
  PRAGMA foreign_keys=ON        # 外键约束
  PRAGMA mmap_size=268435456    # 可选 mmap
SQLite 不支持连接池 → 不设 pool_size（设 timeout connect_args）

    async SQLAlchemy 要点¶

    expire_on_commit=False   # 必须！防 commit 后 lazy-load 失败（async 上下文）
autoflush=False          # 显式控制 flush 时机
autocommit=False         # 显式 commit
pool_pre_ping=True       # 防 stale 连接
pool_recycle=1800        # 30 分钟回收
Alembic URL 自动映射: sqlite+aiosqlite:// → sqlite://（async→sync 驱动互换）

    二、AI 应用模板（full-stack-ai-agent，Vstorm）¶

    结构: backend(FastAPI+PydanticAI) + frontend(Next.js 15) + PostgreSQL/Redis/Celery
标配: JWT + refresh token（HTTP-only cookies）/ WebSocket 流式 + conversation_id 恢复
     / Alembic 迁移 / Redis 缓存 / OpenTelemetry 可观测性 / Docker CI
分层: repositories(数据访问, flush 不 commit) → services(业务规则, 抛域异常)
     → 路由层统一 commit = 原子性
PydanticAI 推荐（Pydantic 团队）: 类型安全(Pyright strict)/原生 Logfire/iter() 流式全事件
设置校验: @field_validator 防默认 JWT secret/通配 CORS/debug 模式上线（生产验证）

    三、对 EPM 的行动项¶

    1. SQLite 加 WAL + busy_timeout——并发刷题/导入不再报 database is locked（当前已知痛点！）
    2. 检查路由是否漏 response_model——防内部字段泄漏
    3. async 端点里禁 time.sleep——AI 调用用 httpx async，同步调用丢线程池
    4. 结构化日志（structlog JSON）——云端部署排查
    5. lifespan 替代 on_event（如有）
    6. AI 调用重试 >5 秒任务考虑 Arq（EPM 目前 BackgroundTasks 够用则保持）
