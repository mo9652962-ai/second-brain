    《小君AI测评》测评文初稿（公众号向）¶

    依据 2026-08-15 大纲成稿，数据全部来自 2026-08-15 本地实测（clone 自 github.com/Joho6666/xiaojunceping @ 5d926a4） 标题候选见文末，正文暂用候选 1

    3 stars 的 AI 选型工具，我部署后给它提了个 PR¶

    当你想做一个项目，该用哪个 AI 模型？哪个 Agent 框架？有人做了个工具想回答这个问题——但它只有 3 个 star。

    它叫小君AI测评（AgentScope）。输入一段项目描述，它输出一整套 AI 落地方案：模型选型、Agent 队列、工具链、成本估算，连 Prompt 都给你生成好。

    名字有点撞车——阿里有个同名开发框架 AgentScope，已经 2.0 了。而这个评估平台，是 2026 年 8 月 13 日才创建、11 个 commit、6188 行代码的早期原型。

    我把它 clone 下来实测了一整天。结论：核心能用，问题不少，但值得研究——我还顺手给它提了个 PR。

    部署：3.3 秒 Ready，但有两个坑¶

    npm install 装完，npm run dev，3.3 秒 Ready。首页渲染正常，知识库自动初始化（103 条种子数据）。DeepSeek Provider 连上，test 接口返回 connected。

    然后坑来了。

    坑 1：模型名必须用官方 ID。 我配的是 deepseek-v4-flash-260425——这是中转站的别名，官方 API 直接拒绝。换成 deepseek-v4-flash 才通过。中转站别名 ≠ 官方模型名，这个教训值钱。

    坑 2：不配 DATABASE_ENCRYPTION_KEY，连接不持久化。 连接存内存，dev 重启就丢。在 .env.local 里加一个任意字符串的 key 才恢复。

    还有个小坑：dev 和 build 共用 .next 目录，会偶发 Cannot find module './682.js'。部署过 Next.js 的人应该秒懂——清掉 .next 重新 build 就好。

    实测：25 秒出一份 54KB 的报告¶

    拿一个真实场景测：电商网站项目。25 秒出报告，54KB，六维评分：技术可行性 82、Agent 适配度 79、风险可控度 67。

    GitHub 参考是核验过的真实数据：commerce 14K★、spree 15.6K★、reaction 12.4K★——不编造。策略判定「基于开源二次开发，置信度 92%」，有依据。

    这个「报告只出不核验数据」的原则，很值得学。模型目录还带 lifecycle，旧 ID 自动标 deprecated 提示迁移——正好命中 DeepSeek 旧别名这个坑。

    发现的 bug：功能 100% 必挂 + 我提的 PR¶

    先说严重的：README 宣称的「JSON 导入」功能，任何用户导入必失败。POST /api/knowledge/import 传合法 JSON 也返回 400。根因是 SQL 引用了 @sourceType 参数，但 import 路由构造的 entry 没传这个字段——Missing named parameter，直接 400。sync 服务自己构造了 sourceType 所以正常，用户导入路径必崩。

    我提的 PR 是另一个：首次初始化知识库就崩，SQLITE_CONSTRAINT_PRIMARYKEY。种子数据里有 2 个重复 id（mcp-brave-search / plugin-github-copilot），seedIfEmpty 用裸 INSERT 撞了主键，3 个测试挂掉。

    修复很简单：删 2 行重复条目，验证 6/6 测试全绿，fork → PR，10 分钟全流程。

    结论：开源项目再小，实证测试都能找到真问题。

    竞品格局：选模型是红海，全套方案是差异化¶

    纯模型选型工具不少：modelcompare、BenchLM、Ofox、chooseaimodel（377 模型 51 provider）。但小君的差异化是「全套方案」——Agent + Skill + MCP + Workflow + Prompt 一起给，不只是选个模型。

    有个数据值得注意（PawBench）：工具/框架选对，比模型选对更影响结果——qwen3.6-plus + QwenPaw 76.5 分，反而超过 qwen3.6-max-preview + Hermes 的 70.2。选型工具的定位逻辑站得住。

    值得学的三件套¶

    1. 知识库 + 来源核验 + 规则引擎：本地 SQLite，种子 105 条，来源分级（official/github/registry），失效/敏感/平台规则过滤——「项目→方案」的参考实现。
    2. 报告只出不核验数据：GitHub 核验走真实 API，查不到就明说。
    3. 模型目录带 lifecycle：旧 ID 自动标 deprecated，提示迁移。

    结论¶

    • 功能 7/10：真实能用，评估链路通
    • 架构 8/10：思路清晰，三件套设计严谨
    • 成熟度 4/10：3 stars 早期原型，JSON 导入必挂、评估链路无降级、报告参考偶尔与项目不匹配

    适合谁：想研究 AI 选型系统怎么实现的人、部署学习者。 不适合谁：当产品用——名字撞车 + 单用户，README 自己都说正式多用户部署前还要接数据库、账户隔离、CSRF。
