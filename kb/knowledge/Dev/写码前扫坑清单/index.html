    写码前扫坑清单（开发 B 坑系列汇总）¶

    2026-08-21 程序员Orion 系列 11 条沉淀浓缩。写代码前扫一遍，交付翻车率直降。 用法：接任何开发任务 → 对照本清单逐项检查设计 → 该改的改完再写码。

    一、接口安全 5 坑（攻防一体）¶

    # 坑 写码时怎么查 参考
    1 前端隐藏按钮 = 安全？ 每个管理接口后端独立鉴权（不信前端 role）；默认拒绝 前端隐藏≠安全.md
    2 参数/幂等/限流缺失 入口参数校验；下单/支付接口幂等；验证码/发送类限流 接口三件套.md
    3 换 ID 拿别人数据（IDOR） 查询带 user_id 过滤（WHERE id=? AND user_id=?） IDOR.md
    4 上传只看后缀 四层检查：限大小/验内容(magic bytes)/随机名/隔离禁执行 文件上传四层.md
    5 验证码无后端限流 后端限频（手机号/IP/设备）+ 人机验证 + 熔断 + 有效期 验证码限流.md

    二、性能 3 坑¶

    # 坑 写码时怎么查 参考
    6 循环调外部 API（自我 DDoS） 改批量接口；没批量上 MQ/延迟队列限频 循环调API.md
    7 for 循环插库（N+1 通讯） executemany / 批量 SQL + rewriteBatchedStatements 循环插库.md
    8 本地缓存跨节点（脏数据） 多节点部署用 Redis 全局缓存，关自带缓存 循环插库.md

    三、架构 2 坑¶

    # 坑 写码时怎么查 参考
    9 小项目硬上微服务 无 10 人团队/大并发 → 单体优先，业务量到了再演进 单体优先.md
    10 微服务无超时 全链路超时：网关/调用/HTTP/DB/MQ + 线程池控制 微服务超时.md

    四、支付/数据/合规 3 坑¶

    # 坑 写码时怎么查 参考
    11 金额前端算 金额计算/转换一律后端（防浮点+防改价） 虚拟支付400.md
    12 物理删除 软删除：deleted_at 时间戳 + WHERE deleted_at IS NULL 软删除.md
    13 体制内单用国际加密 医院/银行/国企/政务 → 国密 SM2/SM3/SM4 + 等保合规 等保国密（技能）

    五、API 契约 1 坑¶

    # 坑 写码时怎么查 参考
    14 改返回字段/结构（前端白屏） 上线接口不删字段不改结构；必须动 → API 版本控制（v1/v2 并存） 接口契约.md
    15 空 catch 吞异常（静默失败） 能恢复→弹窗提示重试；致命→记日志；关键流程→返回明确失败状态 空catch吞异常.md
    16 并发超卖/覆盖（先查再扣） 条件更新兜底：UPDATE ... WHERE stock > 0，影响行数=0 报错（乐观锁） 并发超卖.md
    17 跑通就交付（无 Code Review） 代码经审查才能合并/交付：PR + review + 门禁（grep 冲突/构建/测试） 代码审查铁律.md
    18 数据库公网裸奔（3306 暴露） VPC 私有子网：DB/缓存不分配公网 IP，仅内网通信；远程用堡垒机/SSH 隧道 数据库公网裸奔.md
    19 缓存一致性（忘了删/TTL 同点） 先更库后删缓存；TTL 加随机抖动防雪崩 缓存一致性.md
    20 LIMIT OFFSET 深分页卡死 大数据用游标分页：WHERE id > last_id LIMIT n，排序字段唯一稳定 深分页-游标分页.md
    21 Git 历史泄密（.env 提交） .gitignore 立即加 .env；密钥轮换（云后台重置）而非删文件 Git密钥泄露-轮换.md
    22 SQL 注入（手动拼接） 参数化查询（? 占位）；ORM 非免死金牌（原生 SQL/模糊查询/动态排序单独防） SQL注入-参数化查询.md
    23 OSS 公共读（隐私泄露） 公私分桶；敏感文件私有 + 后端签名短时效 URL（5 分钟） OSS公共读-隐私泄露.md
    24 日志泄露（打印敏感信息） 统一 Logger 拦截器 + 脱敏（密码/手机号/token 不落日志） 日志泄露-脱敏.md
    25 每请求新建连接（连接耗尽） 连接池复用（HikariCP/mysql2 pool），限连接数 数据库连接池.md
    26 定时任务多机重复执行 Redis 分布式锁（SET NX EX），抢不到退出 分布式定时任务-锁.md
    27 无操作审计（盲盒系统） 拦截器/切面记录：操作人/时间/前后值 操作审计-盲盒系统.md
    28 无脑 Boolean 设计表 可能超两种状态 → status 枚举（0未付 1支付中 2已付 3失败） 状态枚举替代布尔.md
    29 超时盲目重试（重复扣款） 幂等键 + 先查状态再重试；指数退避 + 上限 超时重试-幂等.md
    30 事务内做网络 IO（MQ/远程调用） 事务最小化：@Transactional 只含 DB 变更；先落地本地消息表，再异步投递 事务内网络IO.md
    31 幂等 key 缺状态（跨状态误判） 幂等 key 含 requestId+当前状态+期望状态；状态机校验前置 幂等跨状态.md
    32 连接池配置错误（越大越好/超时默认） 池大小=core×2+spindle（SSD 用 core×4）；获取连接超时≤3s；maxLifetime 30min 连接池配置.md
    33 读写分离无延迟感知 Slave 延迟 >1s 自动路由 Master 读，防「下单成功但查不到」；写后读走主库（ThreadLocal 标记） 高吞吐韧性.md
    34 无背压/舱壁（队列 OOM） 有界队列（满则拒绝）；依赖分线程池+超时；禁止级联重试（重试带抖动） 高吞吐韧性.md
    35 无 AI 工作负载观测 LLM 调用要 Token 追踪/质量评估/幻觉告警（eBPF+OTel 2026 标配） 高吞吐韧性.md

    六、通用排障顺序（出问题时）¶

    ① 查自己业务接口/参数/字段值（排除 90%）
② 查外部接口（微信/支付宝/短信）
③ 查权限/配置（开通状态/回调域名/appid）

    使用流程（接开发任务时）¶

    1. 读需求 → 对照「接口安全 5 坑」检查设计（鉴权/校验/IDOR/上传/限流）
2. 涉及性能 → 对照「性能 3 坑」（批量/缓存/队列）
3. 涉及架构 → 对照「架构 2 坑」（单体/超时）
4. 涉及支付/数据 → 对照「支付/数据/合规 3 坑」
5. 写码 → 测试（web-api-testing 边界/并发）→ 交付前再过一遍
