    二、研究评估 ✅（搜索引擎验证 + 决策）¶

    1. Activepieces（Awesome-Lists 待办：部署个人自动化）¶

    • 研究：MIT 开源自动化平台（Zapier/n8n 替代），280+ 集成，Docker 10 分钟部署，原生 MCP 支持（pieces 自动变 MCP server，可接 Claude/Cursor/Hermes），可跑 PGLite+内存 Redis（免数据库）
    • 评估：对 sora 价值 = 复杂多系统流程（闲鱼→微信→Obsidian→邮件联动）。但当前 Hermes cron 已覆盖核心自动化（31 个任务），Activepieces 属于"锦上添花"
    • 决策：暂不部署，保留为可选增强。若未来出现"多平台跨系统复杂流程"需求再上（Docker 部署 10 分钟）

    2. ActivityWatch（Awesome-Lists 待办：收集时间数据）¶

    • 研究：开源免费，本地优先（数据不出设备），自动追踪应用/浏览器使用 + AFK 排除，跨平台
    • 缺点：无 AI 分类、无团队、无发票——原始数据需自己处理
    • 评估：对 AI 博主数据化（内容生产时间分布）有价值，但违反低摩擦原则（装了要持续维护）
    • 决策：暂缓。若要做"时间审计"项目时再装（安装即用，无云组件）

    3. Protobuf 序列化（s4mp 待办：替代 pickle）¶

    • 研究：Protobuf vs pickle = 类型安全 + 跨语言 + schema 演进 + 防任意代码执行（pickle 恶意帧可执行代码！）。Python 实现速度不如 pickle，需 .proto schema + 代码生成
    • S4MP 场景：当前已加 HMAC-SHA256 签名（防伪造/篡改），残余风险 = 明文窃听（局域网可接受）
    • 决策：Protobuf 是正确方向但非紧急——签名已覆盖主要威胁。排期：若协议要跨语言（如 C# 客户端）则必须换 Protobuf；纯 Python 局域网可维持现状
