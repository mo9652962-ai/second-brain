    多 Agent 协作 20 查询基线设计（EBR 3.0 Phase 0 落地）¶

    团队：k 指挥 + WorkBuddy 深研 / dsh 数据 / Codex 编码 / Antigravity 前端

    方法论：multi-agent-research（G0-G4 验证门）

    评测优先级：确定性 > LLM judge > 人工；N=5 仅冒烟；本基线 N=20 真实代表性查询

    报告：pass@1 + pass^k（k=3）；95% CI（Wilson 区间）

    二、3 个 deterministic grader 示例¶

    Grader 1：arXiv 引用真实性 + 字面匹配（调研类通用）¶

    # grader_arxiv_citation.py

# 用途：A1/A3/A4 等涉及 arXiv 引用的调研查询

# 输入：trial 的最终产物文本；任务定义中的 expected_arxiv_ids（可选）

# 输出：{pass: bool, reasons: []}



import re, urllib.request, rapidfuzz



def grade(artifact: str, task_spec: dict) -> dict:

    reasons = []

    # 抽取所有 arXiv ID（格式 2608.22152 或 2603.07670v1）

    ids = re.findall(r'\b(\d{4}\.\d{4,5})(?:v\d)?\b', artifact)

    if len(ids) < task_spec.get("min_ids", 1):

        reasons.append(f"arXiv ID 数量不足：{len(ids)} < {task_spec['min_ids']}")



    # 验证每个 ID 真实存在（HTTP 200）

    for aid in set(ids):

        url = f"https://arxiv.org/abs/{aid}"

        try:

            code = urllib.request.urlopen(url, timeout=10).getcode()

            if code != 200:

                reasons.append(f"arXiv ID {aid} 不可达（HTTP {code}）")

        except Exception as e:

            reasons.append(f"arXiv ID {aid} 验证失败：{e}")



    # 字面引用匹配：产物中每个被引片段应在 arXiv 原文中 fuzzy≥90

    for quoted in task_spec.get("expected_quotes", []):

        # 这里简化为与预存原文对比；实际从 arxiv HTML 抽取

        ratio = rapidfuzz.fuzz.partial_ratio(quoted.lower(), task_spec["source_text"].lower())

        if ratio < 90:

            reasons.append(f"引用片段匹配度 {ratio} < 90：{quoted[:60]}...")



    return {"pass": len(reasons) == 0, "reasons": reasons}

    Grader 2：编码类测试套件 + 静态分析（C1-C4 通用）¶

    # grader_code.py

# 用途：所有编码类查询

# 输入：trial 的 git diff（补丁）；任务定义中的 test_cmd/lint_cmd

# 输出：{pass, reasons, metrics: {tests_pass, lint_clean, regression_intact}}



import subprocess, json



def grade(repo_dir: str, task_spec: dict) -> dict:

    reasons = []; metrics = {}

    # 1. 指定测试命令退出码 0

    r = subprocess.run(task_spec["test_cmd"], cwd=repo_dir, capture_output=True, timeout=120)

    metrics["tests_pass"] = (r.returncode == 0)

    if r.returncode != 0:

        reasons.append(f"测试失败：{r.stderr.decode()[:500]}")



    # 2. 静态分析（ruff/mypy/bandit）0 error

    for lint in task_spec.get("lint_cmds", []):

        r = subprocess.run(lint, cwd=repo_dir, capture_output=True, timeout=60)

        if r.returncode != 0:

            reasons.append(f"静态分析失败 [{lint}]：{r.stdout.decode()[:300]}")

    metrics["lint_clean"] = all(

        subprocess.run(l, cwd=repo_dir, capture_output=True, timeout=60).returncode == 0

        for l in task_spec.get("lint_cmds", [])

    )



    # 3. 回归：main 分支既有测试仍 pass（G3 副作用门）

    if task_spec.get("regression_cmd"):

        r = subprocess.run(task_spec["regression_cmd"], cwd=repo_dir, capture_output=True, timeout=180)

        metrics["regression_intact"] = (r.returncode == 0)

        if r.returncode != 0:

            reasons.append("回归测试被破坏（G3 副作用门失败）")



    # 4. 无 unrelated 文件改动（git diff 仅触及 expected_files）

    r = subprocess.run(["git", "diff", "--name-only"], cwd=repo_dir, capture_output=True)

    changed = r.stdout.decode().strip().split("\n")

    if any(f not in task_spec["expected_files"] for f in changed):

        reasons.append(f"越界改动：{set(changed) - set(task_spec['expected_files'])}")



    return {"pass": len(reasons) == 0, "reasons": reasons, "metrics": metrics}

    Grader 3：数据类产物语法 + 数值一致性 + 副作用（B1-B4 通用）¶

    # grader_data.py

# 用途：所有数据类查询

# 输入：输出文件路径 + 源文件路径

# 输出：{pass, reasons, metrics: {rows_match, sort_correct, source_untouched}}



import pandas as pd, json, subprocess



def grade(output_path: str, source_path: str, task_spec: dict) -> dict:

    reasons = []; metrics = {}



    # 1. 输出文件语法合法（CSV 可被 pandas 解析 / JSON 可被 jq 解析）

    try:

        if output_path.endswith(".csv"):

            df = pd.read_csv(output_path)

        elif output_path.endswith(".json"):

            with open(output_path) as f:

                json.load(f)  # 不抛异常即合法

    except Exception as e:

        reasons.append(f"产物语法非法：{e}")

        return {"pass": False, "reasons": reasons, "metrics": metrics}



    # 2. 数值一致性：输出值与源逐行比对（deterministic diff）

    if task_spec.get("numeric_check"):

        src = pd.read_csv(source_path)

        for col, expected_vals in task_spec["numeric_check"].items():

            got = df[col].tolist()

            if got != expected_vals:

                reasons.append(f"列 {col} 数值不一致：{got} vs {expected_vals}")

        metrics["rows_match"] = (len(reasons) == 0)



    # 3. 排序正确（降序/升序）

    if task_spec.get("sort_col"):

        col = task_spec["sort_col"]

        if not df[col].is_monotonic_decreasing and task_spec["order"] == "desc":

            reasons.append(f"列 {col} 非降序")

        metrics["sort_correct"] = (len(reasons) == 0)



    # 4. 源文件未被修改（G3 副作用门）

    r = subprocess.run(["git", "diff", "--stat", source_path], capture_output=True)

    if r.stdout.decode().strip():

        reasons.append("源数据文件被修改（G3 副作用门失败）")

    metrics["source_untouched"] = (len(r.stdout.decode().strip()) == 0)



    return {"pass": len(reasons) == 0, "reasons": reasons, "metrics": metrics}

    三、评测执行计划¶

    3.1 对照设计（单 Agent vs 多 Agent）¶

    | 组别 | 编排 | 子 Agent 数 | 说明 |

    |---|---|---|---|

    | 对照组 A（单 Agent） | k 单独完成，不派子 Agent | 0 | 基线：同模型、同工具集、单线程 |

    | 实验组 B（多 Agent） | k 指挥 + 按类派 WorkBuddy/dsh/Codex/Antigravity | 1-4 | 现有编排，G0-G4 门启用 |

    | 消融组 C（多 Agent 无门） | 同 B 但关闭 G1/G2/G3 验证门 | 1-4 | 验证门是否值得（隔离幻觉雪球/副作用） |

    三组跑同一 20 查询集，每查询 ×每组跑 k=3 trial（pass@1 用首次，pass^3 要求全过）。

    3.2 指标采集（每 trial）¶

    | 指标 | 采集方式 | 维度归属 |

    |---|---|---|

    | task_success | deterministic grader pass | task_success |

    | claim_support_rate | LLM judge 双盲抽检产物中随机 N 条断言 | claim_support_rate |

    | cost_per_success | (子 Agent token 费 + 指挥费) / 成功数 | cost_per_success |

    | p50/p95 latency | harness 记录 trial 起止时间戳 | latency |

    | duplicate_work_rate | 日志中相同工具调用 / 总工具调用 | duplicate_work_rate |

    | intervention_minutes | 人工介入时长（429 重试、纠偏等） | intervention_minutes |

    3.3 统计报告（95% CI）¶

    • pass@1：每组每查询首次 trial 的通过率，报 Wilson 95% CI（N=20，小样本用 Wilson 区间而非正态近似）。

    • pass^3：每查询 3 trial 全过的比例，同样 Wilson CI。

    • 组间差异：A vs B、B vs C 用 McNemar 配对检验（同查询配对），报 p 值 + 效应量（Cohen's h）。

    • 失败模式归因：按 4 类（429 限流 / 幻觉雪球 / 同源集体幻觉 / 确认偏差）标注每条失败 trial，报各模式占比。

    3.4 评测优先级与门控¶

    • 确定性 grader 优先（上节 3 个示例覆盖 20 查询中的 14 个：A1/A3/A4/B1-B4/C1-C4/D1/E3/E4）。

    • LLM judge 补位（双盲、给 "Unknown" 出口）：A2/B4 聚类质量/D2 视觉/D4 Figma 语义/E1/E2。

    • 人工抽检：仅对 LLM judge 与确定性 grader 分歧的 trial 做 10% 抽检，校准 judge。

    • G0-G4 门启用规则：对照组 A 仅 G0；实验组 B 全门；消融组 C 仅 G0+G4（关 G1/G2/G3）。

    3.5 执行节奏¶

    1. 冒烟（N=5）：先跑 A1/B1/C1/D1/E1（每类 1 个低难度），验证 harness + grader 无 bug。

    2. 全量基线（N=20）：3 组 × 20 查询 × 3 trial = 180 run，预计 1-2 天。

    3. 读 transcript：人工读至少 10 条失败 trial，确认失败是 Agent 真错而非 grader bug。

    4. 决策门：若 B 的 pass@1 − A 的 pass@1 > 10 个百分点且 p<0.05，多 Agent 编排值得；若 B vs C 差异 >5 个百分点，验证门值得。

    3.6 已知风险缓解¶

    • 429 限流：trial 间加退避（指数，上限 60s）；intervention_minutes 记录重试时长。

    • 幻觉雪球：G1 事实交接门 + claim_support_rate 指标双保险。

    • 同源集体幻觉：A 类查询故意让 WorkBuddy 单源 vs k 交叉验证，测同源偏置。

    • 确认偏差：LLM judge 双盲（不告知 trial 来自哪组）。

    附录：设计依据¶

    • v3.0 EBR 3.0：确定性 > LLM judge > 人工；N=5 只冒烟；pass@1 + pass^k；95% CI。

    • Anthropic Demystifying Evals：task/trial/grader/transcript/outcome 定义；code-based 优先；pass@k（≥1 成功）vs pass^k（全成功）语义；20-50 任务起步；balanced problem sets（正反例）；读 transcript 是关键；grader 要防作弊（grade outcome not path）。

    • 团队 multi-agent-research：G0（任务进入前）/ G1（事实交接）/ G2（候选产物）/ G3（副作用前）/ G4（交付后）；已知失败模式 429/幻觉雪球/同源集体幻觉/确认偏差。
