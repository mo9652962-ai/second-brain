    黑盒热榜 5 项目实证研究（2026-09-08）¶

    来源：小黑盒 GitHub 热榜日报 → 全量实证研究 方法：GitHub API 实证 star + clone 读代码 + 子代理深度研究 + 质疑式核验 结论：3 项有借鉴价值 / 2 项不引入仅作参考

    二、各项目核心结论¶

    1. marketingskills（48.2k★，MIT）— ★最值得深挖¶

    不是技能文件集合，是一套「AI 营销自动化操作系统」： - 55 个营销 skill 覆盖漏斗全环节 + 51 个零依赖 Node CLI 工具 - 每个 skill 配 evals.json（prompt + 20+ 断言验证输出质量）——可测试技能库 - product-marketing 上下文原语（所有 skill 先读产品定位）——解决「技能不知道给谁做」 - marketing-loops 编排（自运行营销循环：keyword-gap/ranking-drop 等，9 要素 + 幂等性 + guardrails）

    对我 AI 营销技能库的启示：不必照搬 55 个，但必须补两个差异化原语：① evals.json 质量断言 ② product-marketing 上下文前置。这是它 48k★ 的核心原因。

    2. DeerFlow 2.0（81.9k★，MIT，Python）¶

    • 字节 2.0 用 LangGraph 重写的「通用 long-horizon SuperAgent 运行时」，已脱离 deep-research 框架
    • 本质差异 vs Hermes/OpenClaw：「真实沙盒执行 + checkpoint 可恢复的多步产出型任务」vs「日常通用助手」
    • 部署：Docker 推荐非唯一——有 Local Execution 模式可无 Docker 跑，但必须 Git Bash（本机可用）；无 Docker = 牺牲沙盒安全边界
    • 卖点核实：官网 + 免登录 demo 属实；MCP 一等集成成熟
    • 短板：跨会话记忆不稳定、小模型 structured output 失败
    • 结论：值得深入研究；部署门槛已降低（2026-09-20 复核：本机虚拟化可用 + Docker CLI 已装，仅 Daemon 未运行，见 [[knowledge/META/current-environment]]）——先轻量评估/借鉴设计，部署待 Daemon 就绪

    3. LunaTV（9.8k★，CC BY-NC-SA）— ⚠️禁商用¶

    • 本质：Next.js 14 前后端单体（41 个 API route 承担聚合/认证/m3u8 代理/存储）
    • 完成度高：README 声称 7 项功能全部有真实代码落地，无画饼
    • License 矛盾：README 徽章标 MIT，LICENSE 实为 CC BY-NC-SA 4.0（需警惕）
    • 可借鉴技术（核心价值）：Promise.allSettled+超时竞速+负缓存聚合容错、自写 LRU/多态搜索缓存、IStorage 存储抽象 + 连接重试、探测式列数行虚拟化网格、服务端 m3u8 改写代理
    • 风险：影视聚合高合规风险；零测试（jest 配了无 1 个测试文件）；认证偏弱
    • 结论：只借技术架构（聚合容错/缓存/SSE），不引入本体（合规红线）

    4. pascal/editor（22.4k★，MIT，WebGPU 3D）— ★对 sora CAD 方向最相关¶

    • 定位：R3F + WebGPU 纯浏览器参数化 3D 建筑编辑，原生内置 31 个 MCP 工具 + CLI
    • 最有价值：MCP 语义工具层（create_room/add_door/furnish_room/check-collisions/validate_scene + apply-patch/undo/redo/export-glb）+ pascal://agent-guide 工作流 + editorUrl 交接人确认 = 完整 AI 驱动闭环
    • 能：建筑/室内全流程（参数化墙 + CSG 门窗开洞、楼层、碰撞/净空校验、GLB/JSON 导出、实时协作）
    • 不能：通用 CAD、无 STEP/制造级导出、受浏览器内存约束
    • 架构纪律可抄：Core 不 import Three.js（headless 零 GPU）、Core sub-path exports、schema 双向约束 UI 与 AI、MCP 语义工具化
    • 对比：implicit-cad（隐式 SDF/有机/打印）与 FreeCAD（B-rep/制造级/需本地）是两极，pascal 是「空间规划 + AI 建造」中间路线，浏览器原生 + MCP 原生化领先
    • 结论：对 sora 的 CAD/PCB 自动化 MCP 方向是直接参考实现

    5. camofox-browser（9.8k★，MIT）— ❌不引入¶

    • 不是独立浏览器，是 Camoufox（Firefox C++ 反检测分支）的 REST 封装服务
    • 反检测在 Gecko C++ 编译期（非 JS shim，无补丁痕迹）
    • 不支持 CDP → 不能做 Hermes CDP 无缝替换
    • 部署：主推 Docker；本机虚拟化已就绪（Docker Desktop+WSL2 路径通畅，Daemon 未运行）
    • 合规：本质 bypass 工具，仅限授权/公开数据采集
    • 不引入（不支持 CDP + 违规风险，Docker 已不再是阻塞项），仅借鉴工程架构（accessibility snapshot 省 ~90% token、会话隔离）
