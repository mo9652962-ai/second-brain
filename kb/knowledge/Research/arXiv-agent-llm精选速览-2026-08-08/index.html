    arXiv Agent/LLM 精选速览（08-06 + 08-07）· 2026-08-08¶

    20 篇论文速览 → 精选 10 篇对 sora 场景最有价值 → 每条给"可借鉴观点 + 落地映射"。不收藏即止：3 条可直接 apply。

    结论置顶¶

    20 篇中最有价值的是 PAST-Bench（记忆系统评估）、HiGram（图记忆→Obsidian 图谱）、Agent Against Agent（提示注入红队）、CoPlan（人机协同论证图）、Test-Time Scaling（模型选择）。前两者与 Second Brain 体系直接同构——建议吸收为知识库评估/结构方法；后三者对闲鱼接单 + AI 安全有实操价值。

    一、记忆/知识管理（直接对应 Second Brain）⭐¶

    1. PAST-Bench（08-06#1）★★★★★ → 可直接 apply¶

    • 观点：保留经验是否真的提升表现——从未被系统测试。基准在"匹配条件下开关保留经验"，26 场景 204 回合，验证 save→retrieve→update 路径
    • 落地映射：Obsidian 知识库 = 假设"收藏即提升"；应验证。我们已有 outcome 标注（✅/⚠️/❌/📌）+ 周度 ✅ 占比 KPI——下一步：周度回顾时抽查"上周笔记是否被实际 recall 用于任务"，不 recall 的降权

    2. HiGram（08-07#8）★★★★★ → 可直接 apply¶

    • 观点：分层图记忆 + 路径级定位与重写——记忆不是平铺，而是按层级路径检索/修正
    • 落地映射：Obsidian MOC 法已分层（HOME→知识域 MOC→笔记）——下一步：图谱优化时引入"路径级定位"（每条笔记标记在 MOC 树的路径，而非只靠双向链接）

    3. Reward Structure（08-07#7）★★★★¶

    • 观点：RL 中情节探索与神经记忆交互——奖励结构塑造记忆形成
    • 落地映射：技能/记忆写入时带"奖励信号"（outcome 标注就是雏形）；低频使用的记忆自动降权（curator 已实现 usage 追踪）

    二、Agent 架构/自进化（Hermes harness 对照）⭐¶

    4. Argus（08-07#1）★★★★★¶

    • 观点：固定模型权重 + 持久项目状态自进化（Manager/Planner/Engineer/Reviewer 角色分工 + 验证门控）——SWE-Bench Pro 78% vs Direct Copilot 59%，成熟任务省 21% token
    • 落地映射：Hermes 的 curator + skill 体系已是"运行时状态自进化"雏形；验证门控（修订必须通过验证才接受）= VeriSkill 双闸门思路，已在评估

    5. Chained RLM（08-07#2）★★★★¶

    • 观点：长任务切成部分任务，每步用"紧凑摘要 + 黑板 + 持久工件"，上下文不膨胀
    • 落地映射：与 Hermes 上下文压缩理念一致；对长任务建议：主动分段（每段产出工件文件，下一段只读摘要）——大文档生成任务可用

    三、代码/开发 ⭐¶

    6. OctoLong（08-07#3）★★★★¶

    • 观点：跨仓库代码上下文（AST + language server 递归引用检索）显著提升长程代码理解
    • 落地映射：graphify 已做代码图谱——下一步：对大型代码库任务，先 graphify 生成引用图再动代码（已实践于 hermes-agent 主仓分析）

    7. Skill-Native LLMs / Skill Entropy（08-07#4）★★★★¶

    • 观点：用"技能熵"度量模型技能覆盖，指导长程推理训练
    • 落地映射：技能审计（biweekly-skill-audit cron 已跑）——可加"技能熵"指标（使用分布均匀度），识别偏科/闲置技能

    四、安全/人机协同（闲鱼接单实操）⭐¶

    8. Agent Against Agent（08-07#9）★★★★★ → 可直接 apply¶

    • 观点：自动提示注入红队系统——Agent 互攻，自动生成注入攻击测试
    • 落地映射：我们处理外部内容（网页/文件/客户文档）时已有"untrusted content"意识——下一步：对从网络抓取并写入知识库的内容做注入检查（当前 RealGuard 人工验证已覆盖部分）

    9. CoPlan（08-07#10）★★★★ → 可直接 apply¶

    • 观点：基于角色可争辩论证图的可信协同——先给方案，用户/专家可反驳，迭代收敛
    • 落地映射：接单需求对齐（Grill）升级：先给方案草案 → 明确请客户反驳 → 迭代——比单向确认更高效（可写进接单 SOP）

    五、评估/模型选择（省钱参考）⭐¶

    10. Test-Time Scaling（08-06#10）★★★★¶

    • 观点：推理期算力三大类（单轨迹扩展/采样聚合/部分状态搜索）——按任务类型选预算
    • 落地映射：deepseek-v4-pro（深度任务）vs flash（日常）的切换 = 推理预算选择；下一步：深度任务明确用 pro（用户已手动切），日常 flash——与记忆一致

    落地优先级¶

    优先级 行动 难度
    🔴 P1 CoPlan 论证图写进接单 SOP（先方案→请反驳→迭代） 低（改文档）
    🔴 P1 Agent Against Agent → 外部内容注入检查（web→knowledge 写入前检查） 低
    🟡 P2 PAST-Bench 周度 recall 抽查（记忆是否真被用） 中
    🟡 P2 HiGram 路径级定位（MOC 树路径标记） 中
    🟢 P3 Skill Entropy 指标（技能使用均匀度） 低
