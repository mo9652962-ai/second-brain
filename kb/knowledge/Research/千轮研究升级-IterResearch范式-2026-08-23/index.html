    千轮研究 · 深度研究智能体范式（IterResearch/WebResearcher）——2026-08-23¶

    研究触发：sora「进行千轮研究和学习」→ 选定主题：深度研究（Deep Research）智能体本身的方法论前沿 元意义：研究「怎么研究」——用最新学术成果升级 k 自己的千轮研究框架 数据截止：2026-08-23 · 信源：arXiv 2509.13309 / 2511.07327 / 2604.24978 / 2608.15191 / 2608.02009 + tianpan.co 工程实践 + Alibaba-NLP GitHub

    🎯 结论置顶¶

    深度研究 agent 的 2026 共识已经形成：迭代合成 > 线性累积。 阿里通义的 IterResearch 范式（ICLR 2026）证明： 1. 每轮工作区重建 + 演化报告作为记忆 → 上下文恒定，推理力不随深度衰减 2. 2048 轮交互只用 40K 上下文，性能从 3.5% → 42.5%（交互扩展性） 3. 不训练也能用：把 IterResearch 当提示词策略用在 o3/DeepSeek 上，比 ReAct 高 +12.7~19.2pp

    对 k 的直接价值：我们的千轮研究可以零成本升级为 IterResearch 式流程——不需要训练任何模型，只需要改研究循环的结构。

    一、核心发现：为什么线性累积会失败¶

    失败模式 机制 千轮研究里的对应症状
    认知工作区窒息 上下文被历史数据填满，思考空间被挤占 研究到第 6、7 轮时开始重复已知内容
    不可逆噪声污染 第 2 轮的错误断言污染第 3-8 轮全部轨迹 一条错误信息带偏整个研究方向
    过早停止 无明确完成标准，两次肤浅搜索就收工 报告覆盖不全
    无限循环烧钱 停止条件缺失，$15 账单换无关细节 多轮搜索边际收益趋零还在搜

    传统 mono-contextual agent（ReAct 式）在多步基准 <10 分；深度研究循环系统 >50 分——5 倍差距全在循环结构上。

    二、IterResearch 范式（阿里 Tongyi Lab，ICLR 2026）¶

    核心机制：MDP 化的研究循环¶

    每一轮的状态 si = (原始问题 q, 演化报告 Report(i-1), 最近一次工具响应)
                        ↓
              Think（内部推理，不入下轮）
              Report（演化报告 = 中央记忆：新发现与已有知识主动整合，
                      解决冲突、更新结论、过滤噪声）
              Action（工具调用 or 最终答案）
                        ↓
              下轮工作区重建（丢弃原始轨迹，只留报告）

    关键设计智慧¶

    设计 为什么聪明
    Report 是中央记忆而非日志 不是追加，是主动综合——错误信息想进入后续轮次必须先过综合关（选择性保留）
    Think 不传入下轮 内部独白用完即弃，防上下文杂乱
    工作区恒定大小 研究 10 轮和 100 轮推理力一致
    策略性遗忘 原始轨迹故意丢弃——只留综合知识

    实测数据¶

    指标 数值
    开源 agent 平均提升 +14.5pp（6 基准）
    作为提示词策略（o3）vs ReAct BrowseComp +12.7pp
    作为提示词策略（DeepSeek-V3.1） BrowseComp +19.2pp
    交互扩展 2048 轮 @ 40K 上下文，3.5%→42.5%

    配套生态（Alibaba-NLP/DeepResearch ⭐19.9K）¶

    • Tongyi-DeepResearch-30B-A3B：30.5B 总参/3.3B 激活 MoE，专为长程信息检索训练，HLE/BrowseComp SOTA
    • 本地部署门槛：Q4_K_M 需 18.7GB 显存（4060 8GB ❌ 不够，需 24GB 卡或 Mac 统一内存 24G+）
    • 社区复现版 Chen-GX/IterResearch 支持 DeepSeek V3.1/3.2 API 跑完整范式

    三、停止准则工程（生产落地的真难点）¶

    「循环容易。让循环在正确的时间、对正确的答案、以正确的成本终止——才是真正的工程。」——tianpan.co

    策略 机制 适用 陷阱
    覆盖率清单 问题分解成子问题清单，全部解决才停 最可靠 初始分解漏了子问题→在不完整答案上收敛
    信息增益阈值 新事实占比 <10% 即收敛 有界主题 「新事实」难自动化度量
    查询饱和 新查询与旧查询语义相似→停 受限主题 开放式研究会漏掉相邻领域
    预算截断 最大轮数/token/金额兜底 所有系统的最后防线 不检测收敛只防爆仓

    最佳组合（ACL 2026 企业级 EDR 验证）：覆盖率清单 + 证据充分性判据 + 预算兜底。 消融实验：去掉步骤级终止判据 → 质量 82.09→73.67，搜索调用 327→224（提前烂尾）；去掉依赖图 → 执行时间 47→222 分钟。

    RAAC 控制器（2608.15191）：轨迹信号驱动¶

    四个无监督信号判断「继续/干预/停止」： - 文档新颖度（本轮新文档占比） - 准则覆盖度（子问题解决进度） - 查询多样性（是否在原地打转） - 与原查询相似度（是否偏题）

    实测：搜索调用 -14~-44 次，准确率反升最高 10%——少搜反而更准。

    HALT（2608.02009）：逐跳证据覆盖停止¶

    把「要不要停」从「生成器自信吗」改成「每个预期证据跳都有支撑吗」——多跳 QA 上减少冗余搜索且 EM 不降。

    四、对 k 千轮研究的升级方案（立即可执行）¶

    升级点 1：演化报告替代线性笔记 ⭐ 最高优先¶

    旧模式：每轮搜索结果堆进上下文 → 第 8 轮上下文臃肿开始复读
新模式：每轮结束写「演化报告」（当前结论+已解决子问题+矛盾点+下一步）
        下一轮只带报告+新工具响应，不带原始搜索结果

    落地：千轮研究中每轮产出 200 字结构化报告，最终报告由最后一轮演化报告扩写。

    升级点 2：研究前先出覆盖率清单¶

    动手搜之前：问题分解成 3-7 个子问题清单
每轮对照清单标记：✅已解决 / 🔄进行中 / ⬜未动 / ❌证据不足
全部 ✅ 或预算耗尽才收工

    升级点 3：三档停止判据组合¶

    正常停止：覆盖率清单全绿 + 连续 2 轮无新增独立信源
干预触发：连续 2 轮查询语义相似（原地打转）→ 强制换角度/换关键词
硬性兜底：轮数上限（简单任务 5 轮 / 中等 8 轮 / 复杂 12 轮）

    升级点 4：多源互证纪律（已在用，保持）¶

    ≥2 独立来源才当事实；一级来源（官方文档/论文）权重 > 二级（博客/论坛）；冲突显式标注不静默取舍。

    升级点 5（进阶，暂缓）：并行研究+综合¶

    WebResearcher 的 test-time scaling：N 个 agent 并行独立研究 → Fusion agent 综合。 对 k 的形态：复杂课题可 delegate 2-3 个子代理分头研究不同子问题，k 做综合者。 暂缓理由：成本 15×，仅用于 B 站重磅选题/付费调研类任务。
