    移动端开发方向指南 · 破解 AI UI 同质化（2026-08-08）¶

    来源：《为什么 GPT 设计的 UI 千篇一律》文章 + 刷题机移动端截图（单词本/今日复习/首页/真题/笔记/设置）+ 竖屏适配踩坑实录

    结论置顶¶

    三条方向原则：①AI 辅助 UI 必须建立"看得见"回路（截图→批评→改），否则永远是统计平均的模板感；②每个界面都必须有具体参考锚点（截图/竞品/线框），抽象描述（"高级感"）等于没给；③验收标准是"全部界面逐屏检查"，不是首页好看就完事——二级界面决定产品可用性。开发流程升级为：需求规范 → 线框确认 → 逐屏实现 → 截图回归。

    一、方法论：为什么 AI 设计的 UI 千篇一律¶

    根因 表现 破解法
    无视觉反馈闭环 AI 生成的代码"看不见"自己，只能靠训练统计平均 → 居中 hero + 卡片栅格 + 标准导航 生成后必须截图回看（browser_vision/移动端截图），建立"看输出→批评→修改"回路
    无参考锚点 "高端大气、有美感"是抽象描述，模型只能取最典型形态 给具体参考：目标 app 截图、色板 hex、间距数值、组件样式
    skill 只补知识不补回路 ui-ux-pro-max 提供风格库/色板/字体，但缺"看自己输出→自我批评→修改"迭代 流程层面强制迭代：每屏生成→截图→自评→修订，至少 2 轮

    二、设计规范（从截图提炼，刷题机移动端直接采用）¶

    2.1 单词本（7 条决策）¶

    1. 显示设置移入"设置"（主页只留必要操作）
    2. 主页保留：搜索、筛选、高频词、最近加入
    3. 普通释义优先，语境释义放真题遇见旁
    4. 同义词/反义词/形近词默认折叠（全局设置开启）
    5. 高频词：琥珀色星标 + 出现次数，不用大色块
    6. 进入单词本后台自动翻译未译词（不阻塞页面）
    7. 今日复习：固定顶进度 + 中央滚动释义 + 固定底按钮

    2.2 今日复习三段式（关键布局）¶

    ┌─────────────────────┐
│ ← 今日复习     08/20 │  ← 固定顶部
├─────────────────────┤
│       abandon        │
│      放弃；抛弃       │  ← 中央滚动区
│  真题语境较长时       │    （长引用只在此滚动）
│  只在此区域滚动       │
├─────────────────────┤
│ [不认识] [模糊] [认识]│  ← 固定底部
└─────────────────────┘

    核心价值：长引用不会把"退出复习"/进度条/底部三按钮挤出屏幕。

    2.3 首页信息架构¶

    • 顶部：试卷选择器（考研英语一）
    • 统计条：试卷/篇目/客观题/高频错题（数字卡片）
    • 练习模块：完型填空 / 阅读 PartB / 阅读理解（随机一篇入口）
    • 词汇回顾：单词卡 + 单词本入口
    • 底部导航：首页/笔记/AI/设置

    2.4 设置页分组¶

    外观（浅色/深色切换）→ 单词本显示 → 题库管理 → 导入题库 → 模型与 API

    三、开发流程：AI 辅助 UI 的 SOP¶

    1. 需求规范（文字，含具体数值/行为）
2. 线框确认（纯文本 ASCII 或简单框图）→ 用户点头
3. 逐屏实现（一次只做一个界面）
4. 截图回归（每屏截图 → 对照规范自检 → 修订）
5. 全界面遍历（首页→二级→三级全走一遍，检查功能可达性）
6. 回归验收（关键操作可用：更新按钮/返回/提交）

    四、踩坑清单（GPT 偷懒实录）¶

    坑 后果 防法
    横屏版直接套竖屏 布局错乱，控件被挤没 竖屏/横屏分别设计布局，不共用模板
    只优化一级界面 首页好看，二级界面原封不动 验收清单覆盖全部界面
    关键功能在二级界面被挤掉 更新按钮找不到了，无法升级 每个二级界面检查关键操作可达性
    只做表面优化 换色/圆角，交互和结构没变 要求"结构级"改动（布局/层级/动效）而非"皮肤级"
