    1. Pretext: Defeating Malicious Skill Detection Frameworks for AI Agents¶

    • ID: 2609.39607v1 | 📄 PDF
    • 作者: Tobias Kaisar, Aritra Dhar
    • 分类: cs.CR, cs.AI
    • 摘要: 技能通过把指令与信息注入上下文来扩展 agent 能力，被 OpenClaw、Claude Code 等广泛使用；既有工作已证明第三方市场托管恶意技能，可让攻击者直接影响受害者的 agent。新兴防御在安装前扫描技能——确定性静态检查 + LLM 语义裁判（如 NVIDIA 的 SkillSpector）。本文证明这类防御在知道检测器的攻击者面前会失效：白盒 LLM 攻击器 Pretext 迭代构造既逃避检测、又投递 payload、同时完成良性任务的技能——把 payload 从代码搬进自然语言（让静态分析失去着力点），把它包装成技能的正当用途，再把指令拆到多个文件（让 LLM 阶段低于其拦截阈值）。在三个开源模型上，对冻结检测器最高 97%、对协同自适应检测器 77% 的攻击成功率，暴露当前技能扫描器的重大缺口。
    • 关联度: ★★★★★ 这是「装前扫描」这类防御的直接反证。k 的 skill_manage 若只依赖单层静态+LLM 扫描，等于把安全押在一个已知可被绕过的检测器上。可落地：① 把扫描结果当信号而非准入判决，与 10-02 速览的「跨 Skill 依赖链检查」叠加；② 对「把指令拆到多文件」的形态做专门检测（现有扫描器逐文件看，天然漏跨文件拼装）；③ 装后仍保持运行时授权（见第 3、4 篇）。

    2. SKILLLITE: Evidence-Guided Malicious Skill Auditing with Compact LLMs¶

    • ID: 2609.36879v1 | 📄 PDF
    • 作者: Haoran Ou, Gelei Deng, Xuanye Zhang, Wenbo Guo, Tianwei Zhang, Kwok-Yan Lam
    • 分类: cs.CR, cs.AI
    • 摘要: Agent Skill 把任务相关指令与可执行组件、辅助资源打包，第三方技能的普及引入新的供应链攻击面：恶意技能可嵌入有害行为，滥用 agent 权限并破坏执行环境或可访问资源。既有 LLM 恶意技能审计方法表现不错，但依赖强商业 LLM；如何在安全敏感、资源受限的环境中用紧凑、可本地部署的模型做有效审计，此前基本未被探索。作者发现紧凑 LLM 难以识别隐藏在复杂技能包中的恶意行为——原因既有行为的隐式性，也有紧凑模型推理能力的限制。据此提出 SKILLLITE：证据引导的 agentic 框架，先抽取安全相关行为并推断技能的预期功能，再让紧凑 LLM 基于「观察到的行为 + 功能上下文」判断恶意性。跨多个紧凑骨干优于代表性审计基线，泛化到行为已被确认的野外恶意技能，同时保持低推理延迟。
    • 关联度: ★★★★☆ 与第 1 篇互补：Pretext 打的是「扫描器可被绕」，SKILLLITE 补的是「审计不必依赖云端大模型」。对 k 的实际价值在本地化——把技能审计做成本地可跑、低延迟的例行检查，而不是每次都调外部模型。可落地：给 skill-vetter 类流程加一层「先抽行为、再推预期功能、最后判恶意性」的证据链，输出可复核的判定依据而非单一分数。

    3. ActionGuard: Tool Call Authorization under Poisoned Skills¶

    • ID: 2609.39450v1 | 📄 PDF
    • 作者: Jihun Han, Yejin Jang, Byung Il Kwak, Mee Lan Han
    • 分类: cs.CR, cs.AI
    • 摘要: 在本来良性的技能里插入恶意指令，就能让良性用户请求触发危险 Tool Call（数据外泄、删文件、未授权代码执行）。ActionGuard 在 Tool Call 即将执行前检查它：把目标 agent 的动作生成上下文与守护者的授权上下文分离——目标 agent 仍可用原始技能做规划，但 Reviewer 不接收可能被投毒的原始技能文本，而是依据「平衡技能画像 + 当前与近期 Tool Call + 本地脚本内容」判断每个动作是否被可信用户请求所证成。在 OpenClaw 的 before-tool-call 阶段拦截，按 fail-closed 策略执行 ALLOW/DENY。评测用 139 个上下文注入 + 180 个明显注入，对比 Dynamic Guardian 与 SkillGuard，三种开源 + 两种商用 Reviewer 模型，每条件重复三次：ASR 相对既有守护降 35.54–46.11 个百分点、相对无守护降 70.44 个百分点，同时保持高良性任务完成率。
    • 关联度: ★★★★★ 「授权上下文与生成上下文分离」是可直接抄进 k 的工程结构——别让做决定的那个 agent 自己审自己。这与既有 hermes-codex-security-gate 的「派活前门禁」同源，但补上了执行边界（before-tool-call）这一环。可落地：高风险工具（写文件、发网络请求、git push）前加一个不看原始技能文本的独立 Reviewer，只依据用户原始请求 + 近期调用 + 本地脚本判定。

    4. ToolFence: Fine-Grained Authorization for Secure Tool-Using LLM Agents¶

    • ID: 2609.37196v1 | 📄 PDF
    • 作者: Yanjie Li, Xiangyu He, Xuelong Dai, Bin Xiao
    • 分类: cs.CR, cs.AI
    • 摘要: 工具使用 agent 易受间接提示注入，根源是可信指令与不可信观察共享同一上下文，恶意内容因此能反过来操纵输入过滤式防御。多路共识防御仍有高 ASR，因为它们检查内容或聚合输出、而非授权效果，尤其对「工具内攻击」无效（工具不变、参数被操纵）。CaMeL 式数据流控制保证更强，但延迟高到限制部署。ToolFence 在执行前编译带类型的授权蓝图，用确定性监视器执行；蓝图不完整时请求授予新能力，而不是逐个裁决具体调用。两个关键优势：① 细粒度、溯源感知的授权能区分用户授权值与不可信观察，有效治工具内攻击；② 确定性快路径 + 能力级运行时授予大幅降低昂贵 judge 调用频率。AgentDojo + Qwen3-max 上把 ASR 降到接近零，干净效用仅降 3.80 个百分点，运行时开销可控。
    • 关联度: ★★★★★ 与第 3 篇同属「执行边界授权」，但机制不同：ActionGuard 换上下文，ToolFence 换粒度（从「审内容」改成「审效果/能力」）。k 的教训很直接——参数级攻击（同一工具、不同参数）是纯内容过滤的盲区，必须授权到「这个参数值是不是用户给的」。

    5. PACE: Provenance-Aware Capability Enforcement for Tool-Using LLM Agents¶

    • ID: 2610.01349v1 | 📄 PDF
    • 作者: Fengpeng Li, Qizhou Wang, Yuke Hu, Kemou Li, Jun Liu, Haiwei Wu, Jiantao Zhou, Di Wang
    • 分类: cs.CR, cs.AI
    • 摘要: 工具使用 LLM agent 把生成文本变成真实副作用，因此被投毒的工具元数据、检索页、记忆与可复用技能都能引导下一次调用。关键在于：准入前审查解决不了这个问题——一个安全变体与一个泄漏变体可以产生相同的准入证据，于是健全的门禁对二者都不能放宽。本文把这个条件形式化，指出这留下了部署端唯一还能行动的边界。PACE 在每次工具调用即将执行前做中介：路径限定对表征出的影响路径做可执行切割；能力与效果验证把 schema 定义的效果对照由已认证请求编译出的权限。并把「经认证的执行契约」与「被评估配置」区分开（后者可在提议拦截后恢复一次已授权调用，或施加声明式修复）。8 个可执行 agent 安全基准 × 3 个目标模型族：被评估配置在 79 个合格攻击列中 62 列取得最低 ASR、14 列持平；完整基准原生效用最多损失 3 分。1167 对配对消融显示安全增益主要来自效果验证，而拒绝控制来自边界自适应；缩小规模的自适应搜索对越权目标 0/30 成功。
    • 关联度: ★★★★★ 这篇给出了三篇「执行边界授权」中最强的理论陈述：准入证据不可区分 ⇒ 唯一可用边界是执行时。可落地：k 的权限模型从「安装时白名单」升级为「调用时对效果做能力核验」，并把「已验证契约」与「当前配置」显式分开记录——否则修复一次拦截后无法说明凭什么放行。

    6. MMSkillRisk: Can Agents Stay Safe When Multimodal Skills Become Traps?¶

    • ID: 2609.35912v1 | 📄 PDF
    • 作者: Lingqi Jiang, Jialuo Chen, Jianan Ma, Xinhao Deng, Xiaohu Du, Sibo Yi, Yuqi Qing, Zhenguang Liu, Qinming He, Shiwen Cui, Changhua Men
    • 分类: cs.CR, cs.AI
    • 摘要: 多模态技能在程序性指令、工具与示例之外额外包含视觉参考，agent 执行时会检索并查看这些图。因为图会引导动作，攻击者可以把恶意指令伪装成本来合法技能内的普通视觉指引。既有技能安全研究主要看文本载体攻击或扫描器检测，图像承载攻击的运行时效果评估不足。本文提出 MMSkillRisk——据作者所知首个面向多模态技能图像承载攻击端到端安全评测的公开基准。攻击面实例化用 NCVA（Native-Context Visual Attack）：把恶意指令伪装成教学图的原生组件（标注、界面标签），配套辅助指引把 agent 引向相关视觉区域而不明说恶意操作。基于 28 个精选干净技能，含 36 个攻击包、108 个可执行用例、覆盖五类攻击目标，攻击成功与良性任务完成分开检查。9 个模型-harness 配置在隔离沙箱中全部被诱导出未授权操作：池化 ASR 达 43.1%，比匹配的文本载体基线高 16.4 个百分点（9 个配置全部更高）；攻击成功与良性任务完成在 36.5% 的用例中同时发生，GPT-5.6-sol + Codex 达 72.2% → 任务成功本身不构成技能使用安全的证据。
    • 关联度: ★★★★☆ 给「任务成功 = 安全」这一默认假设又补了一刀，且补的是多模态盲区。k 处理图片类素材（截图、产品图、PPT 截图）时，图里的文字同样是注入面。可落地：① 从外部拿到的图片素材进入 agent 上下文前，视为不可信文本处理；② 验收报告里「任务完成」与「未发生越权操作」分两栏，别合成一项。

    7. Approval Laundering: Systematizing Approval–Execution Binding Failures in AI Coding-Agent Harnesses¶

    • ID: 2609.38983v1 | 📄 PDF
    • 作者: Yang Wang
    • 分类: cs.CR, cs.AI, cs.SE
    • 摘要: 现代 AI 编码 agent harness（Claude Code、Codex CLI、Cursor）把安全边界建立在一个几乎无人审查的假设上：人类批准的动作 A 就是 harness 执行的动作 A'，其中 A 由「范围授予 / 会话级批准」的既定策略固定。本文证明该假设系统性且可复现地失败，并给出 Approval Laundering 分类法——六种失败模式，描述 harness 的执行机制如何在批准后静默把 A 替换成 A'：Scope（范围）、Argument（参数）、Temporal（时序）、Tool（工具）、Delegation（委派）、Semantic（语义）洗白。与既有「用静态语料评估风险分类器」或「推断隐式意图」的工作不同，本文直接审计批准与执行之间的绑定关系。
    • 关联度: ★★★★★ 这条直接命中 k 的审批语义：sora 说「可以推」，k 推的是不是同一个东西？六类洗白里最危险的是 Argument 与 Semantic——批准「更新笔记」却执行了「更新笔记 + 顺手改配置」。可落地：把审批记录写成「批准对象 + 参数 + 范围 + 有效期」四元组，执行前回读比对，不一致就停下重新确认，而不是「差不多就办了」。

    8. Aletheia: Permission-Minimality Testing for Coding-Agent Rules¶

    • ID: 2609.39678v1 | 📄 PDF
    • 作者: Jieke Shi, Yuchen Chen, Junda He, Yue Liu, David Lo
    • 分类: cs.CR, cs.SE
    • 摘要: 仓库指令文件指导编码 agent，同时也把它们暴露于提示注入：恶意规则可以一边让 agent 产出正确的补丁、一边索取凭据访问或数据外传。本文提出 Aletheia，做权限最小性测试：把规则请求的权限翻译成带类型语言，并合成可执行沙箱配置；先在完整权限下、再在每次只去掉一项权限的独立限制下运行未改动的规则与任务。若在严格削减的权限下仍能通过独立功能测试，就得到该权限可省的「可弃性见证」，Aletheia 结合任务上下文把它解释为可疑请求的诊断依据（并形式化了这一判据）。在共享重构任务上，Aletheia 对全部 314 个 AIShellJack 攻击输入都执行并检出，5 个良性模板零告警；在 80 条人工核验的良性 GHAgentFiles 规则中只产生 3 个误报（3.75%）。
    • 关联度: ★★★★☆ 提供了「逐项撤权看还能不能过」这一干净的可执行判据——比静态读规则文本可靠得多。可落地：给 k 自己的高风险脚本做一次权限最小性自查（每去掉一项权限跑一次功能测试），把「其实不需要的权限」从默认授权里删掉。这也天然生成一份可审计证据，比「我觉得它安全」有说服力。

    9. MCRI: A Four-Dimensional Framework for Analyzing and Evaluating Agent Skills¶

    • ID: 2610.01506v1 | 📄 PDF

    • 分类: cs.AI, cs.SE
    • 摘要: 随着 agent 从单工具系统演化为模块化复合架构，技能正成为能力开发与分发的重要机制，但学界缺乏系统分析/评估技能的结构化框架。作者基于信息增益与行为约束提出四维 MCRI 框架，并操作化为基于 LLM 的 MCRI-Eval 评估方法。用 OpenClaw Skill Hub 的 63,812 个公开技能、跨 BigCodeBench / BFCL-Fundamental / Mind2Web 的 58,275 次技能条件化模型执行来评估。MCRI-Eval 分数与社区热度信号正相关，在被评估方法中下游排序一致性最高；top-1 技能选择在三个基准上分别把下游性能排名推进 17.7 / 22.8 / 19.6 个百分点。结论是它提供了执行前筛选信号，可在昂贵执行式评估之前优先化有希望的技能。

    10. SkillSeek: Revisiting Agent Skill Retrieval at Marketplace Scale¶
