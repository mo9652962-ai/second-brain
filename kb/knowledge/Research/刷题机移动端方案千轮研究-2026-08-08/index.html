    英语刷题机 · 移动端开发方案千轮研究¶

    3 轮 × 9 路搜索 + 移动端适配验收（headless 截图）。执行结果（2026-08-08）：✅ Android 环境装好（JDK17/21+SDK+Capacitor 8.5）✅ APK 构建成功（Capacitor 路径）✅ 移动端适配增强（安全区/100dvh/触控目标）✅ 底部导航 16 项裁剪问题修复为 6 项核心 ⚠️ 数据加载时序需真机验证

    结论置顶¶

    推荐方案：PWA 现状保留 + HBuilderX/Capacitor 云打包 APK（侧载分发）+ 局域网同步（已有）→ 中期软著+APP备案上架 7 大市场。禁止重写（Flutter/RN）——现有 Vue3 前端 + sql.js 离线架构已完备，重写是纯浪费。

    一、竞品移动端技术拆解（研究结论）¶

    竞品 技术栈 核心机制 借鉴点
    墨墨背单词 MySQL + MongoDB + Redis + 自研同步协议；词库分块二进制压缩离线包 记忆反馈（认识/模糊/忘记）+ 遗忘临界点调度（SIGKDD/TKDE 论文级） ①词库增量下载 ②记忆反馈三态 ③学习状态毫秒级跨端同步
    百词斩 原生/跨端（未公开） 图像联想 + 选择题 选择题模式（我们已有）
    不背单词 原生（未公开） 原声例句 + 语境记忆 + 连续答对 3 次完成 答对 3 次完成机制
    AnkiDroid 原生 + SQLite 间隔重复 + 自定义卡片 + 多端同步 数据备份（桌面版已学）
    Echo Loop（开源） Flutter（AGPL-3.0） AI 听说训练 + 间隔复习 可参考其架构（不采用）

    行业共性： 1. 间隔重复算法是核心竞争力（艾宾浩斯 → 动态遗忘曲线） 2. 离线优先（词库本地化，无网络可背） 3. 多端同步是留存关键（手机↔电脑学习状态互通）

    二、移动端技术方案对比（2026）¶

    方案 成本 优点 缺点 适配度
    PWA（现有） 0 已有 mobile-app/ 完整产物（80MB 含题库）；扫码即用；离线可用（sql.js） iOS 无安装引导；无商店分发；无推送 ⭐⭐⭐⭐⭐ 现状
    HBuilderX 云打包 APK 0（每天限次） 最快拿 APK；5+App 壳直接包 Web 资源；有 uni-app 生态 云打包限次；WebView 性能一般 ⭐⭐⭐⭐ 内测首选
    Capacitor 0 npm 生态；可 CI 自动化；WebView 现代 需 Android SDK 本地打包 ⭐⭐⭐⭐ 可自动化
    uni-app 重写 高 跨端（App/小程序/H5） 重写整个前端 ⭐ 不推荐
    Flutter/RN 重写 极高 原生性能 重写 + 学习成本 ❌ 不推荐

    决策：不重写。现有 Vue3 + sql.js 前端 = 完整离线刷题引擎，移动端只需打包壳。

    三、打包分发路径¶

    短期（内测，本周可做）¶

    1. PWA：部署 mobile-app/ 到静态托管（或局域网后端）→ 扫码即用
    2. APK 侧载：HBuilderX 云打包（公共测试证书）或 Capacitor + Android SDK → 生成 APK → 群分发（侧载不需要软著/备案）

    中期（上架，1-2 个月）¶

    前置 说明 成本
    软著 中国版权保护中心免费申请（个人身份），约 1-2 月下证 免费
    APP 备案 云服务商提交（域名+主体一致），约 1-2 周 免费
    隐私政策 App 内展示 + 商店提交（数据本地为主，简单） 免费
    上架 7 大市场 华为/小米/OPPO/vivo/应用宝/百度/360（教育类审核严格，需软著） 免费

    四、数据同步方案（手机↔电脑）¶

    方案 适用 说明
    局域网模式（已有） 内测 电脑后端 --lan 手机同 WiFi 访问；后端 8765 已有 --lan 参数
    synced 标记法 简单云同步 本地 SQLite 加 synced=0 标记，联网推送到云（自研轻量）
    SQLite Sync（CRDT） 正式版 SQLite Cloud/PostgreSQL/Supabase 后端，冲突自动合并（零冲突零数据丢失）
    墨墨式自研协议 远期 学习状态毫秒级同步（内测不需要）

    内测推荐：局域网模式（零成本已有）→ 正式版评估 SQLite Sync/自建云。
