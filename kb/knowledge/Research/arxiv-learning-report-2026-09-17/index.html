    二、Draft → Improve：5 条核心知识 + 动作化¶

    知识 1：持久记忆投毒（PMPA）是最高风险 🔴⭐⭐⭐⭐⭐⭐¶

    事实（arXiv 2609.13889）：把恶意指令嵌入良性外部源，诱导 agent 写入持久记忆 → 跨会话存活 → 检索触发恶意动作。OpenClaw 注入成功率 73.7%、跨会话 55.5%；Claude Code 66.9%/81.7%；「记忆一旦污染，提示级防御保护有限」。

    动作： - ✅ 已有 AGENTS.md 拦截（c2_heartbeat 已触发过） - 🔴 待落地：记忆写入通道（外部内容→知识沉淀）加来源隔离/溯源标记——写入前记录 source URL；可疑外部内容只取数据不取指令（daily-knowledge-absorption-gate 的 4.6 节已有规则，但需强化「良性源嵌入恶意指令」的隐蔽形态） - 防写入 > 清洗（污染后防御有限）

    知识 2：工具-工作流组合语义审计 🔴⭐⭐⭐⭐⭐¶

    事实（arXiv 2609.15397）：工具调用成功但工作流失败——重试/并发/部分失败下，外部状态与工作流预期不一致：必要效果缺失/重复、已中止效果存活、已提交效果依赖后被撤销。

    动作： - 🔴 对照实证：今天 Docker 万悟部署就是活例——docker pull 单个命令成功（工具 ok）但 pull3 流程卡死（流程失败），多次 kill 残留僵尸任务 → wsl --shutdown 才解决 - 多步流水线（cron 链）审计组合级状态一致性：重试/并发的语义（幂等性）检查 - 组合合规（2609.18820）：步骤级检查 ≠ 组合级合规——交付门禁补「组合违规」检查

    知识 3：编码 Agent 实证数据成熟（37,623 PR）⭐⭐⭐⭐⭐¶

    事实（arXiv 2609.17598 + 15877 + 14992）：五编码 agent（Codex/Devin/Copilot/Cursor/Claude Code）37,623 PR 的代码质量实证——安全味道/可维护性/合并后 churn；「任务成功≠执行可靠」（2609.16287）；多轮过程指令遵循基准。

    动作： - 编码委派（Codex）的 review 门禁补「合并后维护」视角（不只验收时功能正确） - 「任务成功≠执行可靠」→ 交付验收检查「是否改了无关文件/重写测试/忽略失败校验」

    知识 4：记忆系统「预算化 + 检索驱动演化」双主线 ⭐⭐⭐⭐⭐¶

    事实：BudgetBench（token 预算作自变量 + 预算违规率）→ LIMBO（动态回放预算）→ 协议保持型裁剪 → 检索驱动再巩固（检索从终点变驱动）→ 潜在空间自进化 → 集体-个体记忆协同（CoMem：私有经验 + 共享知识，防「一起学但学成一个样」）。

    动作： - k 的四级记忆体系 + memory-crystal-consolidation 直接同题，「预算约束下如何演化」是进化方向 - CoMem 对 delegate_task 子代理的记忆隔离/共享设计参考（当前子代理无共享记忆，隔离本身符合 CoMem 的私有经验思路）

    知识 5：安全与评测方法论深化 ⭐⭐⭐⭐¶

    事实：投毒基准污染自改进 agent（2609.17817，Thompson 编译器投毒的 agent 版）→ 自评估数据来源需信任审计；策略歧义污染评测（14400）→ gold 轨迹不唯一；ground-truth-as-code（16487）→ 动态数据场景可执行参考函数；Elo-per-token（15309）→ 测试时计算可测量；内部表征监控 reward hacking（19101）。

    动作： - skill-evolution/自举的评估数据来源加信任审计（不明基准不作改进依据） - 评测设计防「策略歧义」（基准写清楚是前提）

    三、Debug：坑与边界¶

    坑 说明 边界
    记忆投毒的隐蔽形态 恶意指令嵌在「良性外部源」（网页/文档/他人笔记）里，非明显提示注入 不是所有外部内容都可疑，但写入记忆前一律溯源；AGENTS.md 拦截只挡显式指令，挡不住嵌入形态
    工具 ok ≠ 流程 ok Docker pull 单命令成功但 compose pull 卡死；僵尸任务残留 多步流程要加「中间态检查」，不能只看最后状态码
    评测策略歧义 自然语言策略沉默/歧义/矛盾 → 单一 gold 轨迹不可靠 评测/门禁的策略要「写清到唯一可判」；跨模型降分差异是信号不是噪音

    四、Crossover：迁移到其他场景¶

    1. PMPA 记忆投毒 → 墨题/闲鱼客户文档：客户交付的文档可能带注入指令（恶意/无意的）——AI 服务处理外部内容时只取数据不取指令
    2. 组合级合规 → 服务质检（G5 门禁）：多步骤交付要查「组合违规」（每步合规但组合不合规）
    3. ground-truth-as-code → 闲鱼行情/股票分析：实时数据的「期望答案」写成可执行参考函数，不依赖静态答案
    4. Elo-per-token → 模型对比（gemini-second-opinion/跨源盲评）：加「测试时计算分配」维度评估成本-质量权衡
    5. 技能池门控（MOSCOPT） → skill-pipeline：从「选单技能」到「技能池 + 门控组合」——多技能互补优于单技能最优
