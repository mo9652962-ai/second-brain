    可借鉴点归纳¶

    技术层面 - 网关/计费：token 级计费 + 渠道倍率 + 分时定价，订阅配额分发是 2026 中转站商业模式（sub2api） - 决策：小决策用 logits 概率直读代替让大模型写 JSON——零输出 token 5x 提速（SemIf） - 安全：MCP/Skill 扫描分类法 MCP01-10 + 名称混淆/Rug Pull/工具阴影（A.I.G），装第三方技能前可扫 - 审查：确定性管线 + LLM 语义分离，行级定位 3 层策略 + 反思模块拦幻觉，~1/9 token（open-code-review）

    方法论层面 - 行为约束单文件化：Karpathy 四原则可合并进任何 agent 的 CLAUDE.md/委派模板 - 「给成功标准而非指令」+ verify 检查点 = 编码 agent 独立循环的关键 - 宁缺毋滥的 Recall 取舍：垂直专用 agent（高 Precision）优于通用 agent（open-code-review） - 可复现基准文化：timing/prompt hash/失败全入库，数字可重跑（SemIf）

    可实操行动 1. Codex 委派模板并入 Karpathy 四原则（假设清单 + success criteria + verify 检查点 + 禁越界重构） 2. skill 安装门禁评估 A.I.G skill-scan（装前扫 SKILL.md vs 脚本一致性 + 高风险模式） 3. SemIf 范式参考：skill-pipeline 质检门/模型路由等高频小决策留作「logits 直读」候选（4060 贴边，可量化 GGUF 试跑） 4. sub2api 作中转商用功能清单对照（EasyCLIProxyAPI 升级路径）；计费倍率概念吸收进 ai-freelance-pricing 5. open-code-review Delegation Mode：委派 Codex 时用它自己的 LLM 审查，省 OCR API
