## 二、问题诊断（六条，附证据）

### ① MOC 索引失效，退化为「追加式日志」

- `knowledge/Research/MOC-Research.md` 中 **「## 其他」标题出现了 3 次**（第 24、186、196 行）——新增笔记没有归组，机械追加进「其他」，索引失去导航价值。
- `knowledge/knowledge-map.md` 已达 412 行，其中 W31~W34 周报速览段落占 180+ 行——**地图变成了 changelog**。周报增量本应去 `memory/weekly-*`。
- `knowledge/Dev/MOC-Dev.md` 尾部挂着未消化的「## 🤖 AI 域（原 AI）」二级标题——域合并（08-15 AI→Dev）后 MOC 没有真正融合，还是两篇笔记拼接。
- `Finance/MOC-Finance.md` 创建后没有任何笔记链接它（扫描判定为无入链）——新 MOC 落地时没有挂回 knowledge-map。

### ② 同一系列并行多套命名

GitHub 研究系列（同一件事）存在 **5 种命名**：

| 命名样式 | 例 | 篇数 |
|:-----|:-----|---:|
| `github-trending-YYYY-MM-DD…` | github-trending-2026-08-05.md | 9 |
| `GitHub-Weekly-YYYY-MM-DD` | GitHub-Weekly-2026-08-14.md | 4 |
| `github-weekly-YYYY-MM-DD…` | github-weekly-2026-07-31-5projects.md | 1 |
| `GitHub热榜-YYYY-MM-DD` | GitHub热榜-2026-08-08.md | 1 |
| `GitHub周榜-YYYY-MM-DD` | GitHub周榜-2026-08-08.md | 1 |

arXiv 系列存在 **3 种**：`arxiv-weekly-*`（6 篇）、`arxiv-2026-MM-DD-agent-llm`（4 篇）、`arxiv-agent-llm-2026-08-08`（日期位置不同，1 篇）；另有 `arXiv-agent-llm精选速览-2026-08-08`（中文混合）。日期格式也有两套：`20260816`（compact，Productivity 报告 5 篇）与 `2026-08-16`（ISO）。

### ③ 孤立笔记 36 篇（明细见第七节）

重灾区：cards 16 篇中 9 篇无入链、Daily 17 篇中 9 篇无入链、`Dev/system-prompts-reference/` 子目录 5 个文件中 4 个无入链（只有 README 被 MOC-Dev 链接）。**note 落盘后没有挂 MOC 是根因**——vault 维护规则第 2 条（INDEX.md:81「每批次研究后更新 knowledge-map 挂载 MOC 防孤立节点」）实际未被 cron/人工流程执行到位。

### ④ 内容重复 7 组（详见第五节合并清单）

最典型：`knowledge/MiMo模型客观评估.md`（根目录，88 行千轮研究）与 `Research/MiMo-V2.5研究-2026-08-08.md`（62 行）**同主题双份且都无人链接**——既重复又孤立。

### ⑤ 主题散落跨目录

- **网络安全**主题 10+ 篇散在 4 个目录：Security（2）/ Research（agent-memory-injection、kutie-context-injection、security-risk-assessment、claude-max-sepa-incident、eu-ai-act）/ cards（eu-ai-act、zero-mem）/ Dev（10-Top-AI-Agent-Projects 的 ClawHavoc 供应链段）。
- **GitHub 研究**主题 35+ 篇散在 Research（25）/ Dev（10+）。
- `INDEX.md:44` 宣称「knowledge/ 7 个子域」，但实际存在 **9 个内容目录**（Finance、Security 未列入清单）——索引与现实脱节。

### ⑥ 流水型笔记无生命周期策略

`token-usage-report-*`（3 篇）、`system-cleanup-report-*`（2 篇）、`skill-audit-*`（3 篇）按日期无限累积，无「保留最新 N 篇、旧的进 Archive」规则。同模式的 memory/ 目录（daily-review ×14、todo-cleanup ×7 等）虽属正常流水，也建议在月度整理时压缩。

## 四、MOC 体系设计

### 三层结构

```text
L1  knowledge-map.md    域级目录：只列 7 域 + 各 MOC 入口 + Daily/cards 索引区（≤80 行）
L2  域 MOC              MOC-Dev / MOC-Research / MOC-Hardware / MOC-Productivity / MOC-Finance
L3  主题切片 MOC        跨域横向主题：MOC-Security（本次新建）、MOC-GitHub（本次新建）
                        后续可按需增加（如 MOC-PCB、MOC-刷题机、MOC-变现）
```

### MOC 五条规则

1. **MOC 只导航不存内容**——不放研究结论，只放链接 + 一句话摘要。
2. **周报增量一律去 `memory/weekly-*`**——knowledge-map 不再追加「Wxx 新增速览」段落（现有 W31~W34 段迁出到 `memory/2026/08/knowledge-map-archive-2026-W31-W34.md` 后删除）。
3. **域 MOC 固定分区**（模板见下），按主题分组；**「## 其他」第二次出现即触发重分组**。
4. **新笔记落盘必须挂一个 MOC**（写入 AGENTS.md 维护规则 + 研究笔记模板的 checklist 项）。
5. **新建 MOC 当场挂回 knowledge-map**（MOC-Finance 无入链就是违反了这条）。

### 域 MOC 模板

```markdown
---
tags: [MOC, <domain>, 索引]
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
# <域名> MOC
> [[knowledge-map|🗺️ 知识地图]] · 共 N 篇 · 最后更新 YYYY-MM-DD

## 主题分组 A（每个主题一个二级标题，链接 + 一句话）
- [[note-1]] — 一句话摘要
## 主题分组 B
…
## 系列笔记（时间流：周报/日报/报告）
- [[series-2026-08-14]] …
## 相关 MOC
- [[MOC-Security]] · [[MOC-GitHub]]
```
